# A21

Section: A. Delivery

## Decision

`dropped.denied` is a count, matching `excluded`, `escaped` and `generated` beside it

## Why

A boolean among three counts answers a different question by accident, and nothing today reads it, which is exactly how the wrong shape would go unnoticed until a caller finally does

## Status

**done** `corpus.mjs` (`collect`), pinned by `test/corpus.test.mjs`.
The special case is deleted rather than flipped from `= true` to `++`: once denial counts the way the other three already do, it falls straight through the classifier's own `if (drop) { dropped[drop]++; ... }`, the same line `excluded`, `escaped` and `generated` already share.
`notSource` keeps its own branch, because it does one thing more: feeding the roster's `others` list.
A sixth count, `unreadable`, holds a tracked path the working tree would not resolve: deleted since the commit, under a directory the scan may not enter, or named in bytes that are not UTF-8, which decode to U+FFFD and name no file on disk.
Those went to `escaped`, which nothing prints, and left the scan without a word; the scan summary now says `N files could not be read, so nothing in them was counted` (`summary.mjs`, `unreadFiles`).
Each listed path is classified once: during an unresolved merge `ls-files` lists a conflicted path once per stage, and every stage was counted, so `lsFiles` drops a repeat through a set rather than `--deduplicate`, which older gits lack.
