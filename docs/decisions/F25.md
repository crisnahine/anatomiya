# F25

Section: F. Safety

## Decision

An explicit `--base` is a commit id only when it names no ref, and a name two refs hold is refused naming both

## Why

The id exemption read the spelling: on a branch named 7812, facade or cafe0, `--base <that name>` passed the hex test, skipped the own-tip refusal and printed 0 changed files at exit 0, which is the outcome F19 exists to stop. git resolves a name a tag and a branch both hold by precedence, tag first, and says so only in a warning that `--verify --quiet` drops, so one repro compared against the wrong commit in silence and the other blamed this branch's own tip for a tag git chose.
The holders are read off `for-each-ref` over git's own lookup rules rather than off that warning, which a locale translates and `core.warnAmbiguousRefs` switches off

## Status

**done** `check.mjs` (`resolveBase`, `refsNamed`).
Ambiguity is caught for a bare name only: `amb~1` still resolves by git's precedence, and the guessed bases (origin/HEAD, main, master) are not checked, since refusing a guess would break the unasked path
