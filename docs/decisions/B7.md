# B7

Section: B. Engine

## Decision

`typescript@5` checker is a second tier that a scan runs on its own wherever it can resolve types: a JavaScript or TypeScript file, a real `node_modules` at the root holding at least one package, a loadable 5.x, and something to type, which is a root `tsconfig.json`, a root `tsconfig.base.json` where there is none, or a TypeScript source file. There is no flag. Pin major 5

## Why

Measured: 26x the parse on first measure; a whole scan with the checker measured about 3x a plain one (typeorm, 3,778 files, 2.1-2.3s against 6.4-6.8s), and on the build that reads ten more languages, 2026-10-08, about 4.5 times (typeorm, 3,347 files read, 5.6 to 5.7s against 1.3s, three dry runs each way with `node_modules` in place and moved aside, at a load of 3.8 to 4.5), whole-program (narrowing the file set drives unresolved types from 3.1% to 36.2%), and it buys 5 entries.
`typescript@7` is the Go port with no JS API.
It was opt-in behind `--deep` until 2026-10-01.
A flag nobody passes measures nothing, and every corpus clone without `node_modules` degraded anyway (typeorm `config-errors` 71%, mastodon and webpack `low-resolution` 28% and 74%), so the dependencies on disk are the gate that decides whether it can answer, not the person.
Measured on react-front-end (2,588 files, pinned, `node_modules` installed): 2.2s plain against 17.4s with the checker, 90.6% resolved, and the pin had closed all 119 `law_of_demeter` slots as `semantic-unbaselined`; on the final build, with no file changed since the pin, 115 read `ratio` and 4 `evidence`

## Status

**done** `semantic.mjs` (`checkerBlocked`: `plain-javascript`, `no-dependencies` or `not-installed`, and `scan.mjs` adds `no-checked-files`, recorded in `semantic.reason`; the refresh stamps `checkerStamp`, which reads the same packages, which of `tsconfig.json` and `tsconfig.base.json` the root is read through and where typescript resolves without importing it, so installing dependencies or adding a config after a scan is a reason to rescan), `semantic-worker.mjs`, `dimensions-semantic.mjs`, `scan.mjs` (the decision, and the baseline reduce asked for the same tier), `plugins/anatomiya/bin/anatomiya.mjs` (`--deep` refused on every command with a sentence saying the checker runs on its own, rather than accepted and ignored).
`typescript` is an optional dependency, never a runtime one, and the range stays inside major 5: a range admitting 7 turns the checker into a silent no-op the day it publishes.
`.github/dependabot.yml` ignores typescript's major versions for the same reason, so a grouped bump never carries one.
One child for the whole corpus, because the checker is whole-program, and one program from the root config, not one per package, measured and refused in B70.
Every row declares its tier and `dimensionsFor` defaults to the syntactic one, so a caller that does not ask cannot be handed a claim nobody ran.
One dimension built, not five: `law_of_demeter` is the only Tier A of them and the tier had to prove it pays before four more were written against it.
The other four are named in `docs/dimension-intake.md` as planned rows.
Never on `check`: the checker is whole-program, so answering a branch would mean building the corpus at two revisions; the check names the type-checked claims it did not enforce instead.
A pin no longer closes the tier: the checker reads the working tree, and a pinned file unchanged since the pin reuses that record, type-checked hits included, so an area whose checked pinned files are all unchanged is baselined over them.
An area holding one changed or renamed since the pin is closed as `semantic-unbaselined` instead: read back from the pin, that file has no type-checked hits, and counting the rest let an edit take a violation out of the baseline (measured on a fixture: 6 of 10 at the pin, 6 of 6 after editing the four violators).
An unchanged file still lends the hits the working tree gives it when its imported types moved in another area, the `tsconfig.json` changed or a dependency was upgraded, because the checker is whole-program and has no pinned program to ask.
The 2.2s against 17.4s rides on every refresh of a repository that qualifies and reads ok; that is the price of a map that does not depend on remembering a flag.
Where the tier reads degraded a refresh pays it once per measurement: it carries the verdict until the build, the packages or the root config move or someone runs `scan` (B8), twice where the checker's run fails, since a failed run is carried from the second in a row, and a refresh of four such repositories measured 4.4s to 21.2s with the checker and 1.2s to 3.8s with the verdict carried.
`unusableReason` in `semantic.mjs` tells an absent checker from one of another major and from a 5.x with no `createProgram`, and doctor prints it.
`plain-javascript` is a root with no `tsconfig.json` and no checked file whose extension can carry types (`holdsTypeSyntax`, by extension only, so a Flow file counts as JavaScript: the checker cannot read Flow), and a declaration file (`.d.ts`, `.d.mts`, `.d.cts`) does not count, since a hand-written one beside JavaScript types nothing that JavaScript imports.
It is named before `no-dependencies` because installing changes nothing for it, and `checkerBlocked` refuses a call that does not pass `checkedRels` rather than defaulting it, since either default answers wrongly for half the repositories.
Measured on the corpus with dependencies installed: huginn, diaspora and whitehall, all JavaScript with no config, read degraded `no-tsconfig` at 35.4%, 25.0% and 39.2%.
A `jsconfig.json` does not count, because the checker reads only `tsconfig.json` and `tsconfig.base.json`.
TypeScript with no root `tsconfig.json` still runs, and B8 carries the thirteen repositories that decided it; the four with a root `tsconfig.json` (mastodon, webpack, react-front-end, typeorm) read ok at 83.5% to 96.8%.
