# H32

Section: H. Layout

## Decision

The fold line counts the folded directories, the files in directories too small for a line of their own, and the files at the repository root as three clauses, never as one number

## Why

One sentence carried all three populations and the noun in it named the first, so every file under no root at all was charged to the directories that folded.
Measured on three repositories: this one printed `and 1 more directory holding 21 files` over a folded root holding 3, so 86% of the number named a directory that does not hold it; a Rails map printed 3,564 over 3,400, charging 164 files to `public` and `app/views`: 147 in 26 directories, `config` at 39 of them, `config/initializers` at 33 and `lib/tasks/archived` at 27, and 17 at the repository root; a front end printed 434 over 323.
Nothing is enforced from the line and the totals still reconcile, so only the attribution was ever wrong.
The repository root is its own clause rather than one of the directories under the floor: `visit` guards the floor test with `!isRoot`, so the root never took that test and failing it is not why it has no line, and it is not a place either, which is the answer `majorityDir` already gives.
It holds 17 of that map's 164 and 14 of this repository's 18.
Where the root is an area (A108) its files are in that clause and in their area both, since the clause says where files sit: gin's line ends `and 53 at the repository root` with 40 of them in the root area.
`foldLine` already carried a second wording for the remainder and a `roots > 0` guard made it unreachable whenever anything folded, which is the shape all three repositories have
