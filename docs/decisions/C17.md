# C17

Section: C. The counted-claim model

## Decision

The three row lists are one registry, and a reader that wants more than one asks for it rather than spelling the union

## Why

A row is declared in `ALL_DIMENSIONS`, in `PAIRINGS` or in `NAMING_CORPUS`, and ten readers across `lib/`, `scripts/` and `test/` each spelled a different subset of the three, so one that missed a list read a shorter registry without a word and a fourth list would have to be added to all of them.
C15 put the load battery over all three lists and it still ran from inside `dimensions.mjs`, which the parse worker then imported

## Status

**done** `registry.mjs` (`REGISTRY`, `REGISTRY_KEYS`, `rowsOfKind`, `rowsForLangs`, `rowByKey`, `assertUniqueKeys`), read by `reduce.mjs`, `check.mjs`, `model-defaults.mjs` and the scripts.
The battery runs here, once, over the union, and `stampKind` writes the kind in place, so a row read through this module is stamped whichever list declared it.
One question a per-list battery cannot ask is asked here: one key names one row, or two rows print the same three numbers twice and a lookup reaches whichever it found first.
A misspelled kind throws rather than answering with no rows, which is a reader switched off in silence.
The parse worker must not reach this module and the import graph is walked to hold it: the worker runs the tree rows off `dimensionsFor`, has no program to run an obligation or a filename row against, and eight forked children pay for whatever it imports (F18's reason).
