# B36

Section: B. Engine

## Decision

The fields a site carries across the worker boundary are one table, `HIT_FIELDS` in `walk.mjs`, each with the reading that takes it off a hit, and `crossing` builds every site from it

## Why

The shape had three writers and no owner.
`collectHits` copied six fields with a predicate each, the semantic worker kept a two-field copy of its own, and the obligation rows built theirs in `pairing.mjs`; nothing held any of them to what the reducer reads.
A field a row added to a hit crossed only if the copy happened to name it, which is how `nesting` was dropped once and the base-class row stated nothing, and the same drop was one `.ts` row away from recurring in the semantic worker.
That worker's two-field copy was the status quo the audit described, not a rule: it builds through the same table now, so a semantic row that grows a field crosses the way a syntactic one does

## Status
