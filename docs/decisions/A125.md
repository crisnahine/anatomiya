# A125

Section: A. Delivery

## Decision

A stop that ends a turn opened by the task notification of a subagent launched after the reuse check's last ask, and before the person's next prompt, records what the turn left, as the stop right after a block does (A91), and asks nothing: that turn is the check's own fix. The subagent tool is read under both its names, `Agent` and the older `Task`

## Why

Claude Code 2.1.312 runs a subagent in the background by default.
The check's search then returns as a task notification, which opens a turn of its own, and the session applies the fix there.
The stop after that turn is no continued stop, so the fix's new content read as fresh work and the check asked again: on the two builds of 2026-10-28 without this rule, 15 of 19 mastodon sessions and 5 of 8 atuin sessions with the plugin ran a second search for code the first had just chosen, against 27 of 174 and 5 of 40 on the 0.19.0 runs.
A session saw a task notification in 261 of 1,020 captured trials on 2.1.310 and in 81 of 101 on 2.1.312.
On the build with this rule, 40 of 40 sessions across four tasks ran one search (`docs/measurements/data/2026-10-28-background-subagents.json`).
Replayed on a captured mastodon transcript cut at the stop that asked again, the rule reads that stop as the check's own.
A message that arrives while the session works is no user entry: Claude Code 2.1.304 and 2.1.312 record it as a `queued_command` attachment, 80 task notifications and 22 typed or sent prompts in this project's transcripts over 30 days, so a prompt queued that way asks, the check's own result queued that way answers, and any other call's result queued mid-turn opens nothing.
A notification for a call launched before the ask, a build run in the background for instance, opens a turn like any other and is asked about, and so does one for a subagent launched after the person spoke again, which a first build read as the check's and so let new code through unasked.
