# A18

Section: A. Delivery

## Decision

Two delivery facts are written down rather than rediscovered: a Read that fails still attaches the area file its path matched, and a subagent is served by the same channel, with the session's working directory deciding what it holds before its first Read

## Why

Both were folklore.
The first is measured here: a Read of `scripts/ab/does-not-exist.mjs` returned the file-not-found error and attached `anatomiya-area-7fb4de45.md` in the same turn, so delivery keys on the path of the attempt rather than on the read succeeding.
It falls the right way and nothing said so: an agent probing whether the file it is about to create already exists is handed that directory's counts at the moment it is about to write one, which is the read-before-write habit the overview's own sentence asks for.
The second corrects the shape #47 filed it in.
Five subagent transcripts on 2.1.220 and 2.1.233, every one with the mapped repository as the working directory, deliver `CLAUDE.md` and the overview on the subagent's first turn ahead of any tool call, so the overview is not absent from a subagent as such.
What is measured absent is a nested repository: started one directory up, the map is nested rather than root and nothing arrives until a file under it is touched, which a Bash-only subagent never does.
That is the #34 gap stated exactly, and it is narrower than the reading that a subagent does not get the map.
Both halves re-run from the transcript store rather than from memory: `scripts/measure-delivery.mjs` counts the deliveries a subagent took, and the transcripts holding one are `find ~/.claude/projects -path '*subagents*' -name '*.jsonl' | xargs grep -l nested_memory`, where the delivery sits at the second entry of the file and the first tool call after it at all
