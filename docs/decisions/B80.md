# B80

Section: B. Engine

## Decision

PHP markup asks in the reuse check's tree rule (B68) on the rows that hold code: a script, or what Blade compiles to PHP, an echo (`{{ }}`, `{!! !!}`), a `@php` block or a directive with an argument. Markup beside them, a Blade comment, a `@verbatim` block, an e-mail address and a CSS rule such as `@media (` stay markup

## Why

Laravel's views are `.blade.php`, so the PHP grammar reads them, and everything outside `<?php` is markup to it.
Before this row every markup line of a view was inert unless the file held a `<script` tag, so `@php $total = array_sum(...) @endphp` in a new view asked nothing: run as the hook, a new view holding it answered `{}`, where a `.blade.php` file holding `<?php function t()` blocked.
Blade reads a directive only after a character that cannot end a word (`\B@` in its compiler), which is why `admin@example.com` is text, and it compiles only the directives it has a method for, which is why `@media (` is left alone; the rule spells both the same way.
An echo closes at its `}}` whatever stands before it (`{{ $n--}}`), `@{{` is Blade's literal braces, and `@php` after a word character (`admin@php.net`) is text, as Blade reads each.
Read by the row and not by the file, since nearly every Blade view holds an echo: asked of the whole file, an edit that changed a CSS class in any of them spent a subagent search, where the other templates ask nothing of markup alone (A122). The rows are read over every chunk of markup in order, as a script was before them: an inline tag cuts a script or a `@php` block in two, and only the first chunk holds what opened it.
The cost is a false ask on a row of a plain `.php` file whose markup writes `{{` for a front-end template, which spends one subagent search
