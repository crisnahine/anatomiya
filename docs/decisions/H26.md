# H26

Section: H. Layout

## Decision

The namesake question is answered off the whole directory where the tail below the root leaves nothing, so one file reads the same whichever root above it is asked

## Why

A tail that is only tree words is the most ordinary layout there is: at `packages/foo` the tail of `packages/foo/src/parser.ts` is `src`, `withoutTree` empties it, and the guard against a bare basename then refused every candidate.
The package read 0 of 2 where `packages` above it and `packages/foo/src` below it both read 2 of 2, which is the huginn `2 of 6` against `0 of 18` class the companion tests already pin: one file, three roots, three answers, and the middle one wrong.
Falling back to the whole directory's tree-less form rather than to the basename keeps the discrimination that guard was there for.
Not the whole path in every case, which was tried and measured and is why this row is narrow: comparing the full tree-less path everywhere collapsed chef's `lib/chef` against `spec/unit` and puppet's `lib/puppet` against the same, taking 428 of 797 and 590 of 1009 to zero, along with every one of fastlane's six gems.
Neither spec tree repeats the package segment its source tree carries, so nothing below the root is left to match on.
A spec tree is free to drop the package segment the source tree carries, and the tail below the root is what sees that
