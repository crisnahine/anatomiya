# A91

Section: A. Delivery

## Decision

A third hook fires on `Stop` and, once per change, blocks the end of a turn that added source lines in a scanned repository, with the one reason that asks a fresh-context subagent to find an existing function for them

## Why

Measured on four hard cases in this repository, three trials each and six for the chosen wording (`docs/research/one-line-that-finds-the-existing-function.md`): with no hook the duplicate stayed in 9 of 9; every wording the model answered inline passed 9 or 10 of 12, missing a rewritten `byCode` or `dirOf`, merging a look-alike of `extOf` it claimed matched, or deleting a genuinely new function with its file; the wording that hands the search to one subagent passed 24 of 24, which bounds its pass rate above about 88% and proves no zero.
`Stop` rather than `PreToolUse`, because a write made through `Bash` never reaches a `Write` matcher, and the working tree at the end of a turn holds every write however it was made.
It refuses nothing: `decision: "block"` stops no tool and no write, it asks for one more pass, and `stop_hook_active` lets the next stop through, so the cap of 8 consecutive blocks is never approached.
It speaks only where `isCorpusPath` passes a changed file with added lines: the same wording on a one-line markdown edit still spawned a subagent, measured at $1.05 and 68s against $0.48 and 16s.
Past the path, it asks through `corpusDrop`, the rule `check` applies to its changed files, so a generated file or a link asks nothing.
A migration, a numbered file right under a `migrate` or `migrations` directory or a `<name>_migrate` one such as Rails 8's `db/cache_migrate` (139 more corpus files, every one a migration or its spec), and a schema dump, `db/schema.rb` or `db/<name>_schema.rb`, ask nothing either: each restates the framework's calls by design and nothing calls it.
Measured on the corpus, 8,027 of the 9,485 files under such a segment that `isCorpusPath` passes are numbered files right under it; the rest, angular's schematics, prisma's `core/migrations`, openproject's `db/migrate/tables`, are library code and are still asked about.
A file whose every added line provably defines nothing callable asks nothing either, and such a hunk is left out of the list the reason calls "these added functions".
It covers three engines (`INERT_ENGINES`): a line rule for oxc and one for prism, described here, and the trees of the seven tree-sitter languages (B68, B73).
The line rule is an allowlist of line shapes per engine, read over the whole file (over each script block, in a component) so a line inside a block comment or a literal spread over lines is read as part of it: a comment (`//`, `/* */`, `#`, `=begin`), an `import`, an `export ... from`, a `require` or `require_relative`, a name bound to a literal (`const`, `let`, `var` or `export const NAME = <literal>` in JS and TS, with an optional type and `as const`; `NAME = <literal>` in Ruby, with an optional `.freeze`), a member of such a literal spread over lines, and a closing `}`, `]`, `)` or `end`.
A JavaScript block comment that is not closed on its line opens only where nothing but whitespace and one `{` stands before it, which is how JSX writes one; after anything else the line asks and carries nothing to the next line, since after code a `/*` may be a regex's `/` and its quantifier.
The line that ends a block comment asks nothing where nothing or one `}` follows the `*/`.
A line comment that holds `*/` asks, since a block comment the rule did not see open may end in it with code after the end.
A Ruby comment that holds `#{` asks, whether it starts the line or follows code, since inside a regex or a percent literal spread over lines it is no comment and the interpolation runs.
A literal is a number, a string with no interpolation (a JS template holding no `$`, a Ruby double-quoted string holding no `#`), `true`, `false`, `null`, `undefined` or `nil`, a Ruby symbol or `%w`/`%i` list, or an array or object whose members are only such literals.
Every other line asks, and a line longer than 400 characters asks unread.
It names what defines nothing because two earlier rules, each naming what might define something, were broken by shapes they left out.
A pattern for each definition shape silenced object-literal methods written mid-line (`module.exports = { double(a) { ... } }`), a method head spread over lines whose first line held a call, `new Function(...)`, `def_delegators`, `mattr_accessor`, `cattr_reader` and `class_attribute`.
The set of tokens that replaced it silenced a callable made by a call (`debounce(f, 300)`, `createSelector(...)`, `React.memo(C)`, `connect(m)(C)`, `compose(...)`, `createAsyncThunk(...)`), a plain alias (`export const useAppSelector = useSelector`), a styled template (`styled.h1` with a template literal), and Rails `enum`, `store_accessor`, `has_one_attached` and `accepts_nested_attributes_for`.
The hook asked about every one of them before either rule, and asks again now.
Parsing was measured and not needed: oxc imports and parses in about 6 ms but runs in the hook's own process, which the scan keeps it out of because a segfault there cannot be caught, and spawning Ruby for prism costs about 50 ms and needs Ruby on the path.
Measured on the last 200 non-merge commits of ten corpus repositories (the two private corpus ones, eslint, Ghost, cal.diy, mastodon, rubocop, discourse, forem, next.js), the rule skips 756 of the 9,223 changed files the hook would otherwise ask about (537 JS or TS, 219 Ruby), where the token rule skipped 2,911. oxc and prism were asked about every skipped file for anything starting on an added line that is a function, method, class, module, lambda, `new Function` or defining call, and past those for any call other than `require` or `.freeze`, any `new`, tagged template, interpolated template or string, spread, conditional, or name bound to anything but a literal, and found none.
Fifteen skipped files read by hand added comments, imports, a re-export, array members and a string constant.
Those counts are of the rule before the four comment rules above and the three below, and were not taken again.
0.15.1 read `const trailing = /\/*$/;` as the start of a block comment, so a function defined on the lines after it asked nothing until the next `*/`.
Counted over every JavaScript and TypeScript file under 1 MiB of the corpus's repositories, 144,292 files: 227 hold a line where an unclosed `/*` follows code; letting one `{` stand before it moved 1,180 lines in 174 files back to asking nothing, and 53 of the 227 still hold such a line, 29 of them in babel.
The line comment that holds `*/` moves 300 lines in 164 of those files to asking and none the other way, and the ones read quote a glob (`**/*.ts`), a block comment or the tail of a commented-out block.
Counted over every Ruby file under 1 MiB there, 66,132 files: the comment that holds `#{` moves 525 lines in 273 files to asking and none the other way, 139 that start with `#{`, 367 comments that quote an interpolation, which is the price in false asks at most, 18 rows of one list in puppet below a commented-out row, and one interpolation after code in an extended regex in rubocop.
A `/*` or a `=begin` that never closes asks about every line from it that is not blank, a string a backslash carries over lines asks on each of its lines, and a `/*` on the line under one the rule did not read opens no comment.
Counted over those 144,292 files and 66,132 Ruby files, 24,892,896 lines: the first moves 30 lines in 16 files to asking, every one a babel parser fixture of a comment that never closes; the second 6 lines in 2 files; the third 874 lines in 64 files, each a false ask for a doc comment in that spot; 910 lines in 82 files in all, and none the other way.
A run of whitespace is read as one character, a tab where it held anything but spaces: before that, 300 lines of `import` and a long run of spaces took 4,888 ms through the rule in its own test, and four such loops of 300 lines each (import, export, typed const, Ruby require) take 15 ms together after.
Given up: JSX text that starts a line with `/*` reads as a comment down to the next `*/`, since no line rule can tell it from one.
Given up: a backtick behind a backslash is counted as a real one, so a template literal that holds one is opened or closed at the wrong line, and lines ask that need not.
What this gives up: an import or re-export can give a callable that exists elsewhere a second name (`import { a as b }`, `export { a as b } from`) and asks nothing, since the function it names is already the existing one; and a definition whose every token sits on lines the edit left alone, such as a changed closing brace, is not asked about, since nothing callable was added.
What it asks about that defines nothing, each costing one search: a TypeScript `type` or `interface`, a local `export { a }`, a Ruby `module` or `class` line wrapping constants, a Gemfile `gem` line or any call with literal arguments, a Ruby heredoc or a `%w` list spread over lines, a member added to a hash that is not bound to a name, a string holding `$` in a JS template or `#` in a Ruby double-quoted string, every line of a JavaScript block comment opened after code other than one `{`, a line comment that quotes `*/`, and a Ruby comment that quotes `#{`.
A component, a `.vue` or `.svelte` file, is asked about the lines its script blocks added and no others: the added ranges are cut to the blocks of the file as it stands, found by the scanner the parse uses (B52), and trimmed to each body's first and last non-blank line.
Asked of every added line, the hook asked about a `<button>` added to a template.
The line rule is read once per block, over the file with everything else blanked, and a line is inert only where every such view says so: read over the whole file, markup holding `/*` put every script line below it inside a comment, so a function the script added asked nothing.
A turn that edited only markup or style asks nothing, and so does a component whose script never closes, a closed block before it included, since the parse rejects that file too.
What this gives up for a component: a function added in a template expression is not asked about, and neither is one in a script the scanner does not find, which is a Svelte script indented on its line and a Vue script below a template whose `{{` never closes.
Once per file as it stands, without writing anything: the reason ends in one mark per changed source file, taken over its content, and a file whose mark this session's transcript already holds is not named again.
The stop right after this hook's own block records what the check left through `systemMessage`, which 2.1.272 was measured keeping in the transcript as a `hook_system_message` attachment.
One digest over the whole diff was measured live, through `--plugin-dir` on a scanned clone, asking again on the very next turn, a prompt to reply "ok", about the fix the check itself had just written, at $0.70; with the per-file marks the same two turns blocked once, recorded the fixed file, and left the second turn silent at $0.057.
A stop another hook continued records nothing, since `stop_hook_active` does not say whose block it was, and a marker file would be one more change the next `git status` reports.
Not on `SubagentStop`: the main session's stop reads the same tree, and a block there would land on the search subagent the reason asked for.
A file is the session's only where its mtime falls inside one of the session's tool calls, from a `tool_use` record's timestamp to its `tool_result`'s, for every tool, widened a second each side for filesystems that keep whole seconds, so a Bash write and a subagent's write count without parsing anything.
FAT keeps 2 s, so there a file written within a second of a call's start or end can read as outside it and is not asked about, the safe way to be wrong.
A call run in the background runs on to the first record of its completion, a queue entry, a queued command or a user record that opens with `<task-notification>` and names the call first, so a prompt quoting a call's id stretches nothing; one with no completion recorded ends at its result, and one with no result charges nothing.
A file another session, an editor or a formatter saved between calls is not asked about, so a session opened on a tree somebody left dirty pays no search for work it did not do; one written by someone else during one of the session's calls still is.
A transcript whose calls carry no timestamps charges nothing.
The diff runs with `--no-ext-diff`, `--no-textconv`, `--no-color`, fixed `a/` and `b/` prefixes and a closing `--`, and `check` shares it: measured on git 2.54, `diff.mnemonicPrefix`, `diff.dstPrefix` or `color.ui=always` in a repository's config read every edit to a tracked file as none, a tracked file named `HEAD` read the whole change as none, a name git quotes lost its lines until the parse unquoted it, and a driver or text conversion is a command git would run.
`git status` still honours the repository's own config, as it always has for `check` and `scan`.
Each git read is held to 5 seconds, and every file a rule reads in one stop to 1 second together, the line rules and the loads, parses and walks of its tree-sitter files, inside the 15 the hook declares; the first load of the runtime and of a grammar counts against that second and cannot be stopped part way (B73).
A file moved with a plain `mv` reads as new, as it does in `check`, which costs a search and never a miss.
Paths a repository named are quoted in the reason wherever they hold anything past letters, digits and `./@+-`, since the reason is read as an instruction

The wording was measured on claude-opus-5 at medium effort, in one repository and one language, on cases written by the author of the hook, and a task prompt that tells the model to do nothing else was measured winning over it.
The reason ends with one sentence the 24-case measurement did not cover: "If this session has no subagent tool, run that search yourself."
The Stop payload names no tools, and a headless run with no Agent tool answered the ask with No such tool and spent its turn (issue #190 measured `error_max_turns` under `--max-turns 6`).
It is last so the measured wording is unchanged where the tool exists; whether it moves the 24 of 24 is unmeasured.
Staying silent where no Agent tool exists was refused: the only signal found is the transcript's `agent_listing_delta` attachment (present with Agent, absent without, measured on 2.1.285), an undocumented build detail whose absence on an older or newer build would silence the measured check where Agent does exist.
A stop whose transcript cannot be read, or holds no timestamped entry yet, asks nothing.
A hunk whose added lines reach past the last line that was read of its file asks, since nothing read those lines.
Both the session's start and the marks are read off it, and asking anyway blocked every turn over a tree left dirty before the session, with nothing ever recorded to stop it.
Nothing is asked while the git directory holds MERGE_HEAD, CHERRY_PICK_HEAD, REVERT_HEAD, rebase-merge or rebase-apply, because the tree against HEAD is then the other side's work.
That directory, and the index's root `.gitattributes` that `corpusDrop` reads, are asked beside the status read, so the reads in a row stay two.
A record below its checkout's own `.git` asks nothing, because git names paths from the top and a scan writes its record there.
A turn that commits what it wrote is read from the reflog rather than from state this writes: the turn begins at the last user entry a person wrote in the transcript (a tool result and a hook's reason are user entries too and are skipped), and the commits `logs/HEAD` records after it, from the turn's last checkout, pull, reset, merge, rebase, first commit or merge commit on, are the turn's own, each dated inside one of the session's tool calls, an Agent call's subagent commits included, widened a second each side for the reflog's whole seconds, and a commit outside them ends the run the way a checkout does; one diff from the first one's parent to the tree reads committed and uncommitted work together, so the git reads in a row stay two.
A file a turn created and committed is listed by its lines without the (new file) label, since the diff does not say it was created.
One gap is named rather than closed: a write another session makes during one of this session's tool calls, or within a second of one, is charged, since Stop cannot tell writers apart.
Narrowing to tool paths would lose every Bash write, and to the turn's own start an interrupted turn's work, since Stop does not run on an interrupt.
A filesystem with 2-second mtimes (FAT) can miss a file written in a call's first two seconds, and a background job still running at Stop has its writes asked about at a later Stop, once its completion is recorded.
