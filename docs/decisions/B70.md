# B70

Section: B. Engine

## Decision

The checker builds one program from the root config and reads no package's own `tsconfig.json`. Measured and refused

## Why

Measured 2026-10-11 on the four workspaces that degrade with a per-package layout (`docs/measurements/2026-10-11-per-package-tsconfig.md`): one program per tracked package `tsconfig.json`, each read under the root's containment, took prisma 65.9% to 65.9%, react 60.2% to 62.4%, Ghost 54.9% to 63.3% and eslint 60.9% to 60.9%, none over the 0.80 floor, at 1.12 to 4.25 times the root program's wall time; peak memory stayed inside the child's heap.
The package configs lift the TypeScript they govern (Ghost 60.9% to 82.5%, react 84.1% to 95.9%) and reach none of the untyped JavaScript beside it, which is most of each population; prisma's gap is its workspace packages exporting an unbuilt `dist/`, which no config read fixes

## Status

**done** nothing shipped: `tsconfig.mjs`, `semantic-worker.mjs` and `semantic.mjs` are unchanged and the checker stays one program (B7).
Given up: those four workspaces stay degraded, and a TypeScript-only workspace with per-package settings and no root config still reads under the floor.
Reopen with a repository where the package configs alone would carry the rate over 0.80
