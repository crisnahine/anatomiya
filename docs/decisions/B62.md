# B62

Section: B. Engine

## Decision

`parseTreeFile` copies a wasm tree into plain objects and deletes it in a `finally` before it returns. Rows, facets and the check read the copy, never the tree

## Why

A wasm tree is memory the collector does not free, and a node read after its tree is deleted answers wrongly without throwing.
Measured on a 990 KB Python file in one process: with every tree kept, resident size grew about 47 MB a parse and the 44th parse threw `RuntimeError: Aborted()`; with the copy and the delete it stayed between 340 and 435 MB from the 10th parse to the 300th, over two runs.
The copy walks with a cursor and a list of open nodes, since a recursive copy runs out of stack on a deep tree.
Given up: the copy holds named nodes only, so an anonymous token is seen only under a node type its language lists in `tokensOf`, and a leaf's text is cut at 256 characters.
A tree too deep for the channel to the parent to carry is read by `scan`, which asks for counts, and is `crashed` to `check`, which asks for the tree, as a JavaScript tree too deep to send is: 100,000 nested brackets come back `ok` in counts mode and `crashed, the tree is too deep to send` in tree mode, in all seven grammars, so a file the map counted can be one `check` cannot examine
