# E3

Section: E. Baseline and drift

## Decision

Unreachable baseline sha: verify with `git rev-parse --verify --quiet`, then drop to counts-only until a human re-pins. Never fall back to stored counts

## Why

Squash-merge-to-main is the common workflow, not the edge.
`git cat-file -e`, which this row first named, exits 128 for a commit that is not there and for a git that refused alike, measured on git 2.39.5 and 2.54.0, where `rev-parse --verify --quiet` exits 1 for the first and 128 for the second (F29)

## Status

**done** `baseline.mjs`, `reduce.mjs`, `git.mjs` (`shaReachable`).
`shaReachable` answers yes on exit code 0 and no on exit code 1, and is never answered from memory (E14).
A pinned commit git could not be asked about is no unreachable one: the scan and the check stop, and the refresh worker ends (F29).
`baseline.mjs` (`readPin`): a pin file that is there and will not load (not JSON, another schema, a half-shaped area, oversize) drops to counts the same way, under status `pin-unreadable`, and the scan, the check and `pin` say why instead of "no baseline pinned"; `loadPin` keeps its null, so the refresh worker is unchanged
