# F13

Section: F. Safety

## Decision

History is read off the stream, and history git could not read is told apart from history that is empty, by exit code rather than by message

## Why

Measured: buffering put an oversize log in the same silent branch as a repository with no commits.
Every file came back with no author, every dimension failed the author gate, and the map stated nothing with nothing to say why

## Status

**done** `authors.mjs` (`authorsByFile`, `headState`), with the stream read in `history.mjs` (`historyFields`) through `gitStreamed`.
A shallow probe git could not be asked is unread history whatever HEAD says, so a repository with no commit carries that error too (F29).
A history store does not stand in for a history git cannot read: a failed walk leaves no store, and a failed read of the order or of the missing commits is the full walk, which says so.
One case is open: a tree or a blob lost after a store was taken, with the commits intact, is answered from the store (D15)
