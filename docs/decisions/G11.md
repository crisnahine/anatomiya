# G11

Section: G. Scope

## Decision

Every measurement trial runs at one named engine, `claude-opus-5[1m]` at `medium`, stated on the command line and recorded in what the run produces. A batch of another model or another effort is a different question and never merges into a held one

## Why

The harness said every setting was fixed rather than inherited and named only the model.
Effort was inherited, and 2.1.250 reads `CLAUDE_CODE_EFFORT_LEVEL` ahead of the session's own effort, refusing a settings bridge with "CLAUDE_CODE_EFFORT_LEVEL overrides effort for this session" in its own words, so an exported level decided every trial while nothing recorded it.
More variables move the model, the thinking budget or the context window the same way, so the child environment is cleaned of every one of them by name and of the `ANTHROPIC_DEFAULT_<alias>_MODEL` and `ANTHROPIC_CUSTOM_MODEL_OPTION` families, and keeps everything naming a credential, an endpoint or a region.
Read off the build by name rather than matched by shape, on evidence: a shape wide enough to catch `MAX_THINKING_TOKENS` also catches `ANTHROPIC_SMALL_FAST_MODEL_AWS_REGION`, and one narrow enough to spare the region lets a trial run with thinking off while provenance records `medium`.
The context group is in it because the pinned model is the 1M one: the build strips `[1m]` and asks for the window with the `context-1m-2025-08-07` beta header, which `CLAUDE_CODE_DISABLE_1M_CONTEXT` takes away.
`medium` is a level `--effort` takes on this build (`sg=["low","medium","high","xhigh","max"]`) and Opus 5 pins no launch effort, unlike opus-4-7, opus-4-8 and fable-5.
The flag is not the last word, though: `settings.env` sits above it, so a settings file naming `CLAUDE_CODE_EFFORT_LEVEL` decides the trial, and an arm is a checkout of the repository being measured.
`--setting-sources ''` looks like the answer and is not, measured on 2.1.250: an arm holding a `paths` rule answered with the map's file count with the sources loaded and NONE without, so excluding them removes the map the experiment installs.
Both settings files are taken out of each arm instead, which leaves the rules directory where it is, and `measure-defaults` refuses to start when a user settings `env` entry names one of them.
An A/B trial loads only the project and local sources, which the arm has cleared (G13), so `ab.mjs` has no such gate.
Only `env`: measured on 2.1.250, `--effort` beats `ultracode: true`, `modelSettings` and `effortLevel`, so refusing on those would fail a machine merely configured for ordinary work and refuse a run the flags were deciding correctly.
The machine this was written on carries `effortLevel: "medium"` with `modelSettings["claude-opus-5"].effortLevel: "xhigh"`, which is what the old harness ran at, since it passed no effort at all; the stated flag is what takes that back.
Managed policy and an organisation's own effort cap sit below neither and cannot be reached from here, and the harness says so rather than claiming a level it cannot guarantee.
The merge guard reads both halves: two batches summed into one tally claiming 60 samples of a run that never happened.
An entry measured before the effort was recorded carries none, and that absence matches no batch that names one, since reading it as `medium` would date those runs to a setting nobody can check; `--force` replaces such an entry with one that says.
A refusal prints which half it disagreed on, because the trials are paid for by the time it fires, grouped by the engine in the way rather than one line per key.
The model string moved too, from `claude-opus-5` to `claude-opus-5[1m]`, so all 24 measured rows in the shipped table refuse on both halves and stand at the older engine's answer until somebody re-measures them with `--force`, which replaces rather than adds.
That cost is the price of not blending two engines into one tally, and `docs/how-it-works.md` says it where a reader of the table will find it.
So the flags are treated as a request and the answer as the record: every trial asks for `--output-format json` and reads `modelUsage` back, which names the model that served it and the window it got, and provenance carries those rather than the flags.
Nothing else can confirm the 1M half, since the `[1m]` suffix never reaches the wire and becomes the `context-1m-2025-08-07` beta header.
Trials that report two engines refuse to be written up as one, and a batch that reported none records the request and says the observation was missing.
`CLAUDE_CODE_NO_MODEL_FALLBACK` is set rather than scrubbed, on the build's own words, "model substitution is disabled": a trial now runs the pinned model or fails, instead of answering from a substitute under the pinned name.
A hand-written list against one build is a guess in five years, so a test reads the installed build for every name shaped like a model, an effort or a thinking budget and fails on one nobody has ruled on; the ones kept on purpose are listed with their reason in `KEPT`.
The evidence for all of this is `docs/research/one-model-one-effort.md`, read off build 2.1.250
