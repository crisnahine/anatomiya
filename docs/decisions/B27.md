# B27

Section: B. Engine

## Decision

A bare `test "..." do` call with a description, inside a class or module body, is minitest

## Why

`RUBY_TEST_CALLS` already held `test`, but nothing set `minitest` from a call, only `testCalls`, and `test` was deliberately kept out of `RSPEC_CALLS`.
Measured on plots2: 23 of 34 mislabelled files use exactly this declarative shape (`ActiveSupport::Testing::Declarative`), no literal `def test_*`, no listed superclass, the dominant cause on that repository, larger than the missing superclass list.
Scoped to a class or module body rather than any bare call: the macro is mixed into `Minitest::Test` subclasses and cannot run anywhere else, so a bare top-level `test "x" do` proves nothing.
A class body alone is not enough either, because `test` is an ordinary word: an in-house rules engine naming its conditions with the same description-and-block shape read three production authorization classes as minitest specs, in their area's own line and in the repository-wide tests line.
So the macro asks for the evidence `def test_*` already asks for, the superclass or the path, plus the `Test` suffix minitest gives its own classes
