# B79

Section: B. Engine

## Decision

A worker the pool's clock killed, or the ready clock killed, is handed no further file. Its reply already on the way is kept, and its exit spawns the replacement that takes the queue

## Why

A reply already queued on the channel when the clock kills the worker still runs `finish` and then `release`, which handed the dead worker the next file.
Its `exit` then reads as a timeout, so that file, which never ran, was charged `parser timed out` and crashed, in a one-worker pool at once and for tree-sitter in a pool of any size (B66).
Measured with a worker that busy-waits D ms on one file and answers the next at once, one worker and a 40 ms clock: at D of 39, 40 and 41 ms, 1, 4 and 6 of 30 rounds charged the innocent file; with the guard, 0 of 30 at each.
The file blamed changed from run to run and moved the crashed count in the overview
