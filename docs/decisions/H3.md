# H3

Section: H. Layout

## Decision

Six shell names are descended past: `src`, `lib`, `app`, `apps`, `packages`, `source`. Every other directory name is printed

## Why

Those six say nothing about what is inside them, so a line naming one carries no fact a reader can use.
Six words rather than a list that grows, because the rule is "this name is empty" and a longer list starts deciding what a name means, which is H2 arriving through the back door.
A Ruby gem's `lib/<gem>` is descended twice, once as a shell and once as a wrapper, and lands on the name the gem actually uses.
`apps` sits beside `packages` for the reason `packages` is there at all: a monorepo splits independently named things under a plural wrapper, and a repository laid out as `apps/*` plus `packages/*` names the same shape on both sides.
Measured on supabase, where `packages` already descended into each package while `apps` rolled seven sites, a product dashboard, a marketing site, two showcase sites, a docs site and a course app, into one bullet, and the always-loaded namesake rate printed a blend of 4.0% over the dashboard's own real 6.9%, diluted by about 1,558 files from sites nobody was going to write per-file tests for
