# G24

Section: G. Scope

## Decision

The website is the static files under `site/`, filled in by `scripts/site.mjs` from the repository it describes and deployed to GitHub Pages by `.github/workflows/pages.yml`: its examples are fenced blocks of the README and the usage guide, its results chart is the README's reuse tables, its counts come from the registry, DECISIONS.md and the code index, and its find demo runs the plugin's own `find.mjs`, copied byte for byte, over the index a scan of the deployed commit wrote. No framework, no build tool beyond that script, and no script or style from another origin

## Why

A page that restates the README drifts from it the first time a number moves, and the README is the copy the docs gate holds. Filling the page at build time leaves one copy of each fact: a placeholder the build cannot fill, a heading the page names that the README lost, or a table it can no longer read stops the build rather than shipping braces or a stale count.
The find demo is the ranking code itself rather than a recording of it. Its four modules use no Node global, and the one Node import among them, `node:path` in `paths.mjs`, is reached only by a function the demo never calls, so the page's import map points that specifier at a stand-in that throws if it ever is. A test holds the module set and the import map to each other, so an import added to `find.mjs` fails the suite before it breaks the page.
Plain HTML, CSS and one module script: a static-site generator would add a dependency and a build for one page. The job that installs and scans holds `contents: read`, and the deploy job holds `pages: write` and `id-token: write` and runs nothing but the deploy action, the split the release workflow already makes (G23).
