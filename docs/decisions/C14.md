# C14

Section: C. The counted-claim model

## Decision

A capability-routing row is offered only where at least three examined files already route through a wrapper; the filename vocabulary is the check's fallback where no map exists

## Why

The most cited agent symptom is framework-default code instead of the repository's wrapper, and the wrapper is repository-specific by construction.
The vocabulary alone over-offers (a repository holding a `config.ts` nobody imports has a name, not a habit) and also under-offers: the Ruby logger conforms on `Rails.logger` receivers no filename carries, so requiring the vocabulary silenced the row on the repositories it is for.
Adoption alone decides, and a line that can only read zero never ships (C8).
Three adopting files is the same bar the concentration gate uses for evidence being worth counting.
Keys are split per engine (`route_logging` beside `logger_over_puts`) because one key is one predicate, and the two engines read different trees; adoption is counted per repository across both engines, deliberately, because a wrapper habit is the team's rather than a language's
