# F17

Section: F. Safety

## Decision

A file in `.claude/rules/` is read by its head and only when it is a regular file, and every listing of them is bounded

## Why

Measured: the ownership test is a regex anchored at byte zero, and it was reading whole files to run it.
A tracked symlink to a 400 MB blob took a scan's peak resident size to 1.2 GB; pointed at `/dev/zero` the read never returned at all, and a symlink is available on every Unix box.
A directory named `anatomiya-overview.md`, which is a fixed name a repository can spell, threw `EISDIR` out of the atomic rename and failed every scan with an errno.
The check listed every name it found, into the context of the agent reading the report

## Status

**done** `rules.mjs` (`readHead`, `HEAD_BYTES`, `occupied`, `listSome`), `check.mjs`, `render.mjs`, `summary.mjs` (`LISTED.report`).
The cap is sized by our own frontmatter rather than by a guess at how long one should be: an area's `paths` list is one line per pattern, and a cover needing 170 of them is 14 KB on canvas-lms, so a first cut at 8 KB put that file's closing fence past the head and this tool's own output came back as a file it had not written, never removable and named as somebody else's in the always-loaded overview.
A megabyte is far past any cover generated across 35 repositories and far short of a file worth holding in memory.
The head is opened first and typed on the handle it is read from, non-blocking so a fifo cannot hold the open, because a stat on the path and then an open of the same path is two lookups and a symlink swapped between them reads something the type test never saw; a shape the platform refuses to open at all, a socket under whichever errno that platform refuses with, or a directory wherever one will not open, is typed on the path with nothing read after it, and still occupies the name.
A file the tool cannot open is its own answer rather than an empty one: read as empty it failed the frontmatter test and came back as somebody else's, which the always-loaded overview then said out loud about the tool's own output, and which no later scan could undo because a file called foreign never re-enters the removable set.
A directory that will not list is reported for the same reason the symlinked one is.
In `.cursor/rules` and `.github/instructions` (A102) only an entry under the `anatomiya-` prefix with that directory's extension is opened, by the same head read, and nothing else there is read: the rest is that tool's own rules, which are meant to be there
