# A35

Section: A. Delivery

## Decision

A stated claim that is perfect and names no exception says, in one clause, which form its own predicate declined to count. A row carries the clause only where one short true clause names the whole exclusion and holds wherever the row does, and the clause is pinned by running the predicate rather than by reading it

## Why

The counts were right and the line read as false, which is worse than a wrong count because the reader who checks is the one who stops trusting the map.
`src/components/Calendar` printed "a prop spread lands on a component, not on a host element / 46 of 46 sites across 5 of 6 files", and one of the five credited files holds `<div {...rest} />` three lines above `<ClickableArea {...rest} />`.
Nothing was miscounted: a wrapper forwarding a rest binding has no list of prop names to write instead, so it is not a free choice and not a site, and the dimension has carried that reasoning in prose since it was written.
The prose was never rendered anywhere.
Four more instances of the same shape sat in that one map, each a perfect count beside a credited file holding what reads as its counter-example.
Only under a claim that is perfect and carries no `except`, because the `except` list is what teaches a reader that a miss gets named, so a bare `N of N` is read as "there is no counter-example in these files", which is stronger than anything the tool measured.
The second bar is what the row is really worth, and the first is why every clause here is pinned by a fixture that runs its row: a clause written off the `sites` prose and never run against the predicate it describes was wrong or partial far more often than not, so the fixtures are the evidence and the prose is not.
Two were false outright, including the worked example above, which had dropped the condition that the exclusion applies only onto a host element: a clause reprinted in this file and in `docs/how-it-works.md` is wrong in three places at once.
The ones that could not be corrected inside a line were the ones whose exclusions are genuinely a list, and a list belongs in `sites`, which nothing prints: `module_include` alone declines five separate shapes.
The middle bar is the one a first pass got wrong in both directions.
A decline that drops a whole file is one the reader cannot meet: the file is not credited, and `N of N sites across X of Y files` already says a file went uncounted, so a line there restates the count above it.
That is why the two migration-wide Rails rows carry none while `column_null_declared` and `reference_foreign_key` do: a `create_table` block can hold four counted columns and one `t.string :name, **opts` that was dropped, all under a perfect `4 of 4` in a file the claim credits, and nothing on the line reveals it.
Ten rows were dropped: the six Ruby rows for length, both naming rows for length, and the two migration-wide rows for granularity.
A41 revisits the filename row: what it owes a reader is a count rather than a sentence, and a count needs no clause and no line.
`absent_is_null` fails the first bar rather than the second, since its sentence names no React effect callback, and it had this repository's own `scripts/` directory, a Node CLI, advertising React.
Twenty remain, each pinned by a fixture that runs the declined form and asserts no site, beside one the row does count, so a fixture cannot pass because nothing parsed.
A41 adds no twenty-first.
A row that grows a clause and no fixture fails the suite, because shape is all `assertApplicability` can check and prose cannot be asserted at all.
The clause prints once per file rather than once per row: nine companion rows share one sentence and two of them reach the same area whenever a repository writes both `_spec.rb` and `_test.rb`, which printed it three times in one `app` area.
Keyed off the registry and not stored on the record, because both readers of the layout have a key and only one has the prose
