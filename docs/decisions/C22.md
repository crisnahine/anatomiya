# C22

Section: C. The counted-claim model

## Decision

`class_base` excludes a class whose superclass is one of Ruby's own exception classes, from a closed table plus the `Errno::` prefix, and the fold excludes a site whose own qualified name is the class the area learned

## Why

Conforming makes an error class a non-`Exception`, and `raise` then answers `TypeError: exception class/object expected`.
Six areas of one repository learned `ActiveInteraction::Base` with a perfect baseline, so the next error class anyone added to any of them was a MUST-FIX, and every Rails service directory grows error classes.
The self-base half is the same absurdity printed on the page: `app/models` states "classes here inherit ApplicationRecord" and lists `application_record.rb` among its own exceptions, and `class X < X` is a NameError.
Together they were 37 of that row's 75 violations.
Only the language's own exception classes, so a repository that gives its errors a base of their own keeps every subclass and the row still states there; the superclass decides it and never the name, because `class ClassifyTransactionError < ActiveInteraction::Base` is a real class.
The learned-class half matches `self === learned` or `self` ending in `::learned`, because a subclass inside `Api::V1` writes the bare `BaseController`; matching the last segment of both would drop `class Base < ActiveInteraction::Base`, which is also a real class
