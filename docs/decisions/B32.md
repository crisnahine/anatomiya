# B32

Section: B. Engine

## Decision

A declaration file is parsed with its own grammar: `.d.ts`, `.d.mts` and `.d.cts` route to a `d.<ext>` grammar rather than the plain one B14 already routes `.ts`, `.mts` and `.cts` to

## Why

`grammarFor` maps all three to one grammar, so a `.d.ts` reached oxc as a synthetic `f.ts`, and a bare ambient `export const x: T;` with no initializer, legal only in a declaration, was charged "Missing initializer in const declaration".
Confirmed on ghost's `db/index.d.ts`, eslint's `use-at-your-own-risk.d.ts`, two babel files and next.js's `packages/next/cache.d.ts`, a real shipped public API file.
Narrower than it first looked, and the refutation is worth keeping: full populations on prisma (267 files), supabase, storybook, cal.diy and canvas-lms parse identically either way, because the three extensions already share a grammar, so a `.d.ts` only mis-parses when its own content is illegal under plain TS
