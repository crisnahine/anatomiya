# H5

Section: H. Layout

## Decision

The roster describes the tree as it is; the five learned rows read the baseline like every other row (D6)

## Why

The roster is counts and never a directive, so there is nothing in it to launder: a tests line that moves when an agent adds a test file is a true count that flips no claim, exactly as the area listing's file counts already are.
A learned row states a sentence, so it reads the pinned population.
The one thing the roster refuses is a subset: a truncated corpus prints `layout: not counted, the scan was truncated` and no roots, because counts over an arbitrary slice of the tree rendered as a description of the tree is what F7 exists for
