# C57

Section: C. The counted-claim model

## Decision

A NIT on a slot no gate stated prints the line the area file prints for that slot, through the same function: its sentence, its scope clause, `: no convention.`, its count and its gate, never the majority side's sentence alone. Such a finding carries `toldInClaim`, and the text and GitHub writers say the gate once. A slot whose scope names the kinds it was counted over raises nothing, at any severity, on a file of another kind, since the claim was never counted over that file

## Why

On fastapi, `docs_src/security` types 8 of 70 functions and states nothing, so a new typed function there drew `NIT functions declare no return type`, while the `fastapi` package types 334 of 334: a true count printed as advice to drop the annotation.
It reads `functions declare no return type: no convention. 62 of 70 sites (ratio)`, the area file's own words.
A claim's own full stop is dropped before the colon, after a word only, so `?.` keeps its dot: 0.14.0 printed `not through React.: no convention.` in 650 area files of 18 corpus repositories (`docs/measurements/2026-10-11-what-changes-in-an-existing-map.md`).
Dropping the NIT, or holding it where the repository states the other side, would each add a rule the map does not carry.
The scope clause comes from the slot's `scope` (B56), so a record read by `check` prints the clause the area file printed; a record without it prints none, as before.
Matching the reason's prose to drop the doubled gate broke whenever either string moved, so the finding says so in a field
