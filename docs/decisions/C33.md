# C33

Section: C. The counted-claim model

## Decision

A fact a predicate could not read is evidence for nothing, in either direction: the site holding it is declined rather than judged, and a statement that cannot be matched neither credits nor charges what it might cover

## Why

One shape convicted and its twin declined, on the same fact.
`options` dropped an entry whose key is not a literal and returned the rest, so `t.string :name, key => false` read as a column declaring nothing while `t.string :name, **opts` declined the site; a `null: false`, an `id:` or a `foreign_key: true` written behind a constant, a local or an interpolated symbol was charged as absent, and `check` grades against that.
Declining under-counts the population, which `N of N sites across X of Y files` already reports; convicting invents a violation the reader cannot fix.
The same fact reached C32's evidence lookup three ways, each found by executing the rows rather than reading them: a statement whose table could not be read was dropped, so the reference it may cover read as a column with no key; one whose `column:` could not be read matched by the plural of the reference name and credited a reference it may never have covered; and a reference on a table that could not be read was charged, since no key can be matched to it.
A key is matched on the table it is added to and the column it covers, so a statement missing either is kept as evidence for nothing and blocks what it might be the key for, and the block is lifted where the options declare the key inline, which is evidence on the site itself.
Each half is ruled out on its own, which is what keeps the block from spreading: a statement on `editor_id` is not a reference on `author_id` whatever table it was added to, and a statement added to another readable table is nobody's key here, so only the fact this tool could not read blocks anything.
Not a blanket decline: measured over 35 repositories, 7,902 migration files hold 8,268 column sites, 1,732 `create_table` sites, 1,758 reference calls and 511 foreign-key statements, and blocking a reference on an unreadable table against every key in its class lost canvas-lms a site its own comment says is a deliberate violation, `create_table :"aua_logs_#{index}"` holding a `t.references :asset_user_access` no statement in that migration covers.
Asking whether a key covers the column keeps it.
2 of the 511 statements are unreadable, both in one openproject migration whose references declare their keys inline, so none of the four counts moves
