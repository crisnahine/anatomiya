# G10

Section: G. Scope

## Decision

A file is dropped from the corpus when its own head carries a generated-file marker in its first ten lines (`@generated`, `Code generated by`, or `DO NOT EDIT` beside a word about generation), or a root `.gitattributes` declares its path `linguist-generated`, whichever directory it sits in

## Why

The fixture gates catch code that looks unusual: old syntax, a foreign copyright, one or two authors.
Generated and vendored code looks ordinary, because it was ordinary somewhere else, and it carries the real git-blame authors of whoever ran the generator or committed the copy.
Proven three ways with plant-and-catch: babel's compiled runtime helpers stated 2 of 20 directives from code nobody typed, and stripping an extension from one produced a real FIX; prisma's `contract.d.ts` files, every one stamped `// GENERATED FILE - DO NOT EDIT`, stated two more from a 24-file area that is 100% generator output, and dropping `type` from one import produced a real FIX; next.js vendors about 678 files of byte-for-byte `@babel/runtime`, stated as its own conventions with four authors

## Status

**done** `corpus.mjs` (`isGeneratedHead`, `generatedAttrRules`, `isAttrGenerated`, `classify`), pinned by `test/corpus.test.mjs`.
`check.mjs` asks the same classifier of every file it examines, through `corpusDrop` in `corpus.mjs`, and drops one refused as generated, so a branch that regenerates a client is not judged against claims counted without it.
The read is bounded to the first ten lines of the first 4 KB.
Bytes alone protect against a single-line minified file the way the parser's own size cap does, and lines are what put the stamp where a generator writes it: `DO NOT EDIT` on its own is an operational warning, and a hand-written file carrying one was dropped with no trace anywhere in the map, since `collect` drops before anything counts.
It now needs a word about generation beside it, and this tool's own `corpus.mjs` had cleared the byte cap by 1,756 of them, which is not a property anyone was maintaining.
What is dropped is named in "Not covered", because a reader who knows the directory is there would otherwise see a map that has never heard of it.
The `.gitattributes` reader takes the root file only, read from the index where the index marks it skip-worktree (a sparse checkout that leaves it out) or assume-unchanged, since git then counts the tree's copy as no change and a pin records HEAD, and three pattern shapes, not gitignore's full grammar; anything else is skipped rather than guessed at.
The file is dropped rather than the directory, so a directory whose files overwhelmingly carry the marker falls out of a stated directive by losing its evidence rather than by a second rule about directories, and a hand-written file beside ninety generated ones still counts.
Not closed: generated code carrying neither a marker nor a declaration, which is babel's own runtime-helper shape, confirmed only by reading its Makefile.
The three shapes are placed the way git places them, checked against `git check-attr` in `test/corpus.test.mjs`: a leading `/` anchors at the root and is not part of the path, a pattern with a slash elsewhere is anchored too, and a slashless one matches the basename at any depth.
Before, `/gen/**` matched nothing, since no listed path starts with a slash, and `schema.ts` matched only at the root.
A bare directory name sets nothing on the files under it, as in git, where attributes are not inherited the way ignores are.
