# A100

Section: A. Delivery

## Decision

A hook process loads only what its verb uses. The binary's one static import is `node-floor.mjs`; it imports `encode.mjs`, `payload.mjs` and `targets.mjs` once the node floor passes, and each arm of its command table imports its own module when it runs

## Why

`targets.mjs` is a leaf that imports nothing and holds the names `--targets` takes.
The hook verbs live in `hook-verbs.mjs` and the refresh worker in `refresh-run.mjs`, the only refresh module that imports `commands.mjs`.
The Wilson bounds and `GATES` are a leaf, `gates.mjs`, and the capability stems and a URL path's words another, `stems.mjs`.
A module a hook reaches loads the Ruby bridge, the end-of-turn change reader, the notice's rules and the type checker's version test only inside the function that runs them, and `encode.mjs` builds its grapheme segmenter on the first cap.
Every hook process loaded 65 modules at run time, `walk.mjs`, `scan.mjs`, `check.mjs` and `reduce.mjs` among them, because the binary imported every command up front, `facts.mjs` took one bound from the reducer, `corpus.mjs` took three vocabulary helpers from the capability rows, `readiness.mjs` imported the Ruby bridge for the node floor check, and the Stop hook's change reader sat beside the echo.
A hook runs on every tool call.
The split left 13 for the echo, 13 for a notice that is answered before its rules and 25 for one that reads them, 22 for the end-of-turn reuse check and 28 for the refresh, none of them the scan, the parser, the walker, the reducer or the check, and none from `node_modules`, where 0.13.3 loaded 7 from it.
Modules counted at run time, distinct files a load hook saw, the binary included.
The timings that follow are of a build one module lighter per hook and two lighter for the reuse check: `rules.mjs` loads `targets.mjs` (A102) and `reuse.mjs` loads `script-blocks.mjs` (B52).
Measured from frozen copies of 0.13.3 and this build under the bench lock, 15 alternating runs each at load 3.5 to 3.8 with bare node at 25.5 ms, medians: echo 65.0 to 39.3 ms, 39.5% less, notice 64.7 to 39.4 when it is answered before its rules and 67.9 to 43.3 when it reads them, the end-of-turn reuse check 107.8 to 89.9 and the refresh 68.7 to 44.6; peak RSS about 60 MB to about 51.
A failed import is a throw inside the never-fail boundary, so a hook whose module will not load still answers `{}` and exits 0
