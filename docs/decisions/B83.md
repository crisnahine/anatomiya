# B83

Section: B. Engine

## Decision

A row is handed one file context by every bridge and by the check, `fileContext` over `FILE_FIELDS` in `walk.mjs`: the path, the language, the source the tree was parsed from or null, the parser's comments and the facets the bridge read or null, every field present; a guard holds each caller to it

## Why

The oxc bridge handed a row three fields, the prism bridge one, the tree bridge four and the check four, and the contract lived in a comment inside `collectHits`.
A Ruby row reading `extra.source`, or a JavaScript row reading `extra.facets`, would have counted in the check and read `undefined` in the scan, so the map and the check would have disagreed with no error either side; the rows that shipped read only `rel`, `source` and `comments`, so no map moved.
The 12-repository corpus oracle read byte-identical plan, result and index hashes before and after the one shape.
