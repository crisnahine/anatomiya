# H49

Section: H. Layout

## Decision

In those seven a function named like a case is one only beside its runner's import, a PHP base class ending in `TestCase`, or a path the language's own tool collects by

## Why

An import is matched on the module it names.
An annotation renamed by its import is read through the import.
A `conftest.py` is pytest's by its name, and a `.rs` file cargo builds by its place is cargo's, with a case in it or none.
The import rule alone reads 179 of django's test files, 289 of fastapi's, 8 of composer's and none of Slim's; the three together read 848, 519, 185 and 29.
The ordinary pytest file imports nothing from pytest, django's cases come from `django.test`, and Slim and composer extend a `TestCase` of their own so 206 of their 214 test files import nothing of PHPUnit's.
The path is read only where the tool reads it: `_test.go` for Go and nothing else (10 files in caddy and hugo declare `func Test` or `func Fuzz` outside one, and `go test` runs none), `test_*.py`, `*_test.py` or a test tree for Python (1,375 django files under `tests` wear no test name and 222 hold cases), `*Test.php` under a test tree for PHP, and for Rust a `tests` directory anywhere above the file or the name `tests.rs`: there a `#[test]` makes the file a test file, and in any other file it leaves a source file that holds its own tests (H51). tokio keeps a module's unit tests in a `tests.rs` beside it, 5 files, and all 5 hold cases.
A runner matched as any segment of an import reads `from app import unittest`, `from .unittest import x` and `import "my.testing"` as runners.
Read by the written name alone, `import org.junit.Test as T` with `@T`, `using T = NUnit.Framework.TestAttribute;` with `[T]`, and `[FactAttribute]` are each no case.
A pytest fixture named `test_client` and a function inside a function are not cases. pytest reads a `conftest.py` by name wherever it sits, for the fixtures and hooks in it: 3 files in flask and 3 in fastapi, none of them holding a case and none in django, each read as `pytest` with no case, which is how a Go `_test.go` of helpers reads.
A file H48 takes by place is told so by its caller, since a crate is known by the files around it and a parse sees one file, and reads as `cargo test` with no case: 12 of ripgrep's 15, 7 of tokio's 287 and 4 of serde's 23.
So a file the layout counts as a test file is one by its facets or its name alone, and the rows that leave test files out (C50, C53) leave out the same files.
A case nothing imports a runner for is `pytest` at file level or in a class with no base and `unittest` in a class something made: 3 of django's 848 read `pytest` and none of flask's or fastapi's 546 read `unittest`.
Not read, and said so: a case a macro declares (ripgrep's `rgtest!`: H48 takes the six files of them directly under `tests` by place, and the two under `tests/index` read as no test; a `#[test]` written inside a `macro_rules!` body is the same, H51), JUnit 3 by superclass (6 files in the three Java repositories name `junit.framework.TestCase`), and PHPUnit's `@test` docblock.
Read wrongly, and known: an annotation type that itself carries `@TestTemplate` is read as a case, so junit's own `RepeatedTest.java` and `ParameterizedTest.java` count as tests
