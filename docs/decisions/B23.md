# B23

Section: B. Engine

## Decision

Whether an engine is ready is one probe carrying one remedy per engine (`doctor`), and installing the node-hosted one is a command of its own (`setup`)

## Why

`/plugin install` copies the files and does not run `npm install`, so the first run a marketplace user gets is the one with no parser in it (B13), and nothing in the tool could put one there: the README told them to run npm by hand in a directory it did not name.
Three engines were detected three different ways and their remedies were spelled at every printer that needed one, so a machine with no `ruby` on it was told to run npm, which is the one remedy that cannot work.
The install belongs in the plugin's own directory rather than in the repository being scanned, since every command runs inside somebody else's tree

## Status

**done** `readiness.mjs` (`readiness`, `remedyFor`, `readinessLines`, `pluginRoot`, `unsupportedNode`).
The node this process runs on is the first row, held to 22.0.0, the floor both manifests declare in `engines`, and a test holds the three together.
Nothing enforces `engines` for a plugin: on Node 20 a scan died on `Map.groupBy` while doctor called every engine ok.
The entry point asks `unsupportedNode()` before every verb but doctor, so `scan`, `check`, `pin`, `setup` and the refresh worker refuse with that row's sentence and exit 1, and a hook answers `{}` and exits 0.
Doctor runs anyway, because saying so is its job., `commands.mjs` (`runDoctor`, `runSetup`), `plugins/anatomiya/commands/doctor.md`, `plugins/anatomiya/commands/setup.md`.
A command of its own rather than something a scan does on finding a dependency missing: that would make every scan an outbound call, and F5 is that it makes none.
The argv is pinned at `npm install --omit=dev --include=optional --ignore-scripts --no-audit --no-fund`, run through `execFile` with `cwd` the plugin root, a 10 minute timeout and an 8 MB output bound.
`--ignore-scripts` is the load-bearing flag: without it a dependency's install script runs arbitrary code in the plugin directory. npm that is not on PATH refuses with the one sentence that fixes it, since npm cannot install itself either, and `doctor` exits 0 whatever it found, because a non-zero exit would read as a probe that could not run.
On Windows it refuses instead of spawning: npm ships as `npm.cmd` with no `npm.exe`, a spawn resolves an extension-less name against `.com` and `.exe` only, so the attempt answers ENOENT on a machine that has npm installed, and running a batch file needs the shell F5 forbids.
The refusal hands over the same argv, after the two short-circuits, so a Windows machine with everything installed still reads `nothing to install` and a dry run still prints the line that is now the by-hand instruction.
The premise in the *Why* is wrong and was wrong when it was written: `/plugin install` does run `npm ci` in a plugin's own directory, from a lockfile beside the manifest.
This plugin had one until 0.3.0 moved it out of the repository root; B35 puts it back, and what is left here is the command for an install that did not run or did not finish `--include=optional` because oxc's native binding is an optional dependency and an npm configured with `optional=false` left it out while answering 'up to date'.
An npm exit of 0 is not the verdict: setup asks the node-hosted rows again in a fresh node (`readinessAfresh`), since a module whose evaluation threw stays failed in the process that tried it, and fails naming any row still not ok.
Where every row loads after an install, its last line is ``run `/anatomiya:scan` again in any repository you have a map in: a background refresh that stopped for what was missing may not run again until that checkout's HEAD moves``: nothing the refresh watches moves when a package arrives, so the map there is as it was (`test/cli.test.mjs`).
The typescript row is probed through `loadTypeScript`, so a copy outside major 5 is present and not ok ('the type checker needs typescript 5.x'), and setup counts a present-but-not-ok node row as needed.
