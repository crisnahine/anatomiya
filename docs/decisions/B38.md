# B38

Section: B. Engine

## Decision

`parseRuby` answers `results`, `truncated`, `version`, `error` and `missingParser`, and nothing else: no `parsed`, `crashed` or `skipped` counter and no `onFile` streaming mode

## Why

The counters had no reader: `parse.mjs` takes `results`, `truncated` and `version` and rebuilds every outcome from `classify`, which is what the facts read, so one count had two owners.
`onFile` had no production reader either, and it existed to spare memory the reduction never asked to be spared
