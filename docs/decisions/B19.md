# B19

Section: B. Engine

## Decision

A `.js`-family file oxc rejects is retried with its Flow types stripped, and the stripper is loaded the first time one is needed and never before

## Why

oxc refuses Flow by name, and react is written in it: 287 of its 2,277 files were charged as syntax the parser rejected, so every site in them counted nowhere and the areas holding them were closed as a population that moved.
Measured after: 2 rejected, both react-devtools files, and the repository goes from 65 stated claims to 78.
The stripper replaces types with whitespace rather than removing them, so the length in UTF-16 code units is unchanged and every offset and line number still lands where it does in the source.
That is the unit oxc counts offsets in and the unit a JS string is indexed by, which is what lets the same walkers and the same reported nodes stand (B5).
The byte length can move and does not need to hold: `Cafe` with an acute is five code units and six bytes, and five spaces are five of each

## Status

**done** `parse-worker.mjs` (`ensureStripper`), `langs.mjs` (`mayHoldFlow`).
Scoped to the JavaScript extensions in `EXT_BY_LANG` that are not TypeScript, derived rather than listed a second time: the retry carried its own copy of the list, so an extension added to the corpus table entered the corpus and was never retried.
Lazy because the stripper reaches `hermes-parser` and costs about 13 MB resident, which all eight workers would pay on every repository as a top-level import; a repository whose JavaScript all parses never loads it.
The trigger cannot be Flow itself, since telling a Flow file from a broken one is what the retry exists to do.
A file the stripper cannot read either, or a retry that still reports errors, stays rejected: the retry may not turn a genuine syntax error into a clean parse.
A stripper that will not import at all is swallowed rather than failing the run the way an absent `oxc-parser` does (B13), and the asymmetry is the point: with no parser nothing is read and a clean empty map is a lie, while with no stripper a Flow file stays rejected and the scan says so on its own line, which is exactly what it said before this row existed
