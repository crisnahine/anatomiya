# A10

Section: A. Delivery

## Decision

An area's `paths` matches the files its counts were taken over, and no others. Sharing a root with a deeper area means one glob per directory it holds files in, or one recursive glob and a negation per foreign subtree, whichever is shorter

## Why

Measured on a 5,495-file Rails repo: 37 of 156 areas over-reached, `app` by 2,425 files.
`app/workers/workers` states a directive at 124 of 125 and its glob delivered it to `app/workers/workers/google`, which measured the same dimension at 14 of 22 and was suppressed by the ratio gate.
The gate decides where a claim may be stated and the delivery channel walked around it

## Status

**done** `areas.mjs` (`assignGlobs`).
A directory whose own name is glob syntax, which a repository may legally have, cannot root an area and cannot be named by a cover: spelled into a pattern it stops meaning that directory, reaching the whole tree in one direction and nothing at all in the other.
Its files fold into an ancestor that can be spelled, whose recursive tail still reaches them.
Where neither exact shape can be spelled, the cover falls back to one recursive pattern from the area root, which describes more of the tree than the exact shapes do and is still bounded by the area.
A directory the encoder would rewrite is unspellable too.
The glob's directory half goes through F3, which turns a word mixing look-alike alphabets into `<path with mixed scripts, N chars>` and ends a path past 120 graphemes in `…`, so `src/раyments` and a 129-character directory each got an area file whose `paths` could never attach, while `facts.json` kept the real glob.
`spellable` now also requires `sanitisePath(dir) === dir`, so such a directory folds like glob syntax does, the encoder is unchanged, and files with no spellable ancestor below the root are reported as uncovered.
Pinned by `test/render.test.mjs`, which reads the rendered patterns back and matches them against the counted files.
Glob syntax includes `(`, `)`, `\` and `,`.
Claude Code does not match with picomatch: it splits each `paths` entry on the commas outside a brace, expands braces, then matches with gitignore rules (the `ignore` package), so `x,y/**/*.rb` read as `x` and `y/**/*.rb` and reached none of its own files.
`(` and `)` are literal to that reader, but a repository read by a picomatch-based tool would still see extglobs, so they stay unspellable.
`\` is an escape to both readers (`ignore` 7.0.5 reaches `a\b/x.rb` only through `a\\b/**/*.rb`), so it stays unspellable too.
Pinned by `test/render.test.mjs` and `test/corpus.test.mjs` through `test/paths-reader.mjs`, which reads the rendered patterns the way Claude Code 2.1.285 does: the comma split, brace expansion, a trailing `/**` stripped, then the real `ignore` package built with its defaults, a root dev dependency pinned at 7.0.5 so CI runs it.
A hand-rolled model of `ignore` agreed on every case tried and still disagreed with the package on the stripped `/**`, on case folding and on a backslash, so the tests read through the package.
That package folds case, so `src/**` reached every file in a sibling `Src/`: a directory whose name folds to the same case as a sibling holding counted files cannot root an area, and both fold into the parent, whose pattern reaches both.
A negation comes after every positive pattern, since `p/a/**` re-included a file cut out of `p/A/`, and a negation that would also cut one of the area's own files by case is dropped, so a left-out file beside or under a case twin of a counted directory stays reached.
`globsReach` folds case the same way, so `check` reads a file added in another case as delivered.
The NFC and NFD spellings of one name are not twins: the package compares code units, and the encoder already refuses the decomposed spelling.
Pinned by `test/render.test.mjs` and `test/corpus.test.mjs`; a random-tree check over 800 layouts per seed went from 611 areas reaching a file they did not count to 0.
A file added in another case after the scan is still delivered to the area whose case it does not share, until the next scan folds it, and `check` picks the owning area by exact prefix (`areaOwner`), the area at the root owning only a path that holds no slash (A108), so until then it judges that file as outside the area its `paths` reach.

`collect` lists it with the left-out source instead, and `reachable` folds case, so the area cuts it out by name like a generated file.
