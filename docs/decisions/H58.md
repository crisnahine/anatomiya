# H58

Section: H. Layout

## Decision

The reuse line (H9) is asked of every area in every language, each read by its own way of naming another file's code: a Ruby constant by Zeitwerk's file name, a Python, Java, Kotlin, PHP or Rust import by its path, a Go call by its package's directory and the file there that defines the name, and a C# type by the file named after it that declares it. A method is named only where the file reached defines it

## Why

Only JavaScript had the line before this row, so a scan of flask, gin, Slim, gson, serilog, ripgrep, ktor-samples or errbit named no helper in any area, and the agent wrote its own copy before the end-of-turn check found the one there was: 35 of 40 mastodon sessions did that in the JavaScript task, at 1.4 to 3.8 times the cost of a session without the plugin.
Where an import names no path, the name is the import: Go names a package directory and the caller writes `pkg.Func`, C# opens a namespace and names a type, Kotlin imports a package's function, and Rails autoloads a constant from the file its name spells.
Each resolver answers with one file or none, as a tail two files end in names neither (H9): a Ruby constant two autoload roots hold, a Go package two directories end in, two C# files named after one type in no namespace the caller opens.
A Python absolute import starts at a top-level package, so a module inside a package is not reached by its last name alone: flask's own `src/flask/typing.py` read as the standard library's `typing` in 8 files before this was held.
A method called on a constant or a class (`TagManager#local_url?`, `Strings.isBlank`, `Money::format`) is named only where the file reached defines it, and the constant alone where it does not: mastodon's roster led with `Account.find` and `Account.where`, which are ActiveRecord's.
An import is not the only way a file reaches another's code, so each language reads the others it writes: a Python attribute call on an imported module (`shop.money.format_price`), a class a Java or Kotlin wildcard import brings in, a Rust path written in the call (`crate::text::escape(x)`), a PHP function, which PHP loads for every file and a call names bare, a C# extension method, which a call on any value of its type reaches, and a Rails helper method, which every view, controller and helper calls with no receiver.
Where a name is common the resolver holds to what the language would let the caller see: a Go import resolves only under a module path a `go.mod` declares, so `github.com/pkg/errors` is never the repository's own `internal/errors`, and a path two `go.mod` files declare, as examples and test data reuse one, resolves nothing; a C# type or extension method only where its namespace is the caller's own, one above it, one it opens, or one a `global using` opens, so `Task.Run` from a file that opens `System.Threading.Tasks` is never `App.Models.Task`; a Python module only from a directory that is the top of the tree, a `src`, or one the importer sits under, so `import json` from `app/` is never `scripts/json.py`, and of two files a tail names, the one the import can start in; a PHP function and a Rails helper method only where one file alone defines it; and a method a file calls bare, or on a value, is the file's own where it defines one of that name, so `current_user` in a controller that defines it is never a helper's, and `this.Format()` is never an extension method's. A class a Java wildcard brings in is looked for in the file's own package first, as Java looks it up.
Measured after the change on the scans that had none: flask 4 areas with the line, gin 1, Slim 8, gson 6, serilog 12, ripgrep 4, ktor-samples 1, and mastodon's `app/lib` names `TagManager#normalize_domain` and `TagManager#local_domain?`.
The import list a JavaScript area prints (`most files here import`) is still asked only of a language with an import graph (`importGraph`)
