# H46

Section: H. Layout

## Decision

A finding capped at FIX names the cap that applied: the run's own cause (the stale reason the header prints, or no merge base), and for a dropped directive whether the area file still names its sentence without counts or says nothing of it

## Why

One fixed sentence per branch told a run with no pin that its map was stale or had no merge base, when it had neither, and told the agent the area file never stated a sentence it printed word for word under the notice (A34).
An agent relays the reason as fact, so a wrong cause points at the wrong fix.
The named/unnamed split is read by position in the notice, not by prose, because facts.json stores no claim-side sentence and the scan that wrote the file had one for every stated slot.
A deleted file owes findings too, so it is counted in the header and listed as `removed`.
The walkthrough's severity table quotes every reason word for word, with N, M, AREA and the like for what the code fills in, because a reader looks a relayed reason up there and a paraphrase is a reason nobody finds

## Status

**done** `verdict.mjs` (`severityFor` `capped`, `verdictFor` and `deliveredOr`, which withhold MUST-FIX from a path the area's globs never delivered the claim to), `check.mjs` (`droppedOf`), `render.mjs` (`droppedSlots`), `check-report.mjs` (`removed`).
`removed` holds deletions committed or only in the working tree, of any path, never a move's old path whatever its new name, never a path HEAD does not hold (added to the index, with or without `-N`, and deleted again), and never a path `changed` already counts.
`check-docs.mjs` reads each `severity`/`reason` literal in `check.mjs` and fails when its row of the table does not quote it.
It reads every reason, the one once held in a named constant included, now written where it is returned. A pattern that finds no reason at all fails the gate rather than passing every reason it never read.
