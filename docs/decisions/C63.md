# C63

Section: C. The counted-claim model

## Decision

The URL forms C59 leaves out stay unread, on measurement: React Router 7's `route()` config, TanStack's `createFileRoute`, a `path` given as an array, Ember's `this.route` map, a file router's directory names, and a link's `to` or `href` under a check-only rule

## Why

#240 asked whether reading them would let `url_segment_case` state where it cannot, measured over the 85 repositories of the three corpora with the tool's own scan (`docs/measurements/2026-10-23-unread-classes.md`).
React Router 7: 0 sites, since the 4 files importing `@react-router/dev/routes` all export `flatRoutes()`, which is file-based.
TanStack: one repository, supabase, 103 of 103 kebab-case, so no second repository and no spread; the string restates the file's own path, which the router's plugin keeps in step, so it is a file-router row under another name.
A `path` array: 2 sites in one file of mastodon, and no slot moves.
Ember's map: discourse alone passes 20 sites, kebab-case 77 of 91 (0.846); read, it opens 9 slots and states in none, and `eslint-plugin-ember`'s `route-path-style` is on in discourse's config and switched off file-wide in exactly the route maps holding the 13 snake_case and 1 camelCase exceptions, which makes it the linter's.
File routers: repository-wide the spread clears (supabase 1.000 over 59, next.js 0.909 over 22, cal.diy 0.652 over 46), but both holders are kebab-case, no area reaches 20 sites, and per area the row states in 0 areas read by listing and in 2, both supabase's, only if each directory is its own section; the counts decide it before C59's reason that the agent sees the directory.
Links: a check-only rule fires only where an area states the URL claim, and across the corpus it would have fired 0 times: a measured React front end's 43 links all agree with its stated `src/router`, supabase's 93 all agree with its two would-be TanStack claims, and mastodon, whose links mix 9 snake_case to 7 kebab-case, states no URL claim

## Status

**done** Nothing is built: `url_segment_case` reads what C59 lists and no more.
File-router file stems (Next.js `pages/`, Nuxt `pages/`, Remix and React Router `app/routes/`, flat names split on `.`) hold one side wherever they hold: next.js 529 of 544 kebab-case, supabase 106 of 107, and cal.diy 10 of 12 and mealie 6 of 6 under 20 sites; no repository holds another class, so a stem row would state a default, and `file_naming_case` already reads a stem outside a router's own syntax.
Not measured: the authors gate in the file-router per-area verdicts, so their "states" is an upper bound; and whether an agent writing into a Next.js `app/` copies the sibling directories it lists
