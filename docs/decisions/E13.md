# E13

Section: E. Baseline and drift

## Decision

One file is read once however many index entries name it

## Why

A repository committed from Linux can hold `a.ts` and `A.ts`, or one name in NFC and NFD; a filesystem that folds them checks out one file, and both names read it, so its sites counted twice and the other entry's blob never.
Measured on APFS: `src/lib 8 files` and `2 of 2 sites` over 7 files and 1 const

## Status

**done** `corpus.mjs` (`collect`, `sameFile`, `listedAs`): only a colliding fold is stat-ed, the fold `paths.mjs` `folded` spells: NFC, then lower, upper and lower case, then NFC again, which also folds the long s onto `s` and the sharp s onto `ss` as APFS does, dev+ino as BigInt since an NTFS file id passes 2^53; the spelling every directory on its path lists is kept, so a pair that differs only in a directory's case keeps the one on disk, and a byte-for-byte listing beats one equal only up to Unicode form, which is how macOS lists a decomposed name git records composed; the other is counted `unreadable`.
None of the 35 corpus repositories holds a folded collision.
Pinned by `test/corpus.test.mjs`.
The fold still only approximates a filesystem's, and a pair it misses errs toward counting twice, never toward merging two real files; the non-source roster still counts both names of a folded pair.
The same fold places a revision's blobs (`revision.mjs` `placements`), where a missed pair merged two real files: `src/s.ts` and `src/ſ.ts` were written to one file on APFS and one was parsed with the other's contents.
`listedAs` reads each directory once per `collect`, and `confine` resolves the root's realpath once per listing, never in a cache that outlives it
