# C49

Section: C. The counted-claim model

## Decision

A Ruby receiver routes HTTP through the repository's client only when the last word of its name is in the network vocabulary

## Why

The last word is what the receiver is.
Read on any word, a Redis-backed OauthClientStore.fetch across 14 files stated 'HTTP goes through the repository's own client' at 56 of 56 in a repository with no HTTP, and flagged the first Net::HTTP call.
Across the 20 corpus repositories holding Ruby the rule drops 95 of 902 conforming sites, 44 of them openproject's RequestStore, the rest hashes (request_params, client_options), caches and *ApiUser service objects.
It loses chef's api_service and api_connection (10 sites), which a head-noun rule cannot tell from a service object.
Issue #194 also asked to gate the claim on a direct HTTP call or a client-named file; that was refused, because a gem client such as Octokit::Client, in a repository making no direct call, would go quiet.
A version word is dropped before the last word is read, since `HttpClientV2` read as its `v2` dropped every site of a repository whose only wrappers were versioned, and a receiver naming a cache or a database anywhere (redis, cache, memcache, memcached, dalli, db, database, pg, postgres, postgresql, mysql, sql, sqlite, mongo, mongodb) is a store: `redis_client.get` and `db_client.execute` across 14 files each still stated the claim at 56 of 56 with no HTTP in the repository.
Version words are dropped from a file stem the same way wherever they sit, so `api_client_v2.rb` and `api_v2_client.rb` are the client and not its first violation

## Status

**done** `dimensions-ruby.mjs` (`clientReceiver`) and `dimensions-capability.mjs` (`nameWords`), pinned by `test/ruby.test.mjs`, `test/dimensions-capability.test.mjs` and `test/applicability.test.mjs`.
The store list is closed: none of its database words names a verb-called receiver in the Ruby corpus repositories, so no measured count moves; a version word (`v2`) is dropped wherever it sits but a bare number only at the end, because a leading one is a migration timestamp or a sequence: discourse's `990_settings.rb` and a backstage `20240808_settings.js` migration stay ordinary files, not the env module.
A store the list does not name (`clamav_client.execute`) still reads as the client.
Receivers ending in the vocabulary that are still not HTTP and name no store stay conforming (`pull_request.fetch`)
