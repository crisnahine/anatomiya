# F6

Section: F. Safety

## Decision

Never buffer subprocess output; `spawn` plus streamed parsing

## Why

Measured: `execFile` throws `RangeError: Invalid string length` inside Node's own exit handler, `maxBuffer` does not protect, V8 caps any string at 0x1fffffe8 bytes

## Status

**done** `git.mjs` (`gitStreamed`, `pathSet`, `nameStatusReader`), `changeset.mjs` (`changedFiles`), `ruby.mjs`.
The two callers that hand-rolled a stream, `corpus.mjs` and `authors.mjs`, share one field split; each kept its own reading of what the fields mean.
The streamed side also bounds one record, which neither hand-rolled reader did: output carrying no delimiter grew one buffer to the same string limit streaming exists to avoid.
Four reads that grow with the repository were still buffered, not one: `filesAt`'s `ls-tree -r`, `changedSinceWorktree`, `diffRange`, and the check's own `changedFiles` (`changeset.mjs`), where a branch off a distant base lists every path there is.
The `--name-status -z` grammar now has a streaming reader beside the buffered parse, both of them one reading of what a rename's three fields mean.
Which runner a function uses is pinned by `modules.test.mjs`, because both answer the same values on a repository small enough to test with
