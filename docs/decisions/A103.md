# A103

Section: A. Delivery

## Decision

Each reader gets the frontmatter it takes, over the same body, and only the patterns it matches as written: a brace set is written as one pattern per extension, and a negation or a pattern the reader would change on the way to its matcher is left out. An area file says in up to three closing lines where what its patterns match differs from the area, and those lines sit under the body and take no line from it

## Why

A Cursor area file carries `generator: anatomiya`, then `globs:` as one unquoted comma-separated line, then `alwaysApply: false`, and its overview carries `alwaysApply: true`.
A Copilot area file carries `applyTo:` as one quoted comma-separated string, and its overview `applyTo: "**"`.
An area with no pattern left has no file in that directory.
Read from the client code of Cursor 3.20.21, lifted and run: a hand-written line reader with no YAML, which cuts each line at its first colon, ends the frontmatter at any `---`, keeps an unknown key and ignores it, splits `globs` on commas outside braces, and matches with minimatch under `dot: true` from the directory that holds `.cursor/rules`, case-sensitively, with nothing put in front.
A leading `!` there is a negation joined to the other patterns by "or": `!test/**` matched all 13 sample paths outside `test/`, so one negation makes the file's patterns match almost everywhere.
Lifted from VS Code 1.140.0 and run: `applyTo` has to be one scalar, an unknown key is parsed and read by nothing, the split skips commas inside braces, a part with a leading `!` matched 0 of 9 files, a pattern that starts with neither `/` nor `**/` gets `**/` in front (`src/*.ts` matched `vendor/x/src/a.ts`), and matching ignores case.
So a negation cannot be said to either reader, and the file names the files it reaches that the area left out.
Brace sets work in both of those readers.
They are expanded all the same: Cursor's documentation shows only comma-separated patterns, GitHub's says nothing about braces, and no Copilot surface but VS Code was read.
What cannot be written for Cursor is a pattern holding `---`, a comma, a brace, a backslash (its reader turns one into a slash) or a line break, one with a space at either edge (trimmed), one that starts with a quote, `!` or `#`, and a lone `true` or `false` (read as a boolean).
For Copilot it is a comma, a brace, a double quote, a backslash or a line break.
Measured on generated files: 300 Cursor area files through Cursor's own reader gave 0 mismatches over 1,250 patterns, and 302 Copilot area files through VS Code's parser and splitter gave 0 over 1,262.
Turning a target on moves no byte under `.claude/rules`: on copies of gin, flask, vitepress, Slim, okhttp and errbit, each scanned plain and then with both targets, every file there is the same, each Cursor and Copilot overview is 42 lines beside Claude Code's 40 with the same roster and the same areas named, and no area file's body differs from Claude Code's
