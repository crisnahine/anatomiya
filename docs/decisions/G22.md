# G22

Section: G. Scope

## Decision

Most tests make their git repository through one helper, `repository(t, options)` in `test/repository.mjs`: a scratch directory under the native temp path, `git init` on `main` with signing off through `GIT_CONFIG_COUNT`, an identity in the repository, and `write`, `author`, `commit` and `read` over it

## Why

Fifteen test files spelled `git init` for themselves, and the copies drifted on the three settings `docs/releasing.md` names as having broken CI: `-b main` in fourteen, `commit.gpgsign false` in four, and a raw `tmpdir()` where the plugin resolves the native path.
The branch and signing are handed to git through `GIT_CONFIG_COUNT`, so the machine's `init.defaultBranch` and `commit.gpgsign` never reach a repository a test makes, and the identity is set in the repository so a test may change the author per commit, as the history and co-change tests do.
Fourteen files make their repository through it now; the three that build worktrees keep `test/git-worktrees.mjs`, which already shared theirs, `test/refresh.test.mjs` keeps its own, since it clones and pushes between two, and the files with a git setup of their own (`git`, `cli`, `hook-verbs`, `facts`, `slot`, `summary`, `readiness`, `write`) were left as they are.
Every migrated file passed as it was.
