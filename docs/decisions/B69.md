# B69

Section: B. Engine

## Decision

A parse child loads its own engine's row tables and the selection, and no other engine's rows. The five base oxc rows sit in `dimensions-base.mjs`, `dimensionsFor` in `walk.mjs`, and each engine body names its own list (`ROWS` in `parse-file.mjs`, `TREE_DIMENSIONS`, the prism tables in `ruby-shard.mjs`); `dimensionsFor` takes its rows from the caller

## Why

`dimensions.mjs` builds `ALL_DIMENSIONS`, so a JavaScript child importing `dimensionsFor` from it loaded every prism and tree-sitter row, walk and table it never runs, in each forked child, and a tree-sitter child the same.
The Ruby shard thread already loaded only its own (B50).
Measured over 25 fresh processes per body and build on macOS arm64 and Node 22 (`docs/measurements/2026-10-11-parse-child-rows.md`): a JavaScript child 1.923 MB to 1.420 MB of heap added at load and 31.5 ms to 25.0 ms, a tree-sitter child 1.944 MB to 1.504 MB, at a load of 21 to 25.
Maps byte-identical over 15 corpus repositories covering every language.
`rows` has no default: a default of `ALL_DIMENSIONS` would make the selection's module import every table, which is the cost being removed
