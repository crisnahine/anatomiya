# G21

Section: G. Scope

## Decision

A harness that measures this plugin can run at one commit: `frozenBuild(sha, scratch)` in `scripts/frozen-build.mjs` checks the commit out under the scratch directory with the working tree's install cloned beside it, and `runFrozen` runs that checkout's copy of the harness, binary and all, with the result files kept in the checkout the run started from; `e2e-corpus.mjs`, `ab.mjs` and `ab-scenario.mjs` take it as `--frozen <sha>`

## Why

The three harnesses ran the binary from the working tree, and the corpus run's own header admitted that a file edited mid-run put two builds in one report: two stability failures on one repository that no isolated run could reproduce, and a frozen rerun that passed all 36.
The freeze before the 2026-10-26 replication was done by hand and recorded only in prose, and `versionsAt` could say no more than "with uncommitted changes" about what ran.
A build is a `git clone --shared --no-checkout` of this repository under the scratch directory, checked out at the commit, with `node_modules` cloned from the working tree where the commit's two lockfiles are the working tree's, and installed from its own lockfile otherwise; the second case needs npm, so on Windows it is refused with the reason rather than run through a shell.
A directory already holding a build of the commit is answered as it stands, so a rerun by commit costs nothing; a build is made under a name of its own and moved into place whole, so two harnesses freezing one commit at once never read half of one.
The first cut ran the frozen binary under the working tree's harness, which read the binary's record against its own `FACTS_SCHEMA` and `MAX_LINES` and cloned this repository's own row from the working tree; the harness runs at the commit too now, so the whole run is one commit's.
