# B77

Section: B. Engine

## Decision

A child is listened to before its pipes are read, and the streamed read keeps its own clock

## Why

Measured on Node 22.22.3 in a helper with a descriptor limit of 64 and a process group of its own: with no descriptor left, `spawn` hands back a child with no pid and no `stdin`, `stdout` or `stderr`, queues `error` for the next tick and then raises `close` with the errno, -24.
`gitStreamed` read `child.stderr` first, so the promise rejected with a `TypeError` and the `error` after it had no listener, which ended the process at exit 1.
`startFor` read `child.stdout` inside the parent's handler of a thread's message, an uncaught exception that ended the scan.
`spawn`'s own `timeout` is never cleared for a child that did not start: Node attaches the listener that clears it to `exit`, and `exit` is emitted inside `spawn` before that listener is there, so with the listeners in order and the option kept the helper stayed up for the whole 120 s.
When that timer fires it calls `kill` on a child with no handle, which signals nothing.
A pipe that fails says so on the stream: with a child's stdout destroyed with an error and nobody listening, Node threw `Unhandled 'error' event` with `read EIO` and the process ended.
An option Node refuses is thrown from `spawn` itself: a NUL in the environment gave `ERR_INVALID_ARG_VALUE` before any child was there

## Status

**done** `git.mjs` (`gitStreamed`), `ruby.mjs` (`startFor`, `onThread`, `parseBatch`), `child.mjs` (`signalChild`), pinned by `test/git.test.mjs` (`a streamed read with no descriptors left for its git is rejected as a git that failed to start`, `a streamed read whose pipe fails is rejected, and the failure ends no process`, `a streamed read whose start throws is rejected as a git that failed to start`, `a streamed read that never returns is ended by its own timeout`) and `test/ruby.test.mjs` (`a child with no descriptors left to start on tells its thread, and every call the thread makes on it is safe`, `a child's pipe that fails tells its thread, and the failure ends no process`, `the files of a batch whose child had no descriptors to start on are charged, as they are for one that could not start`).
`gitStreamed` attaches the child's `error` listener before it touches a pipe and reads each pipe only where the child has one, so a child that never started rejects the read with `git <subcommand> failed: <the system's message>`.
A start that throws rejects with the same words.
Its clock is a timer of its own that sends `SIGTERM` through `signalChild` (B76), is cleared on `close` and on any failure, and is unreferenced, so a clear that is missed holds no process open.
A stdout that errors rejects the read, since half of stdout is no answer, and a stderr that errors is passed over, since stderr only words a failure.
`startFor` attaches `error` and `close` directly after the start, reads each pipe only where the child has one, and gives the thread `read()` and `input()`, both safe on a child with no pipes.
A stdout or a stderr of that child that errors is posted to the thread as the child's own error is, and the child is ended through `signalChild`; the thread fails the batch and its files are charged as crashed.
`parseBatch` reads its child's pipes with no such guard and throws without a `spawner`, so the one child it reads is the stand-in a thread makes, which always has its streams.
Every other start in the library is behind `guardedChild`, is `blobReader`'s (E17), or is the refresh worker's, started with every stdio closed (A95)
