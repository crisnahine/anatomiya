# B3

Section: B. Engine

## Decision

Guards per file: 1 MB size, 5s timeout, 1 GB RSS polled after 250ms in flight

## Why

Measured; no V8 heap flag caps it.
The size cap was 4 MB, and a 35-repository sweep found the 1 to 4 MB band holds only bundles, compiled output and perf fixtures (no hand-written source exceeds 850 KB) sitting at the timeout boundary, flipping between crashed and parsed with machine load; each flip moved the always-loaded overview (A5).
A size cap is deterministic where a wall-clock timeout is not, so the cap moved to where the source ends.
The timeout stays for the hang the cap cannot catch, and a parse it kills is retried once when the queue drains, alone: the batch it died in was competing for the machine, and a file charged as crashed moves the always-loaded overview.
The Ruby bridge owes the same retry for the same reason: its idle window and its wall clock are timers of ours, so a child either of them killed is spawned once more for the files that never answered, while a child that died by itself, an absent interpreter or a fatal from the script is charged on the first attempt and answers the same way twice

## Status

**done** `limits.mjs`, `pool.mjs` (`attempts`, `retries`: a killed parse waits until the queue is empty and no worker holds a job, then runs alone, one at a time; it had gone back on the end of the live queue and, measured under 22 busy loops on 11 cores, six near-cap files killed in one burst were retried side by side and all six charged as crashed.
A parse killed while no other parse was in flight is charged on that attempt: its retry would find the same empty pool around it, and each serial retry adds the whole timeout to the scan.
The machine's own load can still ease between attempts, and that is the loss accepted.
A one-worker pool never runs two parses at once, so it never retries: every one-file batch (a `check` that adds one JS file, or runs with no merge base; an edited file is parsed beside its base copy as a two-file batch) and every scan or check on a machine with 2 or fewer CPUs charges a timer kill on its first attempt, the same as the last parse of a larger pool that ran alone), `ruby.mjs` (`attempts`)
