# B26

Section: B. Engine

## Decision

The test runner needs a declared case somewhere in the file, not just a matching import

## Why

The label was set by an import edge alone.
Measured: cal.diy, 13 of 72 "playwright specs" are 2 config files, 9 support and page-object files importing only types or helpers, and 2 Checkly uptime monitors that import bare `playwright` and call `chromium.launch()`, `goto()` and `screenshot()`, never `test`, `describe` or `it`; storybook's 3 "cypress" files are all `cypress.config.ts` importing `defineConfig`, while its 3 real specs were labelled something else; appsmith, all 12 "playwright specs" are not tests while the 6 real ones are missed.
`TEST_CALLS` already answered "is a case declared" at the file's own top level; the gate reuses it at any depth instead, since Ember nests `test(...)` one level inside `acceptance(...)` and that still declares a case, and a real spec that imports nothing and relies on an injected `cy`, `describe` or `it` never depended on the import in the first place

## Status

**done** `facets.mjs` (`jsFacets`, `declaresTest`), pinned by `test/facets.test.mjs`.
The case is named by the identifier its callee chain starts from (`calleeRoot`), through calls, member reads and tagged templates: `test.each([...])("x", fn)` has a call for its callee, and a file of nothing but `describe.each` cases lost its vitest label read one level deep.
