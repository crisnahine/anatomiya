# A19

Section: A. Delivery

## Decision

Each command is one in-process entry that answers with a record, deciding a write and performing it are two calls, and `plugins/anatomiya/bin/anatomiya.mjs` is argv, calls, printing and exit codes

## Why

The recipes lived in the argv parser, so the only copy of what a pin does could be exercised only by spawning a process, and the wording of every printed line sat inside whichever printer emitted it.
Four readers scrape those lines, the agent through `plugins/anatomiya/commands/scan.md`, the corpus harness, the CI smoke greps and the tests, which is a contract nothing held in one place.
The write had the shape from the other end: the one caller that wanted the map without creating it derived every rendered body a second time, and a second derivation of the same thing is a drift waiting for a field to move

## Status

**done** `commands.mjs` (`runScan`, `runPin`, `runCheck`, `runDoctor`, `runSetup`), `summary.mjs` (`SUMMARY_SCHEMA`, `scanSummary`, `scanLines`, `pinSummary`, `pinLines`), `write.mjs` (`planMap`, `commitMap`, and `writeMap` composed from them), `plugins/anatomiya/bin/anatomiya.mjs`.
The summary is the facts and the lines are the words, kept apart so a caller that is not a terminal reads the same answer rather than a second derivation of it (A20).
Every refusal belongs to the half that plans: a corpus only partly read refuses to pin at all, and the escaped-directory and occupied-name refusals (F2, F17) fire on a dry run, where a plan reporting a clean write that cannot happen is the one answer worse than the failure.
A plan is committed to the root it was planned for and to no other, since the two calls can now be separated by anything.
Nor after another scan replaced the record it was planned from: `planMap` keeps the size and mtime of the `facts.json` it read, and `commitMap` refuses with `another scan wrote the map meanwhile, so nothing was written: scan again` where they moved, since a hand scan and a refresh can run at once and a stale plan left the other scan's new area file on disk, named by no record and loading for good (A104 keeps an unrecorded file); what is left is the window between that check and the renames. A refresh that loses that race records no failure: the refusal is marked `stale`, and the refresh's next pass finds the other scan's record at the same stamp.
`runPin` writes the pin before it answers, because the old order printed the sha it had pinned and then failed.
`pinTarget`, which `pin --dry-run` asks, refuses by name every shape the write cannot get past (a file at `.claude` or at the store, a directory at baseline.json, a store linked to a file), as the map's planning half already did: measured, the dry run said "would write" and the pin died on a raw `ENOTDIR`, `EEXIST` or `EISDIR`.
`planMap` refuses a directory at `facts.json` the same way, where the scan died on `EISDIR` out of the rename `blockedOnTheWay` (`rules.mjs`) also refuses a nearest existing directory this process cannot write, for the map and the pin alike, and a pin names its root as the scan does.
