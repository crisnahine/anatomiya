# H48

Section: H. Layout

## Decision

Each of the seven languages tree-sitter reads has a test name of its own, read inside its family only. A root named exactly `tests` prints as `tests/`

## Why

Go's `_test.go` and Python's `test_*.py` or `*_test.py` make a test file on the name alone; PHP's `*Test`, Java's and Kotlin's `*Test`, `*Tests` and `*IT`, and C#'s `*Tests` and `*Test` make one only under a test tree; Rust has no name, and a `.rs` file directly in a crate's `tests` directory is a test by place.
`Spec` is not a suffix.
Measured on three repositories per language.
The two names that stand alone are the ones the language's own tool collects by: `go test` builds a `_test.go` and nothing else (578 files, 567 holding a case, the other 11 helpers or empty), and pytest collects `test_*.py` (1,180 files, 1,168 holding a case).
`*_test.py` is the other half of pytest's default and none of the three writes one, so it is there on pytest's word and not on a count.
A CamelCase suffix is a word a producer wears in earnest: of 3,691 files so named, 17 sit outside every test tree and 9 of those are not tests, junit's own `RepeatedTest.java` and Laravel's `UnitTest.php` among them, which is H35's reason over again.
Inside a test tree 141 so named hold no case of their own and most are a subclass that inherits them (`ArrayCacheFunnelTest extends CacheFunnelTestCase`), so the name and the tree decide and the case is not asked for.
A test tree is the six shared names plus what the family's build uses: a Gradle source set ending in `Test` (500 files in okhttp and kotlinx.serialization sit under one) or named `testFixtures` (junit5 tracks 101 files under one in 8 modules, and none of the other five JVM repositories holds the source set), a dotted .NET project name ending in `Tests` or `Test` (all 22 test projects in the three repositories end in `Tests`, and Autofac names its two in the singular, `Autofac.Test` and `Autofac.Specification.Test`), a `Test` or `Tests` directory in PHP (316 composer files under `tests/Composer/Test`; none of the three writes `Tests`, and symfony keeps one inside each component, 2,986 `*Test.php` files under them).
H50 holds what each word credits.
`IT` wants a lower-case letter or digit before it, or `EXIT` is one.
Two files in the 21 repositories end in `Spec` and neither is a test.
No Kotest runner is read: kotlinx.serialization holds 7 files that import `io.kotlintest`, Kotest's package before its rename, and the 4 that also import `kotlin.test` print as `kotlin.test` specs while the other 3 (`RandomTests.kt` twice and `CborWriterSpecTest.kt`, two of them a `ShouldSpec`) are test files by name and tree with no runner on the tests line.
By default cargo builds every `.rs` directly in a crate's `tests` as an integration test whatever it holds, a crate being a directory with a `Cargo.toml` or a `src` in it.
A manifest can turn the default off, and no manifest is read. ripgrep declares 349 of its 365 cases with a macro of its own, `rgtest!`, 333 of them in six of the ten files directly under `tests`: read by attribute its tests line is `3 cargo test specs under crates`, and by place `15 cargo test specs`, ten under `tests` and five under two crates. tokio reads 287 for 280 and serde 23 for 19.
Given up: a crate that sets `autotests = false` is counted by the default all the same. ripgrep does, and declares one target, `tests/tests.rs`; the other nine files directly under `tests` are that target's modules, all ten count as specs, and four of the ten hold no case (the target file, `hay.rs`, `util.rs` and `macros.rs`).
And a level down the directory makes nothing a test, so serde's 118 compile-fail sources under `tests/ui` stay out and so do ripgrep's two `tests/index` files of 16 `rgtest!` cases.
None of the seven takes a JavaScript or Ruby name, the mirror or `__tests__`.
The tests line is labelled `tests`, and 7 of the 21 repositories hold a root of that name (ripgrep, django, fastapi, jellyfin, laravel, flask, Slim) where none of the 35 older ones does, so such a root prints with a slash, `- tests/: 41 .py, 9 .html and 10 other; 23 pytest specs`, and the two bullets never share a label.
Given up with the family words: a directory or project named for something that is not a test suite reads as a test tree where its name fits.
PHP models of medical tests under `src/Models/Tests`, `BloodTest.php` and four like it, read `5 test files` and not `5 .php; 0 of 5 have a namesake test`; factories under `src/Tests/Fixtures` are asked for no namesake test; and in a C# project named `Contoso.ABTest`, `LatencyTest.cs` reads as a test file and its four siblings are asked nothing, while `Contoso.Test.Utilities`, where `Test` does not end the name, is read as source
