# C26

Section: C. The counted-claim model

## Decision

The module that implements a routing claim is not one of its own sites, decided by the file's own stem: every word of it in the capability's vocabulary, where an import needs one

## Why

Something has to reach the platform.
The repository's own logger calls `console`, its own client calls `fetch` or `Net::HTTP`, its own config module reads `process.env`, and the always-loaded map read `network calls go through the repository's own client, not fetch directly ... except src/queries/request.ts`, which is the client: the map told an agent that the client breaks the client rule.
Admitted in a `blind` field and recorded nowhere.
Not a site rather than a conforming one, because the file implements the rule instead of following it and a conforming hit would also make it one of the three adopters C14 asks for.
The strict word rule is measured: it keeps all 22 Ruby clients and the one JavaScript client 301 files import, and drops the 92 files that merely mention the vocabulary; one word would have excused a real `Net::HTTP.get` in an ordinary service and exposed 20 log-named files, five of them `db/migrate` log-table migrations where `puts` is normal
