# B2

Section: B. Engine

## Decision

`oxc` runs in a pool of warm **child processes**, never in-process, never worker threads

## Why

Measured: uncatchable SIGSEGV from inside `parseSync` at nesting depth, a worker thread does not contain it, and no static pre-screen predicts it.
The pool is also *faster*: 8,463-10,563 files/sec vs 3,058
