# A118

Section: A. Delivery

## Decision

A scan's sweep of `.claude/anatomiya` removes what a killed pin, a killed create of the refresh lock or the commit lock or a killed breaker of either left there: a staged file of `baseline.json`, `refresh.lock` or `commit.lock` whose stager is not running, every lock token and token's own token of a generation its lock does not name, which is all of them where the lock is gone, a token's own token of the dead generation the lock names whose own mtime is more than 62 s from the clock, and a `refresh.lock.stale-<pid>-<16 hex>` an older build moved aside, where that process is not running. It never removes a lock token of the generation the lock names, a token's own token of the generation a live lock names, or an entry that is not a regular file

## Why

The sweep read three names, `facts.json`, `layout.json` and `refresh.json`, so the staged file of a pin or a lock create killed part way stayed in the store for good.
A breaker killed while it held a token's own token left a dead refresh lock nothing breaks (A117): on that tree `acquire` answered null 3 of 3 times and the three files stayed.
An age rule on the token's own token inside the lock would end that without a scan, and it brings back the race A117 refuses, two calls removing one old file and the second taking the first's fresh one, on a path the echo runs in parallel batches.
A scan is one process and runs far less often than a hook.
The sweep removes at the commit the names it planned earlier in the same scan, and that gap breaks nothing.
A lock token of a gone generation taken from under a breaker still running changes nothing for it: it asks the judge again, finds the lock is another generation, and leaves it.
A lock token name comes back only with the same random nonce, and while a token's own token is stuck every `acquire` answers null, so no worker removes or makes one in that gap.
The first lock token of the dead generation is kept: once the token's own token is gone, the next worker breaks it by the protocol.
Given up: after a breaker is killed holding a token's own token, the checkout's map is not refreshed until someone runs a scan there, and neither `doctor`, the summary nor the delivered map says the refresh is stuck
