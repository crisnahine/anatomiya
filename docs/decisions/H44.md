# H44

Section: H. Layout

## Decision

Every roster clause is printed over the population it counted: the helper facet as `f of j JSX files inline a helper`, sibling modules named only by stems that repeat, a namesake root with the count that sits there where half the matches named it (`4 of 63 have a namesake test, 3 under src/utils/__tests__`), and the fold line's files as `too small for a line of their own`, so "floor" in the overview means only the area floor

## Why

Each clause was right as a number and wrong as a sentence.
On the client map `src/utils` read `0 files inline a helper` over 1 JSX file while 11 of its other 74 files keep a private helper; `70 sibling modules named analyticsPath/applyProfitAndLossImport/assert` named three unique stems in code order; `4 of 63 have a namesake test under src/utils/__tests__` had 3 there; and the api map's `176 files in 29 directories under the floor` sat ten lines above `under the per-directory floor`, a different threshold, over directories that are areas.
A relative specifier ending in `/` resolves through the directory's index, the way Node and TypeScript read it, and it had resolved to nothing
