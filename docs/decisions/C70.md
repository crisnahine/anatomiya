# C70

Section: C. The counted-claim model

## Decision

`logger_over_print` asks Python, PHP, Java, C#, Rust, Kotlin and Go whether output goes through a logger: a call that writes to the console is a site that does not conform, and a level called on a receiver named for a logger, or Rust's level macros, one that does. It is a logging capability row, offered only where three files write through a logger. Go was refused on a first rule and clears the bar on the one that ships (C71)

## Why

`route_logging` and `logger_over_puts` asked the question of JavaScript and Ruby, and nothing asked it of the tree-sitter languages.
By the C51 bar every one of the six clears it, most by far: Python 0.3113 to 1.0000, PHP 0.0000 to 0.2500, Java 0.0000 to 0.9919, C# 0.0000 to 0.9979, Rust 0.0000 to 0.8229, Kotlin 0.0534 to 0.8689.
Go, by a first rule that counted `fmt.Print*`, `print` and `println`, read caddy 0.9449, gin 1.0000 and hugo 0.9409, none under 0.90.
That rule took every call into a logger package for a write; read by the one that ships, which counts a level, `Print`, `Fatal` or `Panic` and zerolog's `Msg`, Go reads caddy 0.8223, gin 1.0000 and hugo 0.8920 and clears the bar (C71).
The receiver is named for a logger (`log`, `logger`, `logging`, any case, leading underscores) rather than typed as one, since a tree holds no types: `LOG.isDebugEnabled()` asks and writes nothing, and `cache.info()` is no logger.
Two repositories here only print, composer and serde, and C14 keeps them from being asked at all.
A PHP file holding markup outside its tags is a template, whose `echo` writes the page, so its `echo` and `print` are no sites; a dump in it still is.
