# C68

Section: C. The counted-claim model

## Decision

A migration's SQL is read as PostgreSQL, MySQL and SQLite each read it, and a statement any of the three would run counts; a dollar quote or an `E''` string limits the reading to PostgreSQL

## Why

A Rails migration does not say which database it runs on, and the three it runs on read the same text differently: PostgreSQL nests block comments, quotes with `$tag$` and escapes only inside `E''`; MySQL escapes with a backslash in any quote, starts a comment with `#` and with `--` only before a space or a control character, quotes names in backticks and runs what a `/*!` comment holds; SQLite does none of that but the backticks.
The splitter C42 described read every `;` outside a single-quoted literal and a `--` or `/* */` comment as a statement's end, which is no database's rule, and each way it disagreed hid a statement or forged one.
Read one way only, each of these hid a statement a database runs: a comment `/* a /* b */ c */` before an `UPDATE`, which PostgreSQL alone ends after `c */`; `/* a /* b */` before one, which MySQL and SQLite end after `b */` and PostgreSQL never ends; `E'\''`, a quote only PostgreSQL reads as escaped; `'a\'s'`, `# it's done` and `SELECT 1--1;` before one, which MySQL alone reads as a closed string, a comment and no comment; a name in backticks holding a quote, which PostgreSQL reads as opening a string; `/*!40000 DELETE FROM t */`, which MySQL runs; and `DO $$ BEGIN UPDATE ...; END $$`, whose `UPDATE` follows `BEGIN` with no `;` between them.
The other way, the `;` inside a function body split it, so a `CREATE FUNCTION` whose dollar-quoted body held an `UPDATE` read as data work, though creating a function or a trigger changes no row; C42 had taken that as the side the row errs on.
The rules are read off each database's own documentation and lexer source (`docs/research/what-a-migration-a-route-and-a-lock-rest-on.md`): PostgreSQL's `scan.l` for the dollar tag, which cannot start with a digit and may not follow a name character, and for comment depth; MySQL 8.4's manual and `sql_lex.cc`; SQLite's `tokenize.c`. `standard_conforming_strings` is on from PostgreSQL 9.1 and cannot be turned off from 19, so a plain PostgreSQL string has no backslash escape.
Over the 85 repositories of the three corpora the map, the record and the summary a dry-run scan produces are byte-identical to 0.16.1's, so no count there moves; the Ruby tree keeps only 40 characters of a string and of each squiggly heredoc line, so most of a long migration's SQL is never read either way

## Status

**done** `dimensions-rails.mjs` (`POSTGRES`, `OTHER_DIALECTS`, `NAME_PART`, `DOLLAR_TAG`, `statements`, which reads a string under one dialect's rules; `sqlWork`, which asks all three and takes a statement any of them runs; `piecesWork`, `PLPGSQL`, the dialect under which `statements` also starts a statement at `BEGIN`, `THEN`, `ELSE` and `LOOP` in code, and `executed`), pinned by `test/dimensions-rails.test.mjs` (`SQL is read as each database a migration can run on reads it, and a statement any of them runs counts`, `a function body is code the database keeps, and a DO block's runs as the migration does`).
A function or trigger body in a dollar quote is code the database keeps, so a statement in it is none the migration runs. A `DO` block's dollar-quoted code runs, and is read as PL/pgSQL, where a statement also starts after `BEGIN`, `THEN`, `ELSE` and `LOOP` met in code, never in a string or a comment; a body the cut left open is read no further, and a statement in it this cannot read is SQL this could not read. Its `EXECUTE` runs a string as a statement: a literal is read as the statement it holds, and a string built at run time, `format(...)` or a variable, is SQL this could not read (`executed`).
A `$` inside a name opens no dollar quote, and `$1` is a parameter, not a tag.
MySQL's `/*!` is read as code whatever version number follows it, which errs toward counting a statement; its manual and its lexer disagree about a version of one to four digits.
`sql_trigger_body` stays data work: its `AS $$` is past the 40-character cut, so the dollar quote is never seen and the pieces after the cut are read as C42 reads them
