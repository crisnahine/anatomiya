# H38

Section: H. Layout

## Decision

A file the change added is asked whether it belongs where it was put, as well as whether its contents match. A test added where the source root it covers has producers and fewer than three namesake tests of its own is a FIX

## Why

Nothing is said of a test that sits in the one place its language's own tool reads it from, nor of a test for a directory the same change created and put source in.
A test is one by the two JavaScript and Ruby names or by its own language's name (H48) in Python, PHP, Go, Java, C# and Kotlin, and no Rust path is one.
Every other rule asks whether a file's contents match its directory's claims, so a file that creates its own directory is the only member of it and conforms with itself, every time.
The one case guaranteed to pass is the one where a convention was most likely broken: `spec/mailers/invoice_mailer_spec.rb` in a repository whose four mailers have no specs was examined and produced nothing.
The counts to answer it were already taken, per source root, as `companions: {with, of}`.
The directory the file is going into is asked first, and it is the nearest evidence there is: a test landing beside tests is following them, whatever a root's ratio says a level or two up.
That is the half of issue #120's own sentence this rule was missing, "a test file in a directory holding no other test file, in a repository whose sibling ratio for that kind is 0 of N", and without it a third spec joining two in one directory was told there was no precedent for it.
The caller answers it, because the two that ask differ twice over.
On what "already" means: nothing the notice can see came from the write it is about, while a check has to exclude everything the same change brought or three of four specs are excused by the first one landing.
And on where to look: the check reads what git tracks, which is the population every other reader here counts, because one ignored `scratch_spec.rb` sitting in a directory read as a test habit and took four findings to none; the notice reads the directory instead, since a `git ls-files` before every write is a subprocess before every write, so it is the quieter of the two where a stray file sits there and the check catches what it let past.
Neither may read silence as an answer: a directory that could not be listed and an index that could not be read both say there is a test rather than that there is none, since what decides whether the finding prints is a fact one of them failed to read, and a `spec/mailers` at mode 111 was reported as holding no other test with a sibling spec in it the whole time (C33).
A caller that cannot answer says nothing, which leaves the rule where it was; the degraded run with no merge base is the one such caller, and it is capped at NIT there anyway.
The finding names that directory, which issue #120 called the strongest possible signal and this did not print.
It says the directory holds no other test rather than that the change created it, which is the operative fact and is true either way; whether a directory is new is a second reading of the base that only `check` could make and the hook could not.
Four more guards keep it honest and each was written for a case that broke it.
`with` at zero means no namesake was matched, never that the directory is untested, so the repository has to be seen pairing tests with sources somewhere before this can say it does not here.
The source root needs three producers, since one or two untested files is a directory that has not spoken and reading its silence as a rule turns whichever file was written first into the convention.
The root's own test files are counted against the same three from the other side: a directory holding four hundred specs that pair with nothing has a habit.
And a tail more than one root answers to is answered by none of them where any one already pairs three namesake tests, because longest is not nearest: a repository with a specced `app/mailers` beside an engine's own untested `app/mailers` told a spec sitting with its four siblings that it had no precedent, off the longer name, which is a directory it has nothing to do with.
Where every root at a tail is untested the verdict is the same whichever it is, so the one with the most producers speaks.
A root recorded for one level is skipped outright, since its record counts nothing its children hold: react's `packages/react-reconciler/src` reads 0 of 81 with 78 tests in the `__tests__` directly beneath it, and every one of the 78 was told the directory holding it had no precedent.
A test is held to a source extension as well as to its name, because the name alone admits `Component.test.tsx.snap`, `seed.test.sql` and `tsconfig.test.json`, which were 42 of react's 461 matches.
Measured over all 35 corpus repositories, every existing test file was asked whether it had precedent where it already sits, on the reasoning that a mature repository put them where it meant to: 41,899 paths matched the name before the extension guard and 40,855 after, and the guards above took the answer from 81 findings to 2, both of them in the repository the rule was written for.
Asked again on 2026-10-11 of every tracked test of all 60 corpus repositories, 46,820 paths, the build before the family hold (H55) gave 5 findings, 1 in whitehall and 4 in a measured React front end, and the hold gave the same 5 (`docs/measurements/2026-10-11-test-by-address.md`).
What no guard reaches is knowingly accepted and named here.
The namesake match is case sensitive, so a repository whose tests live in their own tree can be fully covered and still read as zero, five Cypress specs named `thing0.cy.js` beside `Thing0.tsx` being the measured shape, and the sentence therefore states what was counted, `Nothing here was matched to a test by name`, rather than a conclusion about the directory that the count cannot carry; closing that properly means a looser companion match, which moves every count in the map and belongs to its own row.
The tail shortens from the right only, so a mirrored tree carrying an extra segment, `test/unit/app/models`, never reaches `app/models`.
Measured over the same 40,855 files: 26,004 of them, 63.7%, reach a root and are answered, and 14,765, 36.1%, reach none and are passed over in silence, which is the direction to be wrong in.
That share is not spread evenly and the aggregate hides it: a repository whose tests mirror its sources one level down is answered almost entirely, Homebrew at 100%, appsmith at 99.8%, storybook at 97.7%, rubocop at 92.5%, while one whose tests sit under a tree of their own is barely reached at all, whitehall at 0.2%, puppet at 0.7%, typeorm at 1.6%, next.js at 4.9%.
Shortening from the left as well, so that every run of segments in the tail is tried rather than every prefix, was built and measured against the same 40,855 files rather than argued about: it takes the answer from 2 findings to 214, all of them on tests that already sit where their repository put them.
So it is not done, and the half of the corpus this rule is quiet on stays quiet.
And a source directory under the layout's own floor is not in the layout at all, so the `app/mailers` of three files that prompted this is invisible in its own repository: the shape is caught, that instance is not, and the floor is a layout-wide decision rather than this rule's to move.
The covered root is found by shortening the test's tail a segment at a time, because a root is a folded directory and a test sits under whichever leaf it is about: `spec/services/order_exports` is about `app/services`, and `src/pages/Product/__tests__` is about `src/pages`, which is the directory the miss this was written for was in and which an exact tail match never reached.
The ratio alone is what got walked through, so the tests a root does hold are named in the same clause as the zero, in the words the roster already uses for them: `0 of 1003 have a namesake test` never spoke about `__tests__/helper.test.ts`, because that is not a namesake, and so forbade nothing.
A relocation counts as an arrival, since moving a test into a directory whose siblings have none is the same deviation as writing it there.
It is read off the path the base version comes from rather than off the status letter, which spells one move two ways: `R` from the diff, and `M` carrying an `orig` from a working tree where the move is staged and not yet committed, which is the state a run before the commit is asked in.
FIX and never higher, and where the siblings put their tests has more than one defensible answer.
It drops to NIT only where no comparison against a base could be made, since that is what says a file arrived; a map with no pin caps at FIX like every other rule and does not stop the diff saying `A`, and reading the two as one printed a NIT saying the run could not establish what the change added, on a run that had.
No `--created-only` flag: the finding already carries its own severity and dimension, and a sweep before handover that hides every other finding is the wrong shape for a sweep before handover.
Three narrowings, each a departure from what the issues asked and each recorded here rather than left to be discovered.
Only test files are asked: issue #120's rule says "has precedent for that kind of file" and its worked example is a test, and a rule over every kind needs a vocabulary of kinds this tool does not learn, so a first `app/policies` in a directory a change invents is silent.
The tests a root does hold are named by their runner and their tree word, `2 vitest specs under __tests__`, rather than by what they cover, which #119's `both for a utils/ helper module` would need a reader of the tests themselves.
And the whole rule turns off in a repository that pairs no namesake anywhere, so issue #119's own case, rebuilt in isolation with no other paired root, produces nothing; it fires on the repository it was found in because that one pairs elsewhere.
That is the first guard doing its job rather than a hole, and it means the rule answers about a repository's habit rather than about a directory in the abstract.
A habit is three namesake tests, the same floor a root's producers take before its silence counts: one namesake among 517 files silenced the rule for every test written anywhere under that root, while its neighbour at 0 of 1023 was answered.
Asked of the 40,701 test files today's predicate admits over the 35-repository corpus as it stands (the counts above were taken before later guards and corpus updates), the floor adds three findings, the two tests in that 517-file root and one Cucumber support file named like a test, and the same floor now holds the repository-wide guard and both of H39's conjuncts.
Where a root does hold one or two namesakes, the counts line no longer calls the tests it names none of them a namesake.
Issues #119 and #120.
In the seven languages of H48 a path is a test by `namesATest`, the rule the layout reads a file by, and its tail is read by `withoutTree`, so `bare/src/test/java/shop/bare` is about `shop/bare` and `test/Bare.Tests` about `Bare`.
Where the language's layout pairs the test's directory with a project (H50) only a root of that project answers: a PHP `tests/Bare` is about the `src/Bare` beside it and not about a `Bare` in another tree.
Where the language's own tool fixes the one place a test sits, and the test sits there, nothing is said (`sitsWhereItsToolReads` in `test-shape.mjs`).
`go test` builds a `_test.go` with the package of its directory and with no other, so a Go test is in its place wherever it is, and a `_test.go` in a new directory, or in one that holds no Go source, is silent as well (`FIXED_PLACE` answers for every Go path).
A Maven or Gradle module compiles its tests from its own `src/test` or `<set>Test` source set, and a .NET test is compiled by the test project it sits in, which are the pairings `pairedWith` reads.
"Put it where the siblings put theirs" has one answer there, the path the file already has, so the finding could only mean that the package is not to be tested.
Python and PHP keep the finding, since pytest and PHPUnit collect from wherever they are pointed and a place is a choice; so does a Java, Kotlin or C# test under a plain `tests` tree that no build pairs.
A tail shortened past a directory the change itself created answers nothing either: that directory has no habit yet, and the files of the directory above it are another directory's.
The change created a directory where the merge base lacks it and the change added a file of the root's family under it that a test could be written for (`isProducer`, H21: no test, story, declaration file, empty file or runner's own file such as `conftest.py`, and under no test tree).
`precedentFindings` hands back the directories each finding turns on (`turnsOn`), every one from the root down to the test's own, and `check.mjs` answers by the arrived paths and by `absentAt`, a `git ls-tree` of the merge base over the directories a finding turns on and the change put source under, each spelled as a literal pathspec so a top-level directory named `:top` is asked by its name, one call for each 16,000 bytes of names (`LISTING_ARG_BYTES`, half the 32,767 characters a Windows command line holds; 20,000 names of 50 bytes in one call drew `spawn E2BIG` on macOS), and no call where there is no such directory.
A base that lacks a directory lacks everything under it, so the first one it lacks that the change put source under decides: a new package `src/bare/fresh` added with its source and with its test in its own `test`, `tests`, `spec` or `e2e`, or two directories below it, draws no finding in JavaScript, TypeScript and Ruby, whose tails keep those words, as in the languages whose tails drop them.
Measured on a branch adding 1,000 packages, each `src/models/p<i>/z.js` with `src/models/p<i>/tests/z.test.js`: no finding, and 2 listings among 2,014 git processes.
A directory holding only the tests the change wrote is the one this row asks about, so each of these is a FIX: four specs in a new `spec/bare/fresh` with no `app/bare/fresh`, four tests in a new `src/bare/fresh/__tests__` with no source beside them or with a helper alone, a Python `test_m0.py` alone in a new `src/bare/fresh`, a PHP `tests/Bare/Fresh/M0Test.php` with no `src/Bare/Fresh`, a Java test in a flat `bare/test` no build pairs.
A new Ruby or JavaScript directory added with its source and its test is silent in `check`.
With no merge base no directory is known to be new and the finding stands, at the NIT that run caps it to; a listing that failed names no directory, so no finding that turns on one is stated and `check` prints one `base-unreadable` caveat with their count, a fact that could not be read deciding nothing (C33), while a finding that turns on no directory is still stated.
The notice has no base to read, so it speaks for a test written into a package the same session made a moment before, and `check` then says nothing of it.
Nine shapes of a first test, each scanned, pinned, then asked through the notice and through `check` on a branch.
Silent in both: the first `_test.go` of a Go package whose sibling package has its own; a new Go package added with its source and its test below an untested one; the same below a directory that folds a tested one; a Maven module's first `src/test/java`; a first `Bare.Tests` project; a Python package's own `tests` directory where tests live in a top-level tree; one more test in that top-level tree; a Rust crate's first `tests/first.rs`.
A FIX and a notice: a Python `src/bare/test_m0.py` beside five untested files where `src/tested` keeps its tests beside its own.
A tenth, a new Python package below `src/bare` added with its source and its test, is silent in `check` and noticed before the write.
Asked of every test file of those languages that 60 repositories hold, the 35 older ones, the 21 of H48 and four of components, as if a branch had just added each: 5,727 files in 21 repositories and no finding, 2,714 of them sitting in a fixed place and asked nothing more (all of appsmith's, commons-lang's, caddy's, gin's, hugo's, gson's, jellyfin's, serilog's, okhttp's and Newtonsoft.Json's, the 2 each of fastlane and supabase, 271 of kotlinx.serialization's 278, 472 of junit5's 473, 2 of ktor's 609, whose modules keep a flat `test` that pairs with nothing) and 3,013 asked.
The rule fires on a fixture for Python and for PHP, a tested directory beside a bare one, and is silent on that fixture for Go, Java, Kotlin and C#.
Rust has no name to read: cargo collects by place, a crate is known by the files around it, and the notice sees one path, so no `.rs` file is asked
