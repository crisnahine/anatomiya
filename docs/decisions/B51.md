# B51

Section: B. Engine

## Decision

The checker's compiler host answers `fileExists`, `directoryExists`, `realpath` and `getDirectories` once per path for one build, and its containment walk resolves each directory off its parent's answer, with one lstat, unless the directory is itself a link

## Why

Measured on a React front end, counted in the checker's process: on 0.13.3 module resolution asked 107,928 stats of 24,737 paths, and the walk's 20,816 `realpathSync` calls each lstatted every directory above their path again.
This build asks 24,781 stats and 367 `realpathSync` calls, with every link still resolved in full.
It makes more `lstatSync` calls of its own, 34,878 on 20,986 paths against 13,892 on 13,710, which is the walk resolving each directory off its parent's answer in place of `realpathSync`'s own lstats.
Three alternating runs under the bench lock at load 5.6 to 6.4: the checker's median wall went from 12,190ms to 11,828ms, 3.0% less and under the 5% the design asked of it, and the whole scan from 12.6s to 12.2s.
It ships anyway: the host's own work fell from 107,928 stats to 24,781 and from 20,816 `realpathSync` calls to 367, and the containment fix below is built on the same walk.
The plan hash matched 0.13.3 on all 35 corpus repositories and this one, and the checker ran on 8 of them.
The answers live in the host, never the module, so a second scan in one process sees the tree as it is then.
The rest of the checker's time is TypeScript typing the corpus for the first time: `measureResolution` asks each receiver once, and the ones it shares with the semantic rows are the receiver cache 0.13.2 measured as noise.
The host also decides containment on the path the OS will open, so a `..` after a link (`src/up/../x` with `up -> ..`) is taken from where the link leads, and a path that steps out of the root that way is refused; 0.13.3 read it.
Windows collapses `..` as text before it opens a path, so there the text is what is checked, and off Windows a backslash is a filename character rather than a separator, so a link named `x\..\y` is checked as itself.
`directoryExists` and `realpath` stay ungated, as on 0.13.3: they answer existence and a resolved path, never content, and gating them can change how TypeScript resolves a linked package, which would change the map
