# F24

Section: F. Safety

## Decision

A site's identity reads every function and class body inside its node as `{}`, and `absorb` matches alike copies by their own text, then the lines around them, then the enclosing name, then count

## Why

Three rows report a whole declaration, so a line added inside a body gave the untouched declaration a new identity and the check reported it as introduced: 2 FIX and 2 NIT on one Empire Flippers client edit, and up to 79 NITs over 70 replayed PRs.
Fixed in the identity, not by moving each row's node to its id, so the snippet, the line and the scan are untouched and every row holding a body (`test_call_style`, `iterate_with_for_of`, `async_error_handling`) is covered at once.
A signature edit is still a new site.
Sharing an identity across alike copies would let walk order pair a new copy with an old one, so the first pass keeps what the old identity matched

## Status

**done** `introduced.mjs` (`siteIdentity`, `withoutBodies`, `absorb`), pinned by `test/introduced.test.mjs`.
A catch clause's body is not elided, since that body is what `swallowed_error` judges.
Nor is a body that starts where the site starts and reaches its end, since it is the site or holds it: an arrow's expression body can be the reported node itself (oxc wraps `console.warn?.(e)` in a chain expression with the call's own span, and that chain is the arrow's body), and eliding it read every such site as `{}`, so an edit inside `() => props.a`, or from `console.log?.(e)` to `console.warn?.(e)`, that 0.14.0 reported went unseen.
The two rows that judge a body (`judgesBody`: `async_error_handling`, and `swallowed_error` through a closure inside the catch) leave out what they judge, so two anonymous copies share an identity whatever their conformance, and they are not matched by name or count.
Their copies, conforming or not, that open on the same line text in the same declaration are aligned as a line diff aligns lines: a copy whose whole text is unchanged anchors, and between two anchors a run holding as many copies on each side was edited in place, so a head copy there is new only where its partner conformed.
A run where the branch added or removed a copy has no partner to read, and its sites are matched as any other, with the whole text as the identity.
Four rounds of tie-breaks (place from the top, then from the bottom, then count where the copies changed in number) each hid a copy that newly broke or reported one that did not; count hid a handler that lost its catch whenever a conforming copy was added or removed beside it.
The line text alone did not tell copies apart: formatted over lines, every catch opens on `} catch (err) {`.
What is left open is what only the names inside the bodies could say: an edited breaking copy next to an added or removed alike copy, with no unchanged copy between them, is reported, and one copy removed above an edited one with another added below reads as the catch moving between them, each what the full-text identity reported before the body left it.
The other way round, a bare copy deleted above one that lost its catch, with a conforming one added below, reads as two edits in place, so the copy that lost its catch is not reported where the full-text identity reported it.
Past 2^22 cells (about 2,000 copies a side) the alignment's table is skipped and the group is matched by whole text: 30,000 alike catches edited at both ends took 10 seconds and 1.2 GB.

A JavaScript row names a site by the class or the binding around its function (F28), so a method added in one class with the name and the text of an old violating method in another class of the same file is reported on its own line when it is written above it: two classes each with a `run` holding `catch (error) {}`, and the new `catch` on line 5 is reported on line 5 as `B.run`.
The Ruby rows name the class (`A#run`) and the tree rows do too (`A.run`).
What a tree row's site is written in is the nearest class around it that has a name, the type a Rust `impl` is for, a Go method's receiver type, and for a Kotlin extension function that class followed by the receiver as written (`ownerOf` and `extendedType` in `dimensions-tree.mjs`; the node names in `tree-shapes.mjs`, held to the grammar by `test/tree-shapes.test.mjs`): `fun Invoice.toDto()` written above an undocumented `fun User.toDto()` is `Invoice.toDto` and is reported on its own line; read by the class around it both are `toDto`, and the finding names the older one's line.
