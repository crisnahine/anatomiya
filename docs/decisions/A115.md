# A115

Section: A. Delivery

## Decision

How a file this tool writes reaches the disk is one module, `store.mjs`, which imports only the path encoder: the name a file is staged under and the reading of that name, the whole-file write, the 64 MiB bound on a read, the put-back of one file, and the replace of a set of files that puts every one back when one fails. The record's own put-back stays in `facts.mjs` and is handed to the replace as `pair.restore`

## Why

These rules sat in three modules: the write, the bound and the put-back in `facts.mjs`, the staged name in `rules.mjs`, the replace of a set in `write.mjs`.
So `baseline.mjs` and `refresh-run.mjs` imported the record's owner to replace one file, and `facts.mjs` took the staged name from `rules.mjs` to spell it while `rules.mjs` read it back.
The one put-back took a third argument, the layout file that answered for the record, and only the record's path ever filled it.
A module that imports nothing of the record cannot write the record's pair again, so that half is passed in: `putBackRecord` in `facts.mjs` writes the pair where a layout file answered for the record (A101), and `replaceAll` calls it for the record's path and `putBack` for every other.
A scan's plan and result hash the same as 0.15.1's on errbit, discourse, eslint, rails-api and django, measured on the build that finished the move.
The cost is one more module on every hook's load path: `store.mjs` is on the echo arm's list in `test/modules.test.mjs`, and the notice, the reuse check and the refresh load it too

`putBack` leaves a file whose bytes could not be read, removes one where nothing was, and replaces any other whole.

`test/modules.test.mjs` refuses an import cycle and an export nothing reads, so the module stays a leaf while every writer imports it
