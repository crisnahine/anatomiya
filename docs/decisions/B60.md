# B60

Section: B. Engine

## Decision

One engine, `tree-sitter`, on the `web-tree-sitter` runtime, reads Python, PHP, Go, Java, C#, Rust and Kotlin, each through one grammar file named after its id. No language gets a host of its own

## Why

A host per language is that language's toolchain on the user's machine and one remedy each, as Ruby already is for prism.
Of the seven reference toolchains, the measuring machine held three (`python3`, `php`, `go`) and lacked four (a Java runtime, `dotnet`, `rustc`, `kotlinc`): `/usr/bin/java` and `/usr/bin/javac` are stubs that find no runtime.
So four of the seven languages would have gone unread there.
The unread files of those four were classed by each language's own parser run in a container, which accepts all 103 (B59, B63).
The runtime is one package with no dependency and no install script, 4.6 MB installed at 0.27.0, and it loads all seven grammars in one process.
A language on this engine adds no row to `ADAPTERS` or `WALKS`.
Given up: a grammar is not its language's own parser, so it reads less than the compiler does (B63), and none of the seven has types or an import graph: `capabilities` is `{ semantic: false, importGraph: false }` for each
