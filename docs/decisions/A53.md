# A53

Section: A. Delivery

## Decision

The docs gate is a function, `checkDocs`, that answers its problems, what is owed and the summary line; the module runs it only when it is the entry point

## Why

Importing the module ran the whole gate: the two tests that reach a reader (`readIntake`, `readGlossary`) spawned the binary for `--help`, ran `git ls-files` and read every document before their first assertion.
`problems` and `claim` live inside the function so a second call answers for itself, and the summary is built only where nothing failed, since it reads a manifest's version the gate may just have refused

## Status

**done** `scripts/check-docs.mjs`, with `UNRELEASED` left at module level for the helper that reads it; `test/check-docs.test.mjs` calls the gate once on the checkout the suite is in.
The function takes the tree's root and runs the rule table over one reading of it (G20).
