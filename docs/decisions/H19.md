# H19

Section: H. Layout

## Decision

An area's `kinds:` line prints its own leftover past the two named extensions, the same `and N other` clause a root line prints

## Why

The omission read as a guard against comparing an area's leftover to a root line's, which is a real risk when the two sit near each other describing the same directory from two different populations.
It is not the risk inside one area's own file: `rootFacts` is handed the area's own files, so the heading's count and this line's `other` are the same population counted twice, and hiding the leftover did not avoid a comparison, it broke the arithmetic the heading and the line owe each other. eslint's `packages/eslint-config-eslint` printed `5 .js, 4 .ts` under a heading of 10 files; canvas-lms confirmed it at scale, 107 of 497 areas hiding a nonzero leftover; storybook's worst case is an 8-file area, one file per extension by design, printing `1 .cjs, 1 .cts` and hiding 75% of itself; supabase's worst erases a whole file type, saying `8 .js, 7 .ts` while the 9 hidden files are every `.jsx` and `.tsx` in the area
