# H28

Section: H. Layout

## Decision

A test directory's own second spelling for the name it covers is learned, on the same bar C22 sets

## Why

The roster half of the same defect: `namesakeStem` strips the suffix that says a file is a test and nothing else, so `address_model_spec.rb` answers `address_model` and never `address`, and the overview read `46 of 166 have a namesake test` for a repository that specs 95 of them.
Learned per test directory, because that is the population the share is a share of and it is where a spelling is actually held to; the corpus as a whole is not a place anybody names a file in.
Held to the same language as the file it would answer, or `index.js` is credited with `index_spec.rb`.
It reaches further than the row that prompted it and the corpus says the reach is right: webpack's `lib/util` read 0 of 75 and reads 48 of 75 now, its files answered by `<name>.unittest.js`, and `lib/dependencies` and `lib` at this level move the same way.
It also answers, from evidence rather than by listing, the question `NAMESAKE_SUFFIXES` left open about the hyphen form: a directory writing `member-test.js` teaches `-test` where enough of its files agree, which is what puts Ember's suites back on the line.
A spelling begins at a separator and is applied only to a candidate of the language it was learned in, and a candidate reached under two names gets a record per name rather than one shared object, or whichever name was settled last overwrote the other's owner and the file whose own name the spec spells read untested
