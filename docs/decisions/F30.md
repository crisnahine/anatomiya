# F30

Section: F. Safety

## Decision

How a path is held inside the repository and how a file is read bounded are one module, `contained.mjs`: `resolveInside`, `outsideClaude`, `blockedOnTheWay`, `leafReplaceable`, `isLink`, `realpathOrNull`, `realpathOf`, `nativeUpTo`, `contains`, `namesIn`, `readHead`, `readTail`, `readTailOf` and `HEAD_BYTES`, which know nothing of the map; `rules.mjs` keeps what the map is called, who owns a file in it and the state of each target, and reads `contained.mjs` for the rest

## Why

`rules.mjs` was 816 lines and two modules: the ownership and target rules the writer and the check share, and the containment and bounded reads every reader of a repository-controlled path shares. Twenty-four of its importers read only the second half, the lock module, the transcript reader, the corpus walk and the worktree guard among them, and each paid for the targets table and the store to get a bounded read.
Every importer was rewired by name, and every test file that imports either module passed unchanged, `test/modules.test.mjs` aside, whose three pins now name the new module.
