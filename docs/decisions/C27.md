# C27

Section: C. The counted-claim model

## Decision

An abstract base is not a companion producer, and a pairing row may not declare a counter-claim at all

## Why

`controller_spec` counts 62 of 65 at `app/controllers/api/v1`, bound 0.8729, and the three non-conforming files are base controllers that are never routed to and can never have a spec.
Exclude them and it is 62 of 62, bound 0.942, and the claim states; a reviewer left "No spec for this controller.
All 56 siblings have one" on a live pull request and the map had the data and could not say it.
The rule lives in `companionOf`, the one function both the scan and the check go through, because a scan-only exclusion makes the one commit in 483 that edits a base controller a finding against a file the map never counted.
The name rather than an inheritance graph, because `check` reports on files the branch created and no graph built at scan time holds a file that does not exist yet; the noun comes off the row's own producer root, so `base_price_controller.rb` stays a site.
The counter half is the other end of the same asymmetry: `pairingViolations` computes one direction, so a pairing row with a counter would print a sentence in the map and enforce nothing.
`worker_spec` is the case that raised it, 0 of 125 and 0 in all 22 worker areas, a convention the repository holds at 100% that the map cannot state; re-weighed rather than re-opened, because "a worker ships without a spec" as a directive tells an agent to write one test fewer, and each area already carries the fact twice, on the kinds line and on the suppressed count line, the first of which the line budget drops last
