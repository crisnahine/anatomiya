# C32

Section: C. The counted-claim model

## Decision

A foreign key the same migration declares apart from the column, as a statement or on the table block, is that reference's foreign key

## Why

The row read the inline option alone, so a reference the migration does constrain read as a violation: 43 of 76 where 72 of 76 is the count.
Two forms were missing and the larger one is the one nobody had looked for: empire-flippers/api writes 102 `t.foreign_key` calls inside the `create_table` block that declares the column, `t.references :shopify_account` answered by `t.foreign_key :shopify_accounts` a dozen lines below it, against 12 inline options and 167 standalone `add_foreign_key` statements.
Matched on the table the key is added to and on the column it covers, which is `column:` where the migration names one and the plural of the reference otherwise, because matching on the table alone would credit every reference in a migration that constrains one of them.
Three pluralisation rules rather than an inflector: an irregular or uncountable table is caught by the equality beside them, and anything neither reaches reads as declaring no key, which under-counts conformance and so suppresses a claim rather than stating one nobody holds.
Measured before it was built: only 8 of the repository's migrations hold both a reference and an `add_foreign_key`, so those 167 are overwhelmingly retrofits onto columns earlier migrations added, and reading them as the repository's idiom for reference columns does not survive the count.
The idiom is the block form, which no grep in the report reached.
A key declared only on the way down is not one: `def down`, and the `dir.down` half of a `reversible` block, add nothing going forward, and the receiver has to be the parameter `reversible` yields or an unrelated `Rollout.down` block would suppress a real key.
The denominator needed no reconciling either: the repository writes 58 `t.references` and 22 `add_reference`, and 4 of the 80 are polymorphic, which is the exclusion the predicate already states, leaving exactly the 76 the line prints
