# C50

Section: C. The counted-claim model

## Decision

`public_doc_comment` asks whether a public function or method carries a doc comment in Python, PHP, Go, Java, C#, Rust and Kotlin, public and documented by each language's own rule, and it may state either side. A file the layout counts as a test file holds no site, nor does a constructor, an entry point, or a Go method golint asks no comment of

## Why

Three repositories per language, conforming over candidates summed over areas.
Python 0.3637, 0.7129, 0.0896 (django, flask, fastapi); PHP 0.9764, 0.7261, 0.6976 (laravel, composer, Slim); Go 0.9296, 0.9787, 0.6375 (caddy, gin, hugo); Java 0.9698, 0.7795, 0.8234 (commons-lang, junit5, gson); C# 0.7928, 0.4986, 0.4983 (jellyfin, serilog, Newtonsoft.Json); Rust 0.9576, 0.9859, 0.2481 (ripgrep, tokio, serde); Kotlin 0.3916, 0.6313, 0.3928 (okhttp, ktor, kotlinx.serialization).
Each ratio is over the sites of the one language named, so it is not what a scan's slots for the row sum to in a repository that holds two of the seven: okhttp's 0.3916 is its Kotlin alone, 553 of 1,412, and with the sites of its 71 `.java` files its areas sum to 561 of 1,461, 0.3840.
Every language has a repository under 0.90, and the spreads are 0.6233, 0.2788, 0.3412, 0.1902, 0.2945, 0.7379 and 0.2397 against a bar of 0.15.
With files a tool wrote left out three ratios move: kotlinx.serialization to 0.4221 (48 of its 690 sites sit in generated guide examples), laravel from 9,455 of 9,684 to 9,448 of 9,677 (0.9763), and Newtonsoft.Json from 587 of 1,178 to 583 of 1,166 (0.5000), with PHP's spread at 0.2787, C#'s at 0.2942 and Kotlin's unmoved.
A site sits in 0.24 to 0.82 of the files read outside tests; the low end is Newtonsoft.Json, where 321 of the 346 files in one directory hold no public method.
The counter-claim spreads as the claim does: five of the 21 repositories sit under 0.40 and six over 0.90.
The row asks the layout's own question about a test file, so a `.rs` file cargo builds from a crate's `tests` (H48) and a `conftest.py` (H49) hold no site: read as source, serde's `test_suite/tests` printed `22 cargo test specs` above 12 of 12 undocumented sites, 11 of them in a file that line counts as a spec, and flask's `tests` area took all 10 of its sites from `conftest.py`.
That is 11 sites in serde, 34 in ripgrep, 18 in flask and 12 in fastapi.
A Go method named `Error`, `Read`, `ServeHTTP`, `String`, `Write` or `Unwrap` is no site, nor is `Len`, `Less` or `Swap` on a type the file gives all three: the names golint's `lintFuncDoc` passes over, `commonMethods` in `lint.go` of golang/lint and the types its `scanSortable` finds. golint passes a method by its name alone, whatever its signature, and so does this row: of the 29 methods named `ServeHTTP` in caddy's 224 Go files outside tests, 24 are `ServeHTTP(w, r, next caddyhttp.Handler) error`, the method of caddy's own handler interface and not of `http.Handler`, and one `String` there is `func (f Flags) String(name string) string`, a getter.
That is 48 sites in caddy, 17 of them documented, 1 in gin and 71 in hugo, 4 documented; counted as sites the three read 0.8989, 0.9792 and 0.6192, and caddy states the claim in 1 area of 28 where it states it in 5 without them.
PHP's `public`, `private` and `protected` are read in any letter case, as the language reads them.
A C# doc comment above a `#if` that opens on the method documents the method.
A Python docstring may sit in parentheses, since CPython takes `("Runs.")` as one, and a tuple or an f-string there is none.
A PHP `__construct` or `__destruct` is no site, as a Java, C# or Kotlin constructor is none to its grammar, and neither is an entry point: a static `main` in Java, a static `Main` in C#, a `main` at the top of a Kotlin or Rust file.
Go's `main` and `init` are not exported.
That is 686 sites in laravel, 160 in composer, 28 in Slim, 2 in commons-lang, 1 in junit5, 4 in gson, 1 in jellyfin, 1 in tokio, 30 in okhttp, 2 in ktor and 130 in kotlinx.serialization, whose guide examples each hold a `main`.
Rust's three were read with their lints: tokio, tokio-util and tokio-stream warn on `missing_docs` and eight ripgrep crates deny it, and all 17 Rust areas that state the claim sit in those crates (14 in tokio's three, and ripgrep's `crates/cli/src`, `crates/ignore/src` and `crates/printer/src`). ripgrep's 8 areas under the lint read 406 of 406 and `crates/index/src`, with no lint, reads 0 of 18.
`missing_docs` is allowed by default in rustc, so a build fails on it only where a crate asks, and the fifth test of the bar in CONTRIBUTING.md does not refuse the row. serde's 0.2481 is 85 sites in `serde_derive` (14 documented), 7 in `test_suite` (none) and 37 in `serde` and `serde_core`, which deny the lint (18 documented): the row reads a bare `pub` as public whatever module it sits in, its stated blind spot.
Without serde Rust reads 0.9576 and 0.9859

## Status

**done** `dimensions-tree.mjs` (`public_doc_comment`, `PUBLIC`, `DOC`, `NO_SITE`, `GO_COMMON_METHODS`, `goNamedByInterface`, `documentedAbove`, `hasDocstring`, `standsAlone`), `test/dimensions-tree.test.mjs`, `test/applicability.test.mjs`, the scan and the check of a test file in `test/scan.test.mjs` and `test/check.test.mjs`.
The method names of a Go type are read once for each file, and a function's place among its siblings from a table built once for each parent (`placeAmong`): a 680 kB Go file of 20,000 methods named `Len` on one type is read in a scan of 0.6 s, where searching the type's methods again for every method ran past the 5 seconds a file is stopped at and the file was counted as crashed.
What this gives up: whether the class or module around a function is public is not read, so a public method of an internal class counts; a helper in a test tree that holds no case, and that no tool collects by its name or its place, is not a test file and its functions count; golint finds a sortable type over a package and this row over one file, so the three methods of a type split across two files stay sites; a static method named `main` in Java or `Main` in C#, and any function named `main` at the top of a Kotlin or Rust file, is passed over whether or not a runtime starts there; Rust code inside a macro call is not in the tree; in a Rust crate that sets `missing_docs` the stated line restates the crate's own lint
