# C53

Section: C. The counted-claim model

## Decision

`declared_return_type` asks Python and PHP whether a named function declares what it returns, and it may state either side: `functions declare what they return` or `functions declare no return type`

## Why

Python 0.0000, 0.9307, 0.4744 (django 0 of 8,744, flask 376 of 404, fastapi 546 of 1,151), spread 0.9307.
PHP 0.1028, 0.8273, 0.9483 (laravel 1,409 of 13,711, composer 2,218 of 2,681, Slim 312 of 329), spread 0.8456.
The counter-claim is the same spread read from the other side and clears the same bar: Python 1.0000, 0.0693, 0.5256 and PHP 0.8972, 0.1727, 0.0517.
A scan of the six states the claim in 12 areas (flask 1, fastapi 1, composer 4, Slim 6) and the counter-claim in 68 (django 40 of 92 slots, laravel 28 of 104), and no repository states both.
Leaving the annotation off is a rule where it is one: django types none of 8,744 functions, and with no counter-claim to state a new function written that way is a NIT under a claim the project never made.
A site sits in 0.46 to 0.93 of the files read outside tests, and no ratio moves by more than 0.0001 when generated files are left out.
The annotation is optional in both languages and neither marks an export, so every named function outside the tests is a site.
A file the layout counts as a test file holds none, a `conftest.py` among them (H49): 20 sites in flask and 12 in fastapi

What this gives up: a repository adding annotations to code that had none gets a finding on each typed function it adds where an area states the counter-claim, until a scan counts enough of them that the area states nothing; a return type written in a docblock or a stub file is not read; and the counter-claim is a count on the area line and reads as an instruction on a finding: in a directory at 40 of 40 untyped, a branch that adds `def new_view(request) -> int` gets `FIX functions declare no return type`
