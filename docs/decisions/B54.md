# B54

Section: B. Engine

## Decision

A JavaScript row is asked of a component's script only where the row lists `vue` or `svelte` itself. Nothing maps the two ids onto `js`. 29 rows list JavaScript; 24 of them list Vue and 24 list Svelte, and the type-checked row is asked of neither (B52)

## Why

A component's script differs from a module in three ways: its top level runs once per instance, its props arrive from a macro or a rune, and its template uses names the script never shows being used.
So each of the 28 rows a JavaScript file is asked without the type checker was run on twelve hand-written components, six per framework (script setup, the Options API, a class component, two blocks, runes, Svelte 4 with `export let` and stores), against the sites a person reading the component would give, and a row is listed where every cell agrees.
On real code, the rows listed for Vue and Svelte collect 4,918 sites in the 3,994 components of vitepress, element-plus, kit and shadcn-svelte that parse: 3,643 in Vue files and 1,275 in Svelte files, 253 of those from the four rows the prop skip below admits (`function_style`, `explicit_return_type`, `doc_comment_style` and `exported_symbol_case`).
Up to 25 per row and framework were read at their file and line, and none was wrong.
A pass aimed at `function_naming_case`, with storybook and supabase added for their Svelte 4 and Options API files (4,387 component files in all, 1,255 Vue and 3,132 Svelte), found 7 misreads, which the two skips below leave out.
Excluded for both, each because the answer is in the template: `module_state_const`, since a top-level `let` in a component is state the template writes (1,252 of 2,568 Svelte sites are such a `let`); `optional_chaining`, since `props` is never absent and 1,424 of 1,425 Vue sites are a read with no `?.`, nearly all of them off `props`; and `type_only_import`, since a component the template renders is a value there (of 401 unmarked Svelte imports, 251 name something the markup also uses, and all 5 unmarked Vue ones are used as a tag).
Vue alone: `error_shape`, because `setup()` and `data()` return the bindings the template reads and `return { data, error }` there reads as a returned result; its 37 real sites are all throws, so listing it buys no claim and risks a false one.
Svelte alone: `hook_per_module`, because a prop named `useCache` reads as an exported hook; it has no site in 3,132 files.
One skip does the rest for Svelte: `export let` or `export var` at the top of a `.svelte` file declares a prop, and six rows leave its declarator out (`function_style`, `explicit_return_type`, `doc_comment_style`, `exported_symbol_case`, `exported_class_case`, `function_naming_case`).
Excluding those rows whole was measured: `function_style` alone left 221 real sites unasked, 212 of them `function` declarations, to avoid 2 misreads in 245.
In a `.vue` file a PascalCase function is no `function_naming_case` site: all 6 PascalCase sites of 893 in two Vue repositories were components the template renders.
`file_naming_case` counts components as a population of their own, so `UserCard.vue` does not vote with the modules beside it, and a component with no script still votes with its name: vitepress states it at 64 of 64 in one area, shadcn-svelte in 60 areas at 1,651 of 1,651, and a router's own names (`+page.svelte`, `[id].vue`) stay no site, which is 965 of kit's 1,016 `.svelte` files
