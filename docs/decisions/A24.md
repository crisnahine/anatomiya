# A24

Section: A. Delivery

## Decision

The plugin declares a hook that re-delivers the map after a turn or a tool call, once per 192 KiB of what the model reads since A92, stamped with the moment it was read, in its own `hooks/hooks.json`; a scan takes out the one an older version wrote into `.claude/settings.local.json`

## Why

The always-loaded channel puts the overview in the system prompt once per turn and that is where H1 leaves it.
What it does not carry is recency: a run three hundred tool calls deep was handed the map at the start and nothing since has said it again, and nothing anywhere says when it was read, so a map that has gone stale against the code reads exactly like one that has not.
The hook says both.
"What is deliberately not built" refuses a hook as the delivery channel and the 10-to-40% adherence it cites was measured on a hook *instead of* the always-loaded file; this is a hook *on top of* it, so the channel that scored 100% is unchanged and nothing depends on the weaker one

## Status

**done** `hooks/hooks.json` (the declaration itself), `hook.mjs` (`echoContext`, `ownMap`, `readOwned`, `planRemoval`, `commitRemoval`, `removeStaleHook`, `HOOK_COMMAND`), `validate.mjs` (which refuses a declaration the loader would silently ignore), `commands.mjs` (`runScan`), `hook-verbs.mjs` (`runEcho`), `plugins/anatomiya/bin/anatomiya.mjs` (`echo`), pinned by `test/hook.test.mjs`.
The echo keeps one thing on disk outside every repository, the batch claim and its lock under `${CLAUDE_PLUGIN_DATA}/echo/` (A92).
That variable is Claude Code's, set for a plugin's hooks, and no option of this tool: where it is unset, relative or cannot be written, the echo answers each call from the transcript alone and writes nothing.
Three events, not two: `PostToolUse` fires only when a call succeeds, so `PostToolUseFailure` sits beside it, or a run of denied edits is the run that hears the map least.
The map is found by walking up from wherever the hook fired rather than joining onto the directory it was handed, since a hook carries the session's own cwd and the map is written once at the root; walked rather than asked of `git rev-parse` because this runs on every tool call and a subprocess per call to learn a path already on disk is a subprocess per call.
The stdin read releases the handle rather than only resolving its promise: an open pipe is a live handle, and a harness that opens one and writes nothing held the process for as long as it held the pipe, measured at 8 seconds against the 2 the bound claimed.
The cost was real and chosen: roughly 500 tokens per turn and per tool call, so a 300-call session spent about 150,000 on it.
A92 keeps the recency and drops the repeats.
That figure was counted on a 2,468-file repository and carried forward by arithmetic when the head grew, not counted a second time.
No knob: no option a scan takes changes what is counted or what a hook says or how often, and no option's value is kept in a file (A102); the number is here so it is a decision rather than a surprise.
The text it echoes is descriptive and says the code outranks it: a hook that injected directives is the shape that gets flagged as prompt injection, and this one hands back counts and a sentence telling the reader to run `/anatomiya:scan` rather than believe a stale copy.
Installed after the map is written and never on a dry run or a blind run, because a hook pointed at a map that was never written echoes nothing on every tool call for the life of the session.
`${CLAUDE_PLUGIN_ROOT}` names the command, the way `commands/*.md` already reach this CLI, so a plugin that moves does not leave a broken hook behind, and where that variable is substituted is the whole of this row's correction.
It is substituted only for a hook a plugin declares in `hooks/hooks.json`.
Written into a repository's own `settings.local.json`, which is what 0.2.4 through 0.2.6 did, it is not substituted at all: Claude Code refuses the hook by name on every prompt and every tool call for the life of that session, which is worse than no hook, and no test could have caught it because every test in this repository runs the command directly rather than through the loader.
Reported from the field on 2.1.238 and reproduced from the settings file a scan had written.
The declaration moved into the plugin, where the loader substitutes it, and what the scan does to a repository is now subtraction only: it takes out any entry running this tool's `echo` through `${CLAUDE_PLUGIN_ROOT}`, quoted or not, which is every spelling that shipped, and leaves a command naming the binary by a path of its own, which is a hook somebody wired and which runs, and leaves the permission lists, other people's hooks and any event that still holds one exactly as they were, removing the file only when it holds nothing else.
That restores A1, since `.claude/rules/` is again the only directory of rules this writes to unless a scan is asked for another (A102).
The cost of the move is that a plugin hook cannot be scoped to a repository and runs in every session the plugin is installed for, so the scoping is the hook's own: it walks up for a map and answers `{}` where there is none, writing nothing and creating nothing.
The cost of that answer is one node process per turn and per tool call in every session the plugin is installed for, and it is almost entirely node's own start: three independent runs on one laptop put the median at 104ms, 73ms and 237ms, and swapping the `node` on `PATH` between an nvm build, a Homebrew one and `/usr/local` moved it from 57ms to 141ms with one 772ms cold start.
So the honest figure is tens to a couple of hundred milliseconds, decided by which node answers and what else the machine is doing, and a single number here would be a measurement of this laptop rather than of the tool.
An earlier draft said 50ms off one warm run and the next draft 237ms off twenty, and neither reproduced.
`echo` is deliberately absent from the usage block and has no `commands/*.md`: a person never runs it and an agent must not, and the docs checker derives the slash-command set from that block.
Measured, from a report that the plugin does nothing in a worktree: a session inside a worktree below the scanned checkout, which is Claude Code's own `.claude/worktrees/` layout, was handed the main checkout's map, stamped as re-read just now, against a branch the counts never described, and a nested repository or unscanned submodule was handed the parent's the same way.
The walk now ends at a boundary: anything named `.git`, at any level holding no map of its own.
The map is asked for before the boundary at each level, so a scanned checkout still answers from anywhere below its root, whichever shape its own marker takes.
The cwd and the marker are both asked about links rather than around them, F2's reasoning arriving at the read side, and a level that cannot be resolved or cannot be looked at answers no map rather than throwing: a hook that exits non-zero interrupts the session it exists to help, on every turn and every tool call for the life of that session.
Three things stand and are named rather than parsed for, because this runs on every tool call: a fixture named `.git` reads as a boundary, a nested repository in another VCS has no marker at all, and the map itself is opened through its links, so a `.claude` or an overview symlinked out of the checkout is read and echoed.
The last is deliberate: the write side refuses it because writing outside the repository destroys what this tool does not own, while a reader that refused it would break the people who keep `.claude` in their dotfiles, and a hostile clone can ship a real file to the same effect.
One boundary is followed rather than stopped at, a linked worktree with no map of its own, and A93 says why A machine with no `node` on the PATH hooks run with fails every hook with exit 127 and `node: not found`.
This is not guarded in `hooks.json`: the POSIX guard is a parse error in the Windows PowerShell 5.1 that Claude Code falls back to without Git Bash, and `; exit 0` parses in both but still prints the shell's own stderr.
The README states the prerequisite instead.
