# B18

Section: B. Engine

## Decision

The raw parser transfer is refused on Windows, whatever `rawTransferSupported()` says

## Why

It allocates a 6 GiB buffer per parsing operation to take a 4 GiB-aligned window inside it, and oxc's own note says almost none of those pages is ever touched.
That is address space where the kernel overcommits and committed memory where it does not.
Windows does not overcommit, this pool runs up to eight workers each parsing, and Windows is the one platform where the pool's memory guard stands down because there is no `ps` to poll.
`rawTransferSupported()` asks about pointer width and the Node version and never about the platform

## Status

**done** `limits.mjs` (`rawTransferAllowed`), `parse-worker.mjs`.
The flag is experimental upstream and the parser answers the same tree without it, so the cost is the measured 3.06x on the parse alone, on one platform.
Not reproduced here: this machine is macOS, and the reasoning is oxc's documented allocation plus Windows commit behaviour rather than a run Where the 6 GiB reservation is refused on any platform (a `ulimit -v`, strict overcommit), `parse-file.mjs` (`parseWith`) drops the raw transfer for the rest of that worker on V8's `Array buffer allocation failed` and parses the same file with the plain transfer.
Measured under `ulimit -v 4000000`: every JS/TS file had come back unreadable and the scan removed the correct area files.
Matched on the text rather than on RangeError.
The raw transfer's own deserializer recurses in JS and throws `Maximum call stack size exceeded` near 3,000 operands in one expression, and that file alone is parsed again with the plain transfer, which measured 0 errors from 3,000 to 30,000 operands and on a 116,000-statement file under the cap.
The plain transfer segfaults only near 100,000 operands, which the forked worker contains (B2).
Such a file is charged as crashed rather than as could not be parsed, deterministically and on one attempt, and a language whose every file is one is held as unreadable (`unreadableLangs` in `scan.mjs`), which is the honest answer when no engine read it.
