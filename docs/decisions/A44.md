# A44

Section: A. Delivery

## Decision

A second hook fires on `PreToolUse` for `Write`, `Edit` and `NotebookEdit`, answers for the one path that call is about, and is silent otherwise. It informs and never refuses

## Why

The claims a repository states arrive on `PostToolUse`, after the file exists, and an area's own file loads only when something in that area is read, or from 2.1.288 after a `Write` or `Edit` there has landed and never before it (2.1.288's changelog, and two call sites read from the build in `docs/research/what-changed-between-2-1-286-and-2-1-290.md`), so the directory nobody read is both the blind spot and where a convention gets broken.
A session was handed the overview more than a hundred times and still put a vitest spec in a page directory whose 1003 files hold no test, then a spec in a `spec/mailers` its own commit created.
Silence on the ordinary write is the design rather than a saving: an unchanged block on every result is what taught that session to skip the clause that mattered, so this speaks only where the counts have something to say, and only for a path nothing is at yet.
An `Edit` names a file that exists every time and a `Write` over one is a rewrite, so there the path was chosen turns ago and repeating the block on each edit of the same spec is the banner this exists instead of.
`Edit` stays in the matcher even so, because the guard that decides is the file's absence rather than the tool's name, and a build that lets `Edit` create one should not need this reopened; the spare process costs 0.08s measured on microsoft/vscode, against a `PostToolUse` matcher of `*` that already spawns one per tool call.
The counts named are the source root's rather than the target directory's, which the issue's own example asked for: a directory the write is creating holds nothing, and "this directory: 0 files" is a line that says nothing.
The issue asked for a second verdict on the write that is fine, `RARE, precedented`; refused, because that fires on nearly every write and is the same banner in different words.
It asked to stop re-sending the unchanged overview too; also refused, since the always-loaded channel is the one that measured 100% and this hook is on top of it rather than instead of it, and what was actually wrong was that nothing spoke at the moment the path was chosen.
It never refuses.
Measured on 2.1.250, `PreToolUse` honours `additionalContext`, and `deny` or `ask` are the only answers that stop a path being chosen; the rule behind the notice rests on a namesake match that reads a tested directory as untested where the names differ in case, and refusing on a count that can be wrong stalls real work.
Every other failure mode there lets the write through and says nothing, and only exit 2 blocks, so the hook never exits 2 and answers `{}` for anything it cannot decide, which is the guarantee A24 already makes for the other three events.
The target is read per tool, because `Write` and `Edit` spell it `file_path` and `NotebookEdit` spells it `notebook_path`, and both it and the root are resolved through their links before they are compared: the root arrives resolved and `resolve` follows none, so a payload carrying `/tmp/x` against a root reading `/private/tmp/x` read as another repository's file and the hook said nothing at all.
The record is read through the same bounded, typed reader the map is, since a named pipe at its path never returns and this runs before every write, but held to its own cap: the record is the whole count of a repository, measured at 9,957,450 bytes on microsoft/vscode, and the megabyte a rule file is held to would have silenced this on exactly the repositories where a directory nobody read is easiest to miss.
The matcher is a list of names rather than a pattern, which is how that build reads one holding only names and pipes.
A notebook cannot produce a notice today, since `.ipynb` is not one of the extensions a test file is held to; the tool stays in the matcher because which key it spells its target with is a fact about the wire rather than about what a rule does with it.
What the matcher cannot reach is named rather than papered over: a model that writes with a heredoc through `Bash` never touches `Write` at all, and under `bypassPermissions` that is an ordinary path.
Measured in a real session, that write got the placement right anyway off the sentence the map states, which is the half of this that is read rather than fired, and the two halves are complementary for exactly that reason.
Matching `Bash` instead would mean parsing a shell command for its redirect target, which is a guess about somebody else's grammar on the hottest tool there is.
