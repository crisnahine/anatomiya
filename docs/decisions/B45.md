# B45

Section: B. Engine

## Decision

A Dependabot pull request that moves the root lockfile has the plugin lockfile regenerated on its own branch by `.github/workflows/dependabot-lock.yml`: only on Dependabot's own pull requests from this repository, with `npm install --package-lock-only --ignore-scripts`, actions pinned by sha, and ci started by `workflow_dispatch` on the pushed commit

## Why

B35's `plugin-lock --check` fails on every Dependabot bump of a runtime dependency until somebody runs `npm run lock:plugin` on the branch by hand.
A push made with a workflow's own token starts no workflow run, so without the dispatch the pull request keeps the failed check of the commit before.
The write token lives in the one job that pushes, on a branch only Dependabot and people who can already push write to
