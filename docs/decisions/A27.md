# A27

Section: A. Delivery

## Decision

Every plugin this repository's marketplace lists is validated as a plugin by `scripts/validate.mjs`: its own `.claude-plugin/plugin.json`, the paths that manifest names, and the file each of its hooks runs. The workflow's own inline copy of those checks is gone, and the script is the copy CI runs

## Why

A second entry was checked for one thing, its directory existing, so a plugin with no manifest, a manifest naming another plugin, a version that is not semver, or a hook running a file the plugin does not ship all shipped green.
Two copies of the contract had already drifted apart in one commit: the inline heredoc read `owner` and the `plugin.json` path keys and the script did not, the script read every listed plugin and the heredoc did not, and neither copy of the overlap was under test.
Returned as sentences rather than printed, because the failure cases only exist as trees on disk and that is what put 51 cases under test.
A review round then read the loader itself and found the script refusing what the loader installs, an object source naming a remote, a prompt-type hook with no command, and a bare `.`, which the entry schema rewrites to `./` before anything reads it, and passing what the loader drops: a hook with no `type`, a `../` spelling, which the schema refuses even where it re-enters the repository, a duplicate name behind a remote source, and a link out of the repository under a manifest directory, a hook file or a declared path.
A first correction took the loader's own marketplace validator, which skips any source carrying `..` from its checks, for the install path, and refused what installs; the install path is a traversal guard, so a source that starts with `./` and resolves inside the marketplace is a source, whatever its name carries.
Two rules of the loader's are the script's now: a local source starts with `./` and resolves inside, and a hook is one of five literal kinds, `command` with its exec-form `args`, `prompt`, `agent`, `http` or `mcp_tool`
