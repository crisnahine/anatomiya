# H47

Section: H. Layout

## Decision

The `test_precedent` sentence stays armed by any runner's pairing and keeps its wording; tying it to one runner and softening it were both refused. The root that arms it has to be one the overview prints, which is H39's

## Why

The request was for either, because vitest specs under `src/utils` armed the line over `src/pages`, whose tests are Cypress specs in a tree of their own.
On that repro with this build: the overview prints the sentence, and the tests line two lines above it names `2 Cypress under cypress/integration`, so "put the test where the siblings put theirs" points at that tree.
A new Cypress spec written under `cypress/integration`, in a new directory or beside the others, gets no notice at all; only a vitest file beside a page gets the per-write notice, which already reads "Nothing here was matched to a test by name".
The sentence says where a test goes and never to skip one, and H38 already names the own-tree zero as a limit.
Tying the conjuncts to one runner needs a runner per test tree that the namesake matcher does not have, and softening moves the wording H39 chose with no session seen skipping a spec because of it.
A transcript of one that did is what reopens this.
"Two lines above it" holds only where the directory with no precedent has a line.
Over 56 scanned repositories, read off each record and overview: 3 of the 35 older ones (backstage, prisma, next.js) and jellyfin store the key armed only by roots the budget folds away, and none of the four prints the sentence; no repository prints it without the key, and babel and junit5 print it on unpaired roots the page shows.
Release 0.13.4 prints it on those three older ones and on vscode, whose declaration files it counts, and not on fastlane, whose Java it does not read
