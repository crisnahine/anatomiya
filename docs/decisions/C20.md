# C20

Section: C. The counted-claim model

## Decision

An export statement counts as a naming site only where it is a direct top-level statement, never one nested inside an ambient module or namespace declaration

## Why

Extends C12's principle, an ambient declaration is not module state, to a site C12 did not cover.
`declare module "legacy" { export var legacyGlobal: number }` is scaffolding describing an external dependency's shape, not a binding this file creates, and the Flow retry deletes the whole block.
The three split naming rows first walked the whole tree, matching the row they were split from, which counted `legacyGlobal` as one site before a retry and zero after: caught by `test/stripped-consistency.test.mjs`, the same battery C12 cites, and reproduced first as a unit test naming the exact shape before the fix

## Status

**done** `dimensions-naming.mjs` (`exportedSites` reads `program.body` directly rather than walking the tree), pinned by `test/naming.test.mjs`.
A real ES `export` is always a top-level statement outside this one ambient exception, so the narrower read changes nothing on ordinary code
