# C54

Section: C. The counted-claim model

## Decision

No row asks how a function or method is named in any of the seven languages. Python, PHP, Java, Kotlin and C# were measured and refused; Go and Rust were not asked

## Why

The learning `function_naming_case` runs, over every function and method an author named, three repositories per language, sites agreeing with their area's commonest class: Python 0.9929, 1.0000, 0.9895 (django, flask, fastapi); PHP 0.9993, 1.0000, 1.0000 (laravel, composer, Slim); Java 1.0000 in commons-lang, junit5 and gson; C# 1.0000 in jellyfin, serilog and Newtonsoft.Json; Kotlin 0.9986, 0.9693, 0.9491 (okhttp, ktor, kotlinx.serialization).
No repository is under 0.90 and the widest spread is Kotlin's 0.0495, against a bar of 0.15.
PEP 8, PSR-1, the Java and Kotlin style guides and .NET's naming rules each fix the case, so the claim is one an agent could not have broken.
Among Kotlin's misses are factory functions named for the type they return.
Go and Rust were not measured: in Go the case of a name's first letter is its visibility, which the compiler reads, and rustc warns by default on a function not in snake case (`non_snake_case`), so each is a claim the language already decides
