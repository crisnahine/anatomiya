# A25

Section: A. Delivery

## Decision

Nothing is written outside `.claude/rules/` and `.claude/anatomiya/` unless a target is on, which `scan --targets` makes it, or an overview this tool wrote that is already in the target's directory, as in a clone of a repository that commits one: a target that is on adds `.cursor/rules/` or `.github/instructions/` (A102), each held to A104. What is left in the local settings scope is a removal, contained by F2, subtracting rather than replacing, and refusing a file it cannot parse

## Why

A1 keeps this tool's writes inside `.claude/rules/` so a writer bug cannot destroy something maintained by hand, and A24 needs a settings file, which is exactly such a thing: it holds permission lists and other people's hooks.
Four rules keep A1's reasoning intact rather than spending it.
F2 first, and it was missing: `join` normalises `..` and resolves no link, so a tracked `settings.local.json -> ../../x`, or one link at `.claude`, both of which survive a clone, put this write in a file the repository does not own.
Measured before the containment call existed, against a real scan: a JSON file two directories outside the repository came back with our hooks merged into it.
The local scope, because `settings.json` is the shared file a team commits and `settings.local.json` is Claude Code's own per-developer one, which is also where a map that is already git-ignored belongs.
Merge-only, keyed on the command string, so installing twice adds one hook and a sibling on the same event is left beside it rather than under it.
And a settings file that does not parse throws instead of being replaced: a writer that reads unreadable as absent is a writer that deletes what it could not read.
The same rule at every level a spread reaches, because only the top one was checked at first: `"hooks": "PreToolUse"` spread into `{"0":"P","1":"r",...}` beside the real entries and was written back that way, and an event whose value was a string spread into a list of characters

The removal is written to a temporary file beside the settings file and renamed over it (`atomic`), so a write cut short, by a full disk or a file-size limit, leaves the file as it was rather than empty. A rename asks only the directory's permission, so a settings file its owner made read-only is refused first, as a write in place refused it.
The exclude line is part of the same decision: a scan that leaves an untracked file without documenting it hands a reader a dirty `git status`, and the README spelled those lines by hand with nothing reading them, so `check-docs` asserts every `EXCLUDE_LINES` entry appears there.
