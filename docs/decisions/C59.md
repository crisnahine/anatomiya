# C59

Section: C. The counted-claim model

## Decision

A URL path's words are a learned naming row: `url_segment_case` over a route's own definition in JavaScript, a route table's or a server's, and `route_segment_case` over a Rails routes file. Each word of two or more words that spells a naming class is a site, a parameter and a single word are not, and a path built at run time is the predicate's blind spot

## Why

A reviewer caught `/members/support_tickets/create/:id?` in a route table whose other multi-word segments are kebab-case, and 0.15.5 said nothing, because no row read a string for its words (#238).
The corpus splits on it: in the research note's probe of every URL-shaped string, 12 of the 19 repositories holding 20 or more sites hold one side at 0.90, 7 snake_case and 5 kebab-case, and in its probe of Rails routes alone 9 repositories hold a side and a measured Rails API alone holds kebab-case, which a model writing Rails's default could not have guessed (`docs/research/what-no-row-reads.md`).
A JavaScript `path` key names a file, a cookie's scope or a JSON pointer everywhere but a router, so a route object is read only in a file importing one of 13 router modules or named for its routes, and an element's `path` only where its name ends in `Route`.
A server's `router.get("/path", handler)` is a declaration too, read on a receiver named app, server, fastify, hono or router or ending in `Router` or `App`, since `api.get("/path", config)` is a request client's call.
A test file holds no site, and neither does a file in a test tree: discourse's data-explorer acceptance tests stated the claim off 35 `server.get(...)` mocks of the plugin's API, which a test declares for the code under test rather than for itself.
A Rails site's identity in the check is its verb and its paths: with its line in it, a route that only moved down the file came back as three new findings on a measured Rails API.
A link was read at first and is not: it names a route rather than declaring one, and over the corpus link sites stated in 9 of the 203 slots they opened, 194 counts lines spent on a route the table already states.
A `resources` symbol is a path, since Rails serves it as one unless a `path:` option replaces it, and that default is exactly where a kebab-case team writes the option.
Two keys rather than one, because one key is one predicate and the two engines read different trees.
Measured on clones of the two measured repositories with the change: the front end's `src/router` states the claim over 41 of 41 sites, the API's `config` area over 256 of 259, and a branch adding the #238 path, or a `get 'support_tickets/create'` in the API's routes, is a FIX on the line.
Measured over the 35-repository corpus: `url_segment_case` states in 1 area, a measured React front end's `src/router`, and `route_segment_case` in 11 (4 in openproject, one each in consul, diaspora, a measured Rails API, forem, canvas-lms, mastodon and openfoodnetwork), every one snake_case but a measured Rails API's. With links read it stated in 9 areas and printed a counts line in 194 more, 102 of them in next.js.
Every exception in those slots was read word by word, and two shapes were not the team's to choose and are no sites: what sits under `.well-known` (`openid-configuration`, `apple-app-site-association`), and a single word, openproject's SCIM `Users` and `Groups`, which the standard spells.
A third was the tool's own: the Ruby tree keeps 40 characters of a string, so a measured route of 42 characters read its last word two letters short, and the last word of a string that long is no site now.
Compared with the build before it, no existing slot moved in any of the 35 repositories, and the four rows this branch adds (`url_segment_case`, `route_segment_case`, `strong_params_style` and `spec_type_declared`) state 308 claims, which shows as 307 more stated claims printed with counts because 1 stated claim, in one area of canvas-lms, lost its counts line to the 40-line budget

## Status

**done** `dimensions-naming.mjs` (`url_segment_case`, `ROUTER_MODULES`, `pathWords`, and `namesWellKnown`, which both rows ask of every route around a site), `dimensions-rails.mjs` (`route_segment_case`, `routePaths`), pinned by `test/naming.test.mjs`, `test/applicability.test.mjs` and `test/dimensions-rails.test.mjs`.
Not read: a link, a Vue or Svelte template's `<router-link>`, a file router's directory names, a route declared through a function (React Router 7's `route("x", file)` from `@react-router/dev/routes`, TanStack's `createFileRoute("/x")`), a `path` given as an array, and a request path handed to `fetch`, which names another service's URL rather than this one's.
A `path` key counts only on an object that also names what the route renders, nests or loads, since a router file can hold a cookie's or an upload's `{ path }` too
