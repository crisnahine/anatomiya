# C45

Section: C. The counted-claim model

## Decision

A facts.json that is on disk and does not parse is map-unreadable, never no map

## Why

A committed map that conflicted on a merge printed "no map on disk" and, two lines later, talked about "the map on disk".
The pin reader already separated the two for the same cause and said so in its own comment, so the facts reader was the one left behind.
A shape that parses but is not a record at all still reads as no map, which is `schemaProblem`'s not-a-record rule
