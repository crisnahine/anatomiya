# C67

Section: C. The counted-claim model

## Decision

A row that learns its class clears point 3 of the bar a new dimension has to clear when the class differs between repositories of one language, each holding its own at 0.90 or more, since then no single form is that language's default. `endpoint_segment_case`'s Python, C# and Rust halves clear it this way; by the point's letter only its Java half does

## Why

Point 3 refuses a claim every repository holds near 1.0, because such a claim is a language's default and the map would state what the model already writes.
A learned row's claim is whichever class an area holds, so its ratio sits near 1.0 wherever a repository is consistent, whatever class that is: a spread of ratios measures how mixed repositories are, not whether a default exists. One class across a language's repositories is what shows a default, and two classes in one language show there is none.
C62's numbers: Python netbox kebab-case (`netbox/dcim` 99 of 99) against healthchecks snake_case (`hc/front` 7 of 7); C# bitwarden kebab-case in 7 areas against jellyfin PascalCase (`Jellyfin.Api/Controllers` 139 of 139); Rust vaultwarden kebab-case (`src/api/core` 70 of 72) against lemmy snake_case (`crates/api` 28 of 28, short of the evidence gate); Java thingsboard camelCase against dolphinscheduler kebab-case (104 of 114, short of the evidence gate), with appsmith's `controllers/ce` mixed at 27 of 43, the one repository that also clears the letter.
C59 and C60 cleared the point as written, with repositories under 0.90.
