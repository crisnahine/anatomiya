# A123

Section: A. Delivery

## Decision

The reuse check's reason (A91) asks the subagent to name every existing function that does the same job or part of it, and the session to call the closest one for each added function, the repository's own before a package's, to call one that does part of the job for that part, and, where one falls short on a case the change needs, to fit the new code to it or to extend it without changing what it returns to its current callers

## Why

The first wording asked for a function that "does the same job" and to "call each named function", and its misses had one shape: the session named the helper and kept its own copy because the helper fell short on one case.
On eslint, all 14 Opus sessions with the plugin that missed named `unIndent` and kept a helper because `unIndent` strips spaces and eslint indents with tabs; on whitehall the one Haiku miss wrote "the one open option is to have `external_link_to` call `is_external?` instead"; on mastodon, Haiku's misses named `local_url?` or `local_uri?` and kept a copy over a default port or an unparseable URL.
A pilot of 5 sessions per arm with the part about a function that falls short took eslint on Opus to 4 of 5, whitehall on Haiku to 5 of 5 and mastodon's link policy on Haiku to 3 of 5: the eslint miss refused to extend `unIndent` because three callers pass tab-indented sources, where the hit rewrote its own sources with spaces to fit it, and the mastodon misses called `ActivityPub::TagManager#local_uri?` or named only that one.
A second pilot with "every", "the closest one" and fitting the new code took mastodon's link policy on Haiku to 7 of 10, every miss calling `ActivityPub::TagManager#local_uri?`, another existing helper that also checks the local domain, and eslint on Opus to 4 of 5, the miss calling `stripIndent` from the `common-tags` package where the repository's own `unIndent` was the one asked for.
So the reason asks for every candidate, the closest one, the repository's own before a package's, and fitting the new code as well as extending the helper; "without changing what it returns to its current callers" is what keeps an extension from breaking them, which the four hard cases' look-alike of `extOf` (A91) is there to catch
