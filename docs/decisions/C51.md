# C51

Section: C. The counted-claim model

## Decision

`caught_error_used` asks PHP and Java whether a catch clause that binds the error reads it or throws. Python, Kotlin and C# were measured and are not asked

## Why

A Java clause that names what it caught `ignored` binds nothing, as `_` does.
A name spelled like the caught one where the language reads no variable is no read: a PHP static property (`A::$e`, `self::$e`) and a property a class declares (`static $e;`, `public $e = 1;`), and in Java an annotation argument's name, an annotation's one unnamed argument (`@A(e)`), a label, the name a `break` or `continue` jumps to, a `case` constant, and the method of a method reference (`A::e`, `this::e`), whose qualifier is still a read (`e::getMessage`).
PHP 0.9936, 0.7907, 0.5714 (laravel 465 of 468, composer 170 of 215, Slim 4 of 7), spread 0.4222, and 0.2029 between laravel and composer with Slim's seven sites set aside.
Java 0.6000, 0.9440, 0.8692 (commons-lang 90 of 150, junit5 539 of 571, gson 93 of 107), spread 0.3440, two of the three under 0.90.
`ignored` rests on one tool: IntelliJ's `CatchMayIgnoreException` inspection passes over a catch parameter whose name matches `ignored?[A-Za-z\d]*`, and over `expected` in test sources only.
Error Prone's `UnusedVariable` exempts a variable named `ignored` as well, but it has no case for a catch parameter and reports none under any name, and its `EmptyCatch` exempts no name, so Error Prone says nothing either way.
Of the names IntelliJ's pattern fits, `ignored` alone is read, and `ignore` and `ignoredException` stay sites.
So named are 18 handlers in commons-lang, 3 in junit5 and 7 in gson, none of which reads what it caught; counted as sites the three read 0.5357, 0.9390 and 0.8158.
Python 1.0000 in all three (django 285 of 285, flask 19 of 19, fastapi 23 of 23): a Python handler binds a name only where it means to read it, so the claim is one nobody breaks.
Kotlin 0.7703, 0.8239, 0.7059 (okhttp 171 of 222, ktor 407 of 494, kotlinx.serialization 24 of 34), where a Kotlin `catch (_: E)` is a typed handler with no name and so no site: all three under 0.90 and a spread of 0.1180, short of 0.15 by 0.0320, three repositories that ignore the name at about one rate.
Counted as an unused binding, `_` is 61 of okhttp's 283 sites and the three read 0.6078, 0.6333 and 0.6486.
C# 0.9321, 1.0000, 0.8961 (jellyfin, serilog on 17 sites, Newtonsoft.Json), spread 0.1039.
A handler is rare, as it is for `swallowed_error` in JavaScript: a site sits in 0.10 to 0.25 of the files read, test files counted.
With generated files left out one count moves, Newtonsoft.Json from 69 of 77 to 68 of 76.
No row in the tree counts the Python, Kotlin or C# sites, so `docs/measurements/2026-10-07-refused-rows.md` is the record of their ratios

## Status

**done** `dimensions-tree.mjs` (`caught_error_used`, `UNBOUND`, `caughtName`, `readsName`), `test/dimensions-tree.test.mjs`.
What this gives up: a Kotlin or C# repository that swallows errors is not told; a PHP or Java handler holding only a comment that says why counts as not using the error, and so does a Java handler that restores the interrupt flag and reads nothing of what it caught; a Java handler named `ignore`, `ignoredException` or `expected` is a site; a throw anywhere under the handler's body counts as the handler throwing, inside a lambda or an anonymous class too; the value of a named annotation argument (`@A(k = e)`) counts as a read; PHP before 8.0 cannot write a clause with no variable, so a deliberate swallow there has no spelling that conforms, and composer, which reads 170 of 215, supports PHP from 7.2.5 (`"php": "^7.2.5 || ^8.0"` in its `composer.json`)
