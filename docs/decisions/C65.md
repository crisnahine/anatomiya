# C65

Section: C. The counted-claim model

## Decision

No row is built for the other unread classes: a directory name's case, a test title opening with "should", a module-level primitive constant's case, an object literal key's case, an i18n key's segment case and its shape, Rails views' lazy keys, the TODO form, and an error message's final period were measured against the bar and refused

## Why

#242 asked for each to be measured against the bar's spread, over the three corpora with the tool's own `collect`, `discover` and gates (`docs/measurements/2026-10-23-unread-classes.md`).
Refused on the numbers. A module-level primitive constant: applicability under a quarter in all 22 C35 repositories with 20 sites (0.034 to 0.182), and the non-SCREAMING side clears the area gates in one repository. An object key: 5 of 28 hold, all camelCase, and the snake_case area holders are translation tables or one file each (eff 1.0 to 1.7). i18n key shape: 7 of 8 hold, identifier 5 and English text 2, and the learned ratio runs 0.886 to 1.000, a spread of 0.114 under the bar's 0.15. The TODO form: applicability under a quarter in every repository (JS 0.008 to 0.169, Ruby 0.012 to 0.073), and `Style/CommentAnnotation` already requires the colon wherever RuboCop runs. An error message's period: applicability under a quarter in all 20 JS and 18 Ruby repositories, and the period side clears the area gates only in React's compiled output vendored under next.js's `src`.
Rails views' lazy keys: 12 with 20 sites, 8 hold the full key, spread 0.399, but a template reaches no parser and has no area, so the row cannot be built as the tool stands.
Four cleared the numbers, Rails views' lazy keys among them, which no parser here reads; the other three and i18n key shape, whose spread fell short, were put to 16 sessions with no map, one model and one effort (G11); in every one that wrote the construct the agent matched the repository's side, having globbed or read the siblings first.
Which side a model writes unprompted (`scripts/measure-defaults.mjs`) was not measured and decides none of them: the five refused on the numbers fail the bar without it, and the four put to sessions were tried in the repository whose side a model is least likely to write, where the agent matched that side anyway.
Directory name case (30 C35 repositories with 20 directories, 12 hold, spread 0.521): appsmith's PascalCase, 4 of 4 sessions that wrote a directory, one of them with no sibling directory, where the parent's own PascalCase files showed the side.
"should" titles (35 with 20 sites, the "does not" share spreading 0.851; the Ruby half is `RSpec/ExampleWording`'s): angular's `packages/common/test/pipes`, 3 of 3, 20 titles all opening with "should", each after reading a sibling spec.
i18n key segment case (6 of 7 hold on two sides, the bar's one repository under 0.90 being a measured React front end's 21 sites at 0.619): backstage's camelCase, 3 of 3, each after reading `translation.ts`, the file a new key has to be added to.
i18n key shape: Ghost's English-text keys, 3 of 3 sessions that wrote a key, where Ghost's own CLAUDE.md shows English-text keys too, so the siblings and that file cannot be told apart
