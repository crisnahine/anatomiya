# B65

Section: B. Engine

## Decision

A wasm `RuntimeError` fails the file it was thrown on and retires the worker: the reply carries `retire: true`, and the pool kills that process and starts another before it hands out a file

## Why

Measured: after the abort in B62 a new parser in the same process threw the same `RuntimeError: Aborted()` on a one-line file, so the process is spent and only a new one reads the next file.
The worker says so on its last reply, because a worker that exits by itself between two files is read by the pool as a crash on the second.
Given up: the trap is recognised by the error's name alone, and the file that hit it is counted unreadable even where a fresh process would have read it
