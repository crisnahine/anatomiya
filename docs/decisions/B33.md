# B33

Section: B. Engine

## Decision

A `.js` or `.cjs` file oxc rejects for a top-level `return` is retried with each reported `return` keyword blanked in place, same length, and reparsed. `.mjs` and the TypeScript extensions are never retried this way

## Why

`parseOptions = { sourceType: "module" }` for every file charges a valid CommonJS file using a guarded top-level `return` as a syntax error. backstage: 1 file, a standard OpenTelemetry preload. next.js: 5 files, all `node --check` clean, two of them vendored copies of the real `bull` and `bullmq` packages.
**`sourceType: "script"` does not fix it**, confirmed by parsing the same fixture both ways: plain Script grammar disallows a top-level `return` exactly as module grammar does, and only Node's own CommonJS function wrapper permits it.
Reproducing that wrapper would nest the whole tree a level deep and break every walker that reads `program.body` as the module's own statements, so the retry blanks the keyword instead: oxc's error carries the exact byte span of each illegal `return`, checked equal to the literal text before it is touched, and any other error in the same file leaves it rejected rather than partly patched

## Status

**done** `langs.mjs` (`mayBeCommonJS`), `parse-file.mjs` (`withoutTopLevelReturns`), pinned by `test/langs.test.mjs` and `test/parse-file.test.mjs`.
Retried only on failure and only where the dialect could apply, the same shape B19's Flow retry already uses, so a file that parses clean pays nothing.
`.mjs` is excluded because Node always loads it as ESM; the TypeScript extensions because TypeScript rejects a top-level `return` as source before any module format is chosen.
Deliberately outside `stripped`/`blindWhenStripped` (B20): this retry blanks a keyword rather than a type, so a file it recovers keeps every row Flow-stripping would have cost it
