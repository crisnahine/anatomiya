# F28

Section: F. Safety

## Decision

A JavaScript site's place is the nearest named owner around it: `Class.method` for a member of a named class, a class expression bound to a name taking that name, `name.method` for a method of an object literal bound to `name` (through nested literals, conditionals, `||`, `&&` and `??`, call and `new` arguments, `await`, `as`, `satisfies` and parentheses), and for an unnamed function the place of the nearest named declaration around it. Only a class's own members carry its name: a named function declared inside a method or a static block is its own name, and so is a method of an object literal a field holds, since only a variable binds a literal

## Why

The JavaScript rows set `where` to the function's bare name, so two identical sites in methods of one name in two classes were one place, and `absorb` (F24) paired a new copy with the old one by walk order: a catch added in `B.run` above the old one in `A.run` was reported on the old line.
The tree rows already named the class (`ownerOf`) and the Ruby rows `A#run`.
Measured on twelve shapes in JavaScript, TypeScript, Vue and Svelte, 48 runs per build: 48 of 48 right, against 32 on the build before.
The same defect held for callbacks, object-literal methods and component methods, `defineComponent({ methods: { run } })` bound to `C` giving `C.run`.
`where` is no part of a site's identity and no map file holds it, so maps do not move; only which copy `check` reports, and its text, moves
