# C40

Section: C. The counted-claim model

## Decision

The check judges a learned-class site as the fold counts it: a bare constant is resolved against its nesting (`sameConstant`), and the chain of parents is followed through the map's `reaches` and through what the branch's changed files in the same area declare, the branch replacing the map where both name a class

## Why

The check held only `reaches`, so a base the branch adds was never in the chain: each of its subclasses was told to inherit the learned base directly while a scan of the same tree counted it as conforming, 31 FIX and 0 real on a replayed empire-flippers/api merge.
The same predicate compared as written where C30 resolves, so a relative superclass the map counted was a finding.
Per area as the pinned map draws it and first-seen, as `parentsIn` builds it, so the check and a fold over the same areas follow the same classes; a base added in another area is followed by neither.
A directory the branch adds inside an area is still that area to the check, and a rescan may make it an area of its own: a class there that the parent area's classes subclass is then followed by the check and not by the fold, so the check passes a subclass the rescan lists as an exception.
The check is the lenient side, and that subclass does reach the learned base.
The branch's declaration replaces the map's because a class moved off the base must stop carrying its subclasses
