# B52

Section: B. Engine

## Decision

A `.vue` or `.svelte` file is a language of its own in the JavaScript family, on the `oxc` engine, read through its `<script>` blocks alone. A hand-written scanner finds the blocks, and neither framework's compiler is a dependency

## Why

`oxc-parser` reads no component file: handed one whole, its grammar rejects the markup, so both extensions failed `isSource()` and a Vue or Svelte repository was counted over its plain modules only, with every component left out.
No tree-sitter grammar reads them: `tree-sitter-vue` was last published in March 2021 (0.2.1) and its package holds no `.wasm`.
The scanner follows each compiler's own rules for what a block is and where it ends, in one forward pass that never reads the JavaScript, since both compilers end a body at the first end tag, inside a string too.
Compared with `@vue/compiler-sfc` and `svelte/compiler` on where each block's body starts and ends and on its `lang` (`docs/measurements/2026-10-08-script-blocks-against-compilers.md`): 0 of 4,100 Vue files wrong across eight repositories, 0 of 3,586 Svelte files wrong across three repositories, and 1 of 4,462 wrong on Svelte's own test components.
Vue keeps the first `<script setup>` and the first plain `<script>` at the top level, skips a template by counting nested templates, and leaves out a block with a `src` or with a `lang` that is not JavaScript or TypeScript.
Svelte keeps the first module script and the first instance script, and the first `<script>` that states a `lang` decides it for both.
A Svelte `<script` counts only where nothing but a comment, a style block or an accepted script precedes it on its line, an indent included, because telling a nested script from the component's own takes the parser: against the compiler on those 4,462 files that rule misses 1, allowing an indent 5, and no line rule 8, with 0 of the other 3,586 files wrong under all three.
The scan is linear.
Measured on 34 megabyte shapes per framework at a load of 5: a megabyte of paired tags took 17 ms, and the slowest megabytes, built to be slow, took 60 ms (one tag with 250,000 attributes) and 58 ms (50,000 closed script tags), with 4 MB of each a little over four times that.
In a Vue file a block's body ends at `</` and its name held one character at a time against the name as written, each with its case bit set, so a lower-case name ends in any letter case and a name holding an upper-case letter or `_` ends nowhere and takes the rest of the file, which is how `@vue/compiler-sfc` reads `<TEMPLATE>`, `<Script>` and `<my_block>`.
A name is lower-cased once, where its tag is read, for the raw elements inside a template: built again at every `</`, the lower-cased copy of a 249,999-character name took over 60 seconds from the third scan in one process.
A comment, CDATA, a processing instruction and any other `<!` are passed over to the end Vue's tokenizer gives each.
A comment's end is looked for from its own two dashes, so `<!-->` and `<!--->` are whole comments, as the compiler reads them.
Against `@vue/compiler-sfc` 3.5.43 on 31 hand-built shapes of those and of upper-case tags, all 31 give the same blocks.
`.svelte.js` and `.svelte.ts` are plain modules and stay `js`.
What this gives up: a Svelte component that indents its top-level script reads as having none; a refused `<script` that is only a mention with no end tag of its own (`<div title="<script>">`) reads on to the next `</script>` and takes a real script with it (0 of 8,048 measured files); a Svelte block in a `lang` that is neither `ts` nor `js` (`coffee`) is read as JavaScript and the file is rejected unless the body parses as JavaScript, while Vue leaves such a block out and the file reads as having no script; and in a Vue file a template, a style block or a comment that never ends stops the scan there with nothing rejected, so a script above it is kept and a script below it is not found, as Vue's compiler finds no block after it either.
A style block or a comment that never ends does the same in a Svelte file, where the compiler rejects the file.
A `{{` with no `}}` after it ends a Vue scan the same way though the template closes, which is valid under `v-pre`: `<code v-pre>{{ opens an interpolation</code>` in a template above a `<script setup>` reads as a component with no script, and the same file with the script first gives the script's site
