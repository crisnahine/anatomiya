# A113

Section: A. Delivery

## Decision

A scan reads a file whole to put it back only up to 64 MiB, the record's own bound, and asks the size before the read. A file past it at a name the map writes or removes refuses the scan; the store's `facts.json` and `layout.json` past it are replaced without being read and never put back

## Why

A repository decides what sits at a name a scan replaces or removes, and with no cap a 600 MB file there took one scan, and every unattended refresh, to 807 MB resident: 682 MB at `.claude/rules/anatomiya-overview.md`, 807 MB at `facts.json` or `layout.json`; with the bound the same scans peak at 111 to 117 MB, against 109 MB with no such file, refusing at the overview and replacing either record unread (`docs/measurements/2026-10-11-put-back-bound.md`, one run each on a loaded machine).
The largest file a scan of the 60-repository corpus writes is microsoft/vscode's 9.7 MiB `facts.json`.
One bound with the record's reader, since a scan should read whole no more than any command reads, and two constants that disagree are one more to keep true.
No command reads a record past `RECORD_MOST`, so it holds nothing a reader could lose, and refusing over it would refuse every scan, the background refresh included, until somebody deleted it by hand; a rollback takes the new record out rather than putting the old one back

Asked at plan time with `lstat`, so a dry run says it, and again on the handle `previousBytes` already types; a file of exactly 64 MiB is read and put back.
In `.claude/rules`, and in a Cursor or Copilot directory the scan named, the scan refuses whole: `".claude/rules/anatomiya-overview.md" is 629145600 bytes, past the 64 MiB a scan reads to put a file back, so nothing was written: move or delete it and scan again`; in one it did not name, that directory reads `unknown` and `unwritable` and is left as it is.
A record past the bound is said once, `".claude/anatomiya/facts.json" was 73400320 bytes, past the 64 MiB any command reads of a record, so it was replaced without being read`, and the scan after is quiet.
Given up: a repository that commits a file past 64 MiB at a map name has its scans refused until it moves; a file that grows past the bound between the plan and the commit refuses the whole scan, even in a directory nobody named; area files an oversize record named read as `unknown` until a later scan writes their areas
