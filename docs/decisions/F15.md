# F15

Section: F. Safety

## Decision

A git read the check could not perform is reported, never absorbed as an empty answer

## Why

Measured: with the base commit's tree object missing, `git diff` exits 128 and every caller in `check.mjs` read its output without looking at the exit code.
The result was zero changed files, zero findings and no caveat, which renders identically to a branch that broke nothing.
Same shape as F13 for history and B13 for the parser, and the same rule closes it: tell "could not read" apart from "read, and there was nothing there", by exit code

## Status

**done** `changeset.mjs` and `check.mjs`.
Every read looks at its exit code before its output: the diff, the added-line ranges and the pending-edits listing in `changeset.mjs` (`changedFiles`, `addedRanges`, `pendingPaths`), and base resolution in `check.mjs` through `resolveBaseRef` and `mergeBase`, which report their outcome rather than an empty string.
A base the check could not ask git about stops it: HEAD, what a candidate names, which ref a typed `--base` names and the merge base each throw where the call had no exit code (F29).
No read of the check that states a fact is soft: whether the clone is shallow, which refs hold the name of a typed base and which parents HEAD's commit records each stop it where git could not be asked (`askGit`), since read as not shallow, a shallow clone is told its base resolves to no commit.
A read that could not be asked and does not stop the check is a caveat in the report: the shallow fetch, the directories at the merge base (`absentAt`) and a blob, with the file named.
The scan's probe of the same question, `shallowHistory` in `authors.mjs`, is unread history where git could not be asked (D11)
