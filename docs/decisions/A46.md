# A46

Section: A. Delivery

## Decision

The entry point reads `process.cwd()` only for the verbs that answer about a repository, and a hook is allowed to have none

## Why

`process.cwd()` refuses with ENOENT once the directory a session started in is unlinked, which `git worktree remove` does to a session sitting in one, and it is read before the payload, so the throw reached the guard and the guard answered the empty object.
Every hook is a fresh process, so both went quiet for the rest of that session while every payload was still naming live paths.
Measured on 0.4.2: the same payload, naming a live file in a mapped repository, answered 1,694 bytes with the shell's directory alive and `{}` with it unlinked.
The value is cached in node and throws only cold, so a case that changes directory and removes it afterwards reads the stale path and proves nothing; the process has to start with the directory already gone
