# H14

Section: H. Layout

## Decision

A learned row may declare `groupedSites`, and `module_include` is the one that does. The worker still emits one hit per included constant, and every hit of one class or module body carries that body's group, so the fold votes once per body and class, counts one candidate per body, conforms a body that includes the learned module whatever else it includes, and lists one exception per body. The check fires one finding per body, at its first include. A tie is still a tie (C13)

## Why

A Rails worker includes `Sidekiq::Worker` and one more module, so with one site per constant the row could not pass 0.5 whatever the directory did, and it failed closed on exactly the directories it was written for.
Measured on a Rails API: `app/workers/workers` read 125 of 234, which is 0.534 and stopped by the ratio gate; grouped it reads 125 of 125 and states, and `app/workers/cronjobs` goes from 70 of 140 to 70 of 70.
The gates, the baseline and the render are untouched because they read candidates, conforming and exceptions, which is where the grouping is settled.
`class_base` names one superclass per class and stays per site.
The grouped finding is fingerprinted from the constants the body mixes in, so adding a module to a body that already violated moves that fingerprint and the branch is charged for the violation: accepted, because the branch did edit the violating body and the severity is still capped by the baseline rules.
H16 added the body that mixes in nothing, which has no constants to be told apart by and answers with its own name instead, and which is reported at the class rather than at a first include it does not have
