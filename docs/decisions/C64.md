# C64

Section: C. The counted-claim model

## Decision

No row is built over non-source files: the YAML extension, the case of a Markdown or a data file's name, a CSS class selector's case, and locale key parity were measured over the three corpora and refused

## Why

#241 asked whether these hold a per-repository convention, over 85 repositories with the tool's own filters (`docs/measurements/2026-10-23-unread-classes.md`).
Three classes clear the numbers. The YAML extension, with the names a tool fixes left out and Rails's own `config/*.yml` and `config/locales` left out in a Rails repository: 35 repositories with 20 sites, 20 hold (`.yml` 18, `.yaml` 2), spread 0.362. Markdown stems: 38 with 20 sites, 25 hold (kebab-case 21, snake_case 3, Title-Kebab 1), spread 0.542. Data file stems (`.yml`, `.yaml`, `.json`): 37 with 20 sites, 19 hold (kebab-case 12, snake_case 7), spread 0.546. No linter in the corpus reads any of the three.
What decides them is that the sibling answers: of the sites with a sibling in their own directory, 0.983 of the YAML holders' agree with it, 0.993 of the Markdown holders' and 0.992 of the data holders'.
Then 17 sessions with no map, one model and one effort (G11): every one that wrote the construct matched the repository, and all but two had globbed or read the siblings first. woodpecker's `.yaml` 4 of 4, canvas-lms's snake_case doc stems 5 of 5 written (3 trials hit the turn cap and wrote nothing), consul's snake_case data stems 4 of 4 multi-word stems. The two that read no sibling first, canvas-lms's runbook with its text given and consul's polling stations (two globs and a Ruby model read, no data file), both with no sibling, wrote snake_case in Rails repositories where snake_case may be the model's own side, so there following the repository and following the model cannot be told apart.
A row would also have nowhere to sit: areas are built from source files, 0.863 of YAML sites, 0.904 of Markdown and 0.951 of data sit in a directory holding no source file, and feeding them to the area partition moves every floor, ceiling and glob against every pin.
#241's second way, a repository-wide fact on the What lives where root lines that `check` holds a new file to, does have a place, since the layout counts every tracked file; it is refused on the sessions above, where an agent with a sibling already matched, and the no-sibling case it would teach is the one left unmeasured below.
CSS class case: read as two sides, kebab-case against BEM, 27 of 49 hold, but a BEM block is kebab-case; read as one lowercase-hyphen family, 39 of 40 holders hold it, which is CSS's default and `stylelint-config-standard`'s pattern, and four of the kebab holders hold through a vendored bootstrap or a built stylesheet. Inside a stylesheet the file's own majority beats the repository ratio in every repository under the gate, and no reader of CSS exists here.
Locale key parity: not re-measured, since it needs a YAML reader and a pairing of locale files per framework. Of the 14 repositories the earlier note measured, 9 track a translation pipeline's config, and `i18n-tasks missing` is that check
