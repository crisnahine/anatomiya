# H11

Section: H. Layout

## Decision

Five learned rows carry a name out of the repository instead of a class from a closed set: `extends_base` and `class_base` for a superclass, `module_include` for a mixin, `interface_prefix` and `type_alias_prefix` for a declared type name's prefix letter. A source-learned class is encoded where the sentence is filled, and a row that can learn an absence writes the absence out in full

## Why

What a new file in a directory is expected to sit on is a review comment nothing here counted, and it is repository-specific by construction, which is what C13 already built the learning for.
Two rules the template alone cannot carry.
The class is text an attacker writes and it lands in a file the agent loads, so it goes through the encoder once at the fill rather than at every render site, where one site would eventually be missed.
And `none` is an absence rather than a value: filled in it renders "named with a `none` prefix", so a prefix row spells the whole sentence instead.
`none` is also the model default for both prefix rows, so a repository that prefixes nothing prints counts and a prefixed one states.
Keyed per engine and per construct, because one key is one predicate and a repository can prefix its interfaces and not its type aliases
