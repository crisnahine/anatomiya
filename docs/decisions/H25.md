# H25

Section: H. Layout

## Decision

A candidate the tail refuses is still credited when it imports the producer outright, and an import-only match votes for the directory the test sits in

## Why

H18 left a false negative it could not close from path shape alone: a plugin keeping its sources at `hooks/` and every test flat under `test/` leaves the tail `hooks` mirroring nothing on the other side and five genuinely tested files read `0 of 5`.
The shape is indistinguishable from the decoy H18 pins at `test/companions.test.mjs`, `apps/www/Page0.tsx` against `test/Page0.test.tsx`: same depth, same flat test root, same language, one-to-one stems.
No rule over paths can separate them, so the evidence has to come from the file rather than from where it sits, and `import ... from "../hooks/counters.mjs"` is the producer named in the one place a guess cannot be wrong.
Additive in what it counts, and only there: the tail is asked first and no match H18 measured is taken away, while the root a file votes for can move, which is the half that needed the most review.
The root is a separate question and the edge never wins it against shared structure, because an edge proves a file is tested and says nothing about where a root keeps its tests.
A covered candidate still votes whatever structure it shares; what it may not do is claim the vote when it shares none.
Reviewed and reproduced before shipping: claiming the vote let a foreign integration test that sorted earlier take `packages/core` from `packages/core/spec` to `apps/admin/test`, a true count under a false place.
A structural root now wins wherever any candidate names one, and the test's own directory is used only where none did.
Reviewed again against those fixes, which found three more: the empty string `wholeRoot` answers for the repository itself is not a place, and counting it as a vote let it outrank one that is; a compiled specifier stripped to its stem answered every file sharing it; and `./x/.` named a directory the trailing-slash guard did not catch.
A third round found one more, again from a fix: making the empty string falsy stopped it ending the walk, so a colocated test, which is what `wholeRoot` also reduces to nothing, let a second suite that merely imports the file name the place.
Structure that answers and names nothing now says so, and the edge does not name a place in its stead.
The same round found a specifier with no extension reaching every file that shared the stem, a stylesheet and a declaration file included, held off real maps only by the single-extension population one caller builds.
Measured old build against new over 12 repositories, `puppet`, `huginn`, `plots2`, `decidim`, `fastlane`, `consul`, `rubocop`, `commander.js`, `lodash`, `express`, `got` and `chalk`, which include H18's own counter-examples: 455 namesake claim lines, byte-identical on 11 of the 12, and every H18 counter-example among them.
`got` is the one that moves, and it moves from a false statement to a true one: `source/core` went 0 of 20 to 3 of 20, `source/core/utils` 0 of 12 to 2 of 12, and all three are hand-verified, `test/parse-link-header.ts`, `test/dns-cache.ts` and `test/weakable-map.ts` each importing the file they are named after through its compiled `.js` spelling.
No producer anywhere in the 12 is credited falsely.
On this repository it credits exactly 5, the five files the row was wrong about.
The stem still has to match, so the sentence stays the one it always was; a repository whose specs never name what they cover, which is every Rails tree here, gains nothing and is told nothing new

## Status

**done** `companions.mjs` (`importedPath`, `coversOf`, the `covered` branch in `namesakeCompanions`), pinned by `test/companions.test.mjs`.
The extension is kept when the specifier carries one and the producer is asked for both spellings, because stripping it here let `./defaults.json` answer `defaults.mjs` and credit a module with a test that only reads the table beside it; caught by a test written before the branch shipped.
A specifier climbing above the root, and a bare package name, resolve to nothing rather than to a file that happens to share the name.
A trailing slash is a directory and resolves to nothing too, or `../src/foo/` would answer the unrelated `src/foo.js` beside it.
A loader suffix is cut, since `./worker.ts?worker` names the file before the question mark.
The four compiled JavaScript extensions are also matched against the TypeScript file they are written for, because NodeNext requires `../src/parser.js` for `src/parser.ts` and refusing it missed the dominant modern spelling; no other extension is stripped, which is what keeps the `.json` table from answering for the module.
The resolution is textual and never touches the filesystem, so a directory import through its own `index` is not followed and reads as no evidence, which is the conservative half of the trade.
`siblings.mjs` resolves a specifier against the corpus and is deliberately not called: it needs the whole file set, and a caller with none would answer no rather than fail, which is how an overview and an area file come to disagree; it also resolves a bare specifier through a tail index, which here would let a dependency name a file sharing its tail.
What `facets.mjs` records is what is read: a static ESM `import` and a top-level `require("...")` bound to a variable, whatever it is declared with, so a dynamic `import()` names nothing, and a type-only import counts the same as a value one.
A specifier written for a compiled file names the TypeScript spellings it is emitted from and no others, so one `./foo.js` cannot answer `foo.json` or `foo.css` beside it
