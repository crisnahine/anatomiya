# B22

Section: B. Engine

## Decision

The parse worker's body is an in-process module the fork shell hosts

## Why

B14, B15, B19 and B20 are all measured incidents inside the worker, and nothing tested it: the body was reachable only through a fork, so every regression was caught end to end or not at all.
The shell keeps the read, the IPC reply and the BigInt fallback, which charges a tree too deep to serialise as crashed, never as a file that would not parse; tests and the pool cross the same seam

## Status

**done** `parse-file.mjs` (`parseFile`), `parse-worker.mjs`, `test/parse-file.test.mjs`.
The stripper is a defined-only override on the body, the same shape the Ruby guards take, because simulating an absent optional dependency is otherwise impossible in-process
