# C28

Section: C. The counted-claim model

## Decision

Four predicates were measured and deliberately left as they are, with what was measured written into the row rather than into a comment

## Why

`optional_chaining` recognises an optional by the receiver's name, and that is the only signal this tier has: a measured 2,485-file repository writes `?.`
2,627 times across 672 files while the row sees 538 sites in 202 of them and calls 21 conforming.
It is not narrow, it measures a different population, and no widening of the six names closes it; answering it properly needs the checker, which knows whether a receiver's type includes null.
`record_lookup` counting `find_by!` as a violation is correct and the sentence was wrong: the axis is what a miss does, and `find_by!` is `where(...).take!` in ActiveRecord's own source, so counting it as conforming would put it in the numerator of both sides of a two-sided row at once.
`absent_is_null` still counts a `: void` function although `return null` there is TS2322, because the annotation is exactly what the Flow retry blanks and reading it would make the row answer differently on a stripped tree than on the same file unstripped, so a stripped base beside an unstripped head would cancel real findings; one measured site is not worth that.
`hook_call_style`'s counter is kept, and it is the distinction the whole exercise produced: a counter whose other side does not compile is a defect, and one that merely pushes against the ecosystem default is a house style, where the escape is one import line and the finding names the sentence
