# A122

Section: A. Delivery

## Decision

The end-of-turn reuse check (A91) reads view templates as well as source: ERB (`.erb`) and EJS (`.ejs`), Razor (`.cshtml`, `.razor`), HAML (`.haml`), Slim (`.slim`), Jinja (`.jinja`, `.jinja2`, `.j2`), Twig (`.twig`) and Nunjucks (`.njk`), and Go templates (`.tmpl`, `.gotmpl`, `.gohtml`), and the markup of a Vue or Svelte component. A hunk asks where a line holds template code, and one that adds markup alone asks nothing

## Why

A view is where a helper's logic is copied most often, and no scan reads one, so a turn that wrote `<% if URI(link).host != request.host %>` into a Rails view was never asked about, where the same comparison in a helper was asked and found `is_external?` in 20 of 20 whitehall sessions.
ERB's code is the text between `<%` and `%>`; `<%#` opens a comment and `<%%` is a literal `<%`, both as Ruby's ERB reads them, and EJS writes the same tags. A configuration file run through ERB, `config/database.yml.erb`, is no view, and no helper answers one.
Razor's code follows an `@` that stands after a character that cannot end a word, so an e-mail address is text and `@@` a literal `@`, and a block opened by `@{`, `@code {` or `@functions {` is code through the brace that closes it; `@*` opens a comment.
A directive that names a type, a namespace or a route, `@model`, `@using`, `@page` and the like, runs nothing and asks nothing; a statement whose body is a block, `@if`, `@foreach`, `@switch` and the rest, holds C# on every line of it that is no markup, through the brace that closes it and an `else` after it, and a brace inside a C# string opens and closes nothing.
HAML and Slim ask on a line of Ruby (`-`), an output line (`=`, and HAML's `!=` and `&=`), a tag whose content or attribute is Ruby (a HAML `{ }` hash, an unquoted value in `( )`, Slim's `[ ]` or a bare Slim attribute, and Slim's `p=total` with no space), an interpolation (`#{}`), every line a Ruby filter holds (HAML's `:ruby`, Slim's `ruby:`), and the line after one of Ruby that ends in a comma, which carries it on; a comment asks nothing. A Slim tag's attributes end at the first word that is none, so `a=b` in its text is text.
Markup and `@:` text inside a Razor block open and close no braces, and a Jinja `{% raw %}` block is text. Twig and Nunjucks write Jinja's tags.
A Jinja expression or statement and a Go template action ask where they compute: a call, a filter, an operator; a name read as it is, `{{ user.name }}` or `{{ .Name }}`, asks nothing. One spread over lines asks on every line it spans, and one never closed asks to the end of the file.
A component's markup asks only where an expression computes with a literal, arithmetic on a number, a method called with a number (`toFixed(2)`) or a string built with `+`, since a binding, a call with names alone, a comparison and `n++` are written on most lines of a template, and the component's own logic is in its script, which is read whole.
An `.html` file is not read: it is Angular's, Vue's, Django's or plain markup, and no one rule reads all of them.
A line longer than the rules read by pattern (`LINE_READ`, 400 characters) asks unread, as under the line rules (A91): measured on a line of 60,000 `{{`, a pattern over it took 2 s, and the rules run on every line of a changed view inside the stop's budget. ERB's rule reads a character at a time and costs no more on a long line, so it reads one whole.
Every rule shares the stop's one parse deadline (`REUSE_PARSE_MS`) and reads the clock once in 64 lines or tags; a file it did not read in time asks on every line that is not blank. Slim's attributes are read by a sticky pattern a word at a time, since one pattern over a 1 MB file of `a----=` lines took 2.07 s.
What this gives up: a `{{` or `}}` inside a string in a Jinja tag or a Go action ends or opens it where the template engine would not.
A template is put through the corpus's file checks as a source file is (`corpusDrop`'s `readAlso`): a denied path, an excluded directory, a link and a generated file are passed over
