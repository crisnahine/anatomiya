# B47

Section: B. Engine

## Decision

The walk carries what a row asks of the nodes above it: the innermost function and class, and on the first `ctx.within` call a count of the node types it is inside. No row scans `ctx.ancestors` per node

## Why

Measured: a row asking every ancestor at every Identifier made a 30,000-operand chain take 7.1 s against a parse of milliseconds, and `last(stack, isClass)` made every row quadratic on nested functions.
Once the raw-transfer overflow was fixed such chains parsed, and past about 15,000 operands they timed out twice under B3 and were charged as crashed.
Counting on every node from the start cost about 25% more CPU on ordinary files, so the count starts only when a walk first asks

## Status

**done** `walk.mjs` (`within`), `dimensions-base.mjs`, `dimensions-extra.mjs`, `dimensions-naming.mjs`.
When it landed, records on 23,139 corpus files matched the old walk exactly.
The JSX and Ruby scans stay: none runs on every node.
A row that needs a function's own nodes walks them with `ownNodes`, which steps over every nested declaration, and `swallowed_error` resolves each name in the one walk, so no row walks a subtree again per node (B71)
