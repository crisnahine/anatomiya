# E8

Section: E. Baseline and drift

## Decision

A pinned file this tool cannot read closes the area, unless it cannot be read today either, which makes it a blind spot rather than something the pin lost

## Why

Any unread pinned file suppressed the whole area, and a permanent blind spot is not a population that moved.
Measured across 35 repositories: 13 lose slots to it, and react is written in Flow, which oxc does not take, so 287 of its files never parse at the pin or today and 507 of its 986 slots were closed for it.
The current pass already leaves such a file out of its counts, so the two passes disagreed about what an unreadable file means.
Closing it takes react from 36 stated claims to 65, webpack 80 to 92, next.js 162 to 172, and population-change to zero on all three

## Status

**done** `baseline.mjs` (`countAtPin`).
The guard stays for the case it was written for: a file that has become readable since the pin still closes the area, because the baseline is then missing sites today can see.
A file readable at the pin needs no exception at all, since the pinned population is what the gates read and it was counted in full.
The obvious objection is laundering, and all three routes were tried on a repository pinned at 54 of 84: breaking the violating file at HEAD leaves the ratio at 0.64 and the gate on `ratio`, because the baseline reads the blob at the pinned commit where it still parses (E2); deleting it reads 1.00 today and is closed by `population-change` (E1); and a file unreadable at both revisions was never counted at either, so it has no sites to hide
