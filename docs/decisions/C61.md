# C61

Section: C. The counted-claim model

## Decision

`spec_type_declared` asks of a `_spec.rb` file's outermost `describe` whether its options name `type:`, and states either side: `specs declare their type: metadata` or `specs leave their type to the directory they sit in`

## Why

A reviewer on a Rails API in the corpus asked a service spec for `type: :service`, and the repository holds it: 1,122 of its 1,359 spec files name a type.
Both sides are a choice, since rspec-rails infers a type from the directory only where a repository turns `infer_spec_type_from_file_location!` on: mastodon types 5 of 1,088 spec files, errbit 83 of 101, forem 593 of 1,260.
One site per describe that no other describe encloses, which is one per spec file in the usual shape, because a nested `describe` inherits its parent's metadata.
Over the corpus it opens 744 slots, and the counter states in 284 areas (discourse 109, canvas-lms 60, mastodon 36, openfoodnetwork 29, consul 23 and four more) and the claim in 2, a measured Rails API's service specs among them.
`RSpecRails/InferredSpecType` flags a redundant `type:`, but rubocop-rspec_rails 2.32 ships it pending, so only a repository that turns it on enforces the counter side: consul does

## Status

**done** `dimensions-ruby.mjs` (`spec_type_declared`, `isDescribe`, `isSharedGroup`, so a `describe` inside a shared group is no site, and `options` from `ruby-walk.mjs`, so options it cannot read drop the site), pinned by `test/ruby.test.mjs` and `test/applicability.test.mjs`, and listed among the rows that may state their inverse in `test/fixtures/counter-pins.mjs`.
Asked only where the Rails profile is detected
