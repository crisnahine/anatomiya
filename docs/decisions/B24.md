# B24

Section: B. Engine

## Decision

One supervisor carries the spawn, the bounded stderr, the two clocks and the kill for every child this tool parses with: the warm parse pool, the Ruby stream and the type checker. The eight subprocesses that are not a parse stay outside it, each bounded by its own caller: the pool's `ps` poll (macOS and the BSDs only, by absolute path `/bin/ps`; Linux reads `/proc/<pid>/status` and runs none), the readiness probe's interpreter, the prism gem listing both the probe and the Ruby parser ask first (`ruby.mjs` `listPrism`), the load check that asks a listed prism's paths for `Prism::VERSION` before the parser is handed them (`ruby.mjs` `loadedVersion`, B44), setup's npm and the fresh readiness probe setup runs after it (`readiness.mjs` `readinessAfresh`), the refresh worker the `refresh` hook starts detached with a 20 minute clock (`refresh.mjs` `startWorker`, A95), and every git read

## Why

Three bridges run one, the warm parse pool, the Ruby stream and the type checker, and each wrote the battery with different numbers and different gaps: three stderr accumulators at 2048, 8192 and 4096 bytes, every one able to overshoot by a chunk; three copies of `cwd: tmpdir()`; two of the pinned empty `execArgv`, whose absence once killed every parse worker before it answered and had the scan blame the parser; and one re-armed timeout where the other two carried an idle window and a wall clock.
A fourth engine would have written it a fourth time

## Status

**done** `child.mjs` (`guardedChild`, `absentInterpreter`, `retryOnce`), `pool.mjs`, `ruby.mjs`, `semantic.mjs`, pinned by `test/modules.test.mjs`, which fails a bridge that guards a child of its own again.
The numbers stay with the caller that measured them and only the shape is shared; the cap is exact now rather than one chunk past.
Two clocks rather than one, because silence is not the only way a child fails to end: `wallMs` is armed at construction and nothing re-arms it, while `idleMs` runs only from the first `touch()`, and `touch(ms)` takes a window because the checker's first silence is its whole program build and every silence after it is a stall.
`settle()` is terminal, so a touch after the run cannot leave a timer holding the event loop open.
Parent-only, and it is the far side of the parse worker's walk: it imports `node:child_process`, so nothing the worker reaches may import it (F18), which is why `parse-file.mjs` still classifies its own absent module rather than sharing that one
