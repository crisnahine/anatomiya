# A126

Section: A. Delivery

## Decision

Where the checkout the session sits in has a code index `find` can read, the reuse check's reason (A124) names the definitions the index already lists nearest each name the change's added lines declare: the best three for a name and five in all, in the order the names were added, leaving out the rows of the changed files themselves. The names are read off the lines the line rule or the tree left asking, by one pattern per language, a name every class writes (`initialize`, `constructor`, `render`, `call`) is not searched, the search stops at 500 ms, and an index of more than 200,000 definitions is not searched. Where it names none, or the reason names no `find`, the reason is A124's word for word

## Why

The index reached the session through one sentence that told the subagent to make up two or three words and run `find`; the map, the area files and the notice never name it.
The hook already reads each added line to tell which define something callable, and the name on such a line is the word a search for the helper is asked with.
On mastodon at the scenario commit, an added `local_url_for?` brings `TagManager#local_url?` first, the helper the mastodon reuse task is about.
Measured in the hook's own process on the two largest indexes of the measuring corpus, bitwarden (645 KB, 5,977 files) and django (634 KB, 39,257 definitions), reading the index took 14 to 21 ms and searching eight names 161 to 238 ms, three runs each at a load average of 4 to 5; the 500 ms stop bounds a change whose names each find nothing.
A name is a word to search with, never a finding: a pattern that misreads a line asks a worse search, and the subagent still judges what it is handed.
The rows of a changed file are the last scan's copy of what the turn rewrote, so they would name the change itself.
A name every class writes found every other class's copy: a change adding `Report#initialize` beside `format_report_line` filled three of the five places with other classes' constructors, so those names are left out and the reason lists only the names that found something.
A call that opens a callback, `it("works", function () {`, ends its line as a method head does, so a parenthesis holding another, or a statement ending in `;`, names nothing.
