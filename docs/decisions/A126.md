# A126

Section: A. Delivery

## Decision

Where the checkout the session sits in has a code index `find` can read and that holds a definition, the reuse check's reason (A124) names the definitions the index already lists nearest each name the change's added lines declare: the best three for a name and five in all, in the order the names were added, leaving out the rows of the changed files themselves, each quoted as repository text and said to be as of the last scan. The names are read off the lines the line rule or the tree left asking, by one pattern per language anchored at the start of a declaration, and a name every class writes (`initialize`, `constructor`, `render`, `call`) is not searched. A search the stop's 500 ms overtakes gives up, and an index file past 2 MiB is judged by its head and not searched. Where it names none, or the reason names no `find`, the reason is A124's word for word

## Why

The index reached the session through one sentence that told the subagent to make up two or three words and run `find`; the map, the area files and the notice never name it.
The hook already reads each added line to tell which define something callable, and the name on such a line is the word a search for the helper is asked with.
On mastodon at the scenario commit, an added `local_url_for?` brings `TagManager#local_url?` first, the helper the mastodon reuse task is about.
Claude Code 2.1.312 hands a Stop hook's reason to the model whole, 12,909 characters arrived byte for byte, and on a measured account twice, as a meta user message and as a system turn; a hook past its declared 15 s is ended by SIGTERM, its output dropped and the stop let through with nothing said to anyone (`docs/research/what-a-stop-hook-reason-reaches.md`). So the list is short, and the time it may take is bounded inside the search: a check that runs out its clock asks nothing at all.
Measured in the hook's own process on the two largest indexes of the measuring corpus, bitwarden (645 KB, 5,977 files) and django (634 KB, 39,257 definitions), reading the index took 14 to 21 ms and searching eight names 161 to 238 ms, three runs each at a load average of 4 to 5. On a synthetic index of 200,000 definitions one search took 900 to 2,100 ms, and reading one of 1,000,000 took 309 ms and 618 MB, so a search checks its deadline as it goes and a file past 2 MiB, about 120,000 definitions at django's rate, is read only for its schema and count.
A name is a word to search with, never a finding: a pattern that misreads a line asks a worse search, and the subagent still judges what it is handed.
The rows of a changed file are the last scan's copy of what the turn rewrote, so they would name the change itself.
A name every class writes found every other class's copy: a change adding `Report#initialize` beside `format_report_line` filled three of the five places with other classes' constructors, so those names are left out and the reason lists only the names that found something.
A call that opens a callback, `it("works", function () {`, ends its line as a method head does, and a declaration's word inside a string or a regular expression is no declaration, so the patterns are anchored, a parenthesis holding another names nothing and a statement ending in `;` names nothing outside C#'s one-expression members.
A doc sentence is the repository's text and now reaches the session that reads the reason, so each candidate is held in a quote it cannot close and a path no shell reads plainly is encoded.
