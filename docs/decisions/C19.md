# C19

Section: C. The counted-claim model

## Decision

The exported-name naming row is judged per declaration kind: `exported_symbol_case` (a function, or a variable not bound to a class expression), `exported_class_case` (a class, or a variable bound to one), and `exported_type_case` (an interface, a type alias, or an enum). Each learns and states its own casing

## Why

Verified by running the real CLI, since reading the code alone does not show which population a claim ends up speaking for.
On typeorm, in an area whose export population is 100% classes, a planted `export function isValidPost(post: Post): boolean`, camelCase and correct by every convention and matching that repository's own recorded precedent `filterByCteCapabilities`, was flagged `FIX ".../entity/Post.ts":19 exported names are PascalCase`; a planted `export function IsValidPost(...)`, wrong by every convention, passed with 0 findings.
The only defect measured across 35 repositories that made `check` wrong in both directions on one directory.
Confirmed from the other side on mastodon, where the conflated row stated "exported names are camelCase, 509 of 518" and listed idiomatic PascalCase type exports as violations though every runtime export really was camelCase; the tool already got this right in that repository's `api_types`, where types dominate, so the defect was the shared bucket rather than the casing rule.
`model-defaults.json`'s own calibration recorded the same conflation and could not resolve it: 12 samples, `classCounts: {PascalCase: 22, camelCase: 10}`, no majority either side of even

## Status

**done** `dimensions-naming.mjs` (`exportedSites`, `exportedPopulation`), `model-defaults.json`, pinned by `test/naming.test.mjs`, `test/applicability.test.mjs` and `test/fixtures/counter-pins.mjs`.
A class keeps a row of its own rather than joining the type row, though both are conventionally PascalCase: it is the one PascalCase declaration that survives a Flow retry with its name intact, so folding it in would make `exported_type_case`'s `blindWhenStripped` false for the sites it borrowed.
`exported_symbol_case` keeps its key and its claim text, narrowed to the population that was always camelCase, so the picker and the A/B plumbing that read that key by name are untouched.
A default export is read when it names what it declares, since one class per file exported that way is the ordinary shape for a component: skipping the statement whole left a repository of five default-exported PascalCase classes stating, through its one named-export outlier, the opposite of what 83% of its classes do.
An anonymous one binds no name and is still no site.
A specifier (`export { foo as bar }`) is not resolved to the declaration it renames and answers none of the three: a real narrowing from the row it replaces, not a gap papered over.
The three defaults are reset to an unmeasured seed rather than carrying the old counts forward, because a default measured over a conflated population is evidence for neither half; re-measuring needs `scripts/measure-defaults.mjs`, which spends model calls and is run by hand
