# A97

Section: A. Delivery

## Decision

`dependency review` is a required status check on `main`; `audit the installed tree` runs on every pull request but stays advisory

## Why

Dependency review compares against the base, so it fails only on what the pull request adds.
The audit reads the whole installed tree, so a new upstream advisory against a dependency already here would fail every pull request after it, including ones that touch no dependency, until someone bumps or waives it.
The audit still runs on every push to `main` and weekly (`17 7 * * 2`), where a red run is seen without blocking unrelated work.
`openssf scorecard` skips pull requests and has no context to require

## Status

**done** `.github/workflows/supply-chain.yml` (job names are the contexts), `docs/releasing.md` ("When a job is added").
The requirement itself is a branch-protection setting, not a file: renaming the `dependency review` job silently drops the gate until the new context is added
