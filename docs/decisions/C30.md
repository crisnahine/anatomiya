# C30

Section: C. The counted-claim model

## Decision

A superclass written bare inside a namespace is the constant it resolves to, and the two spellings count as one base

## Why

Ruby resolves a bare constant against the enclosing nesting before the top level, so `module Api::V1; class QboController < BaseController` names `Api::V1::BaseController`.
Compared as written, empire-flippers/api's four relative spellings counted as a second base and took a 59-of-64 convention to 55 of 64: the strongest fact in its largest controller area, inverted, telling an agent to write `< ApplicationController` in a directory where 59 of 64 do not.
Resolution is only ever from the site's own namespace prefixes, longest first, which is what `Module.nesting` offers, and it runs in both directions because either side may be the bare one: a repository whose plurality spelling is relative learns the bare name and its scoped sites have to count too.
Narrower than the suffix match `isLearnedItself` refused and does not touch it: that one accepted any name merely ending in the learned one, with no nesting to justify it, and it asks about the site's own name rather than about the base it chose.
A scoped name has already said which class it means, so `Api::V1::ChromeExtension::BaseController` stays a different base.
The count moves; the gate does not, and 59 of 64 still reads "no convention" because the Wilson lower bound is 0.83 against the 0.90 bar.
Fixing a miscount is not the same as restating a claim, and widening the gate is a separate decision with its own evidence
