# H61

Section: H. Layout

## Decision

The reuse line (H9, H58) and the code index (H60) count a definition's importers by one rule, `creditOf`: a name the index credits to a definition of the file counts every file that definition is credited with, a call written `Class.method` credits the class as well as the method, and a name no definition answers, a default import or a JavaScript or Ruby constant, counts the files that import it, as it did. The line keeps its own filter, importers outside the area, its namespace skip and its top five

## Why

The two counted one helper two ways: the line by the names a file imports, the index also by `Class.method` calls, module and package qualified calls and the class around a method, so one helper could show one number in its area file and another in `find`.
Over 979 areas of 12 repositories, the new rule changed 94 lines: 88 rows gained importers and none lost any, 94 rows joined a line and 43 left one's top five as others rose (`OrganizationSale.From` behind `OrganizationSale` on bitwarden), nearly all a class or module whose methods the rest of the repository calls, `ApiHelpers (9)` beside `ApiHelpers.GetDateRange (4)` on bitwarden, `TagManager (30)` and `FeedManager (35)` on mastodon's `app/lib`.
The lines of eslint, excalidraw, gitea, atuin, ctfd and kotlinconf did not change, since their names already were the definitions' own.
The line keeps the names it printed; the index keeps definitions, so a default import and a JavaScript or Ruby constant, which the index does not list, are still counted by name.
A bare name two definitions of one file share, a method `find` on two classes there, counts the files reaching either, where `find` shows each definition's own.
