# C46

Section: C. The counted-claim model

## Decision

A name a declaration cannot change is not a naming site: an interface at the top level of a declaration file with no import or export, a binding annotated as a React component type, and a module-level function this file calls with new or reads a prototype off

## Why

A script-mode .d.ts merges its top-level interfaces globally exactly as declare global does, so `interface_prefix` asked for `interface Window` to become IWindow, which stops the merge.
On the corpus copy of the client this was the 4 misses in src/types (76 of 80, true figure 76 of 76).
A React.FC binding that returns null hands out no JSX and is rendered only from another file, so the naming rows asked for a lowercase component name, a host tag: formik-persist.tsx plus 8 more client components.
A pre-ES6 constructor asked for camelCase where the class it stands for is never a site: chartTrendline.js.
Declaration files only, because moduleDetection can make any other file a module whatever it holds

## Status

**done** `dimensions-naming.mjs` (`interface_prefix`, `isModuleSyntax`, `noteConstructed`, `function_naming_case`, `exported_symbol_case`, `fillClass`, which also makes a prefix claim read 'an I prefix'), `dimensions-jsx.mjs` (`typedAsComponent`), pinned by `test/naming.test.mjs`.
A PascalCase function that only returns null is not taken for a component: both measured cases are typed React.FC, and a bare null-only function is weak evidence
