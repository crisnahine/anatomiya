# B63

Section: B. Engine

## Decision

A tree-sitter tree whose root reports an error is unread: the record is `ok: false` with a count of its ERROR and MISSING nodes, never under one, and the file gives no site and no facet. The gate is one-sided: a file the grammar reads clean is counted, whatever its language's own parser would say of it

## Why

An unread file prints as a file this tool's grammar could not read, apart from a file whose own parser rejected its syntax.
A recovered tree holds less than was written, and counting it moves the denominator, which is B15's reason.
What differs is the meaning: oxc and prism are their languages' parsers, and a grammar is not.
Unread on three repositories per language, as files and as the largest share of one repository's lines: Python 1 of 4,173 files and 0.00% (a django fixture broken on purpose); PHP 2 of 3,783 and 0.02% (one fixture, one nowdoc `php -l` reads); Go 0 of 1,372; Java 7 of 2,685 and 0.97%, all accepted by javac 25 (junit5: a type annotation on a varargs, `import module`; commons-lang: a NUL character in a string); C# 2 of 3,414 and 4.35% after B64's retries (a collection expression, in serilog and in jellyfin); Rust 0 of 1,126, and over both corpora 23 of 2,357 accepted by rustc 1.99.0 and unread, 22 in next.js (9.71% of its Rust lines) and 1 in vscode: 12 for a `box` pattern, which only nightly takes, 9 for an attribute on a field of a struct pattern, 3 for `raw` as a name after `&` and 2 for an `unsafe extern` block, with 3 files needing two (`docs/measurements/2026-10-11-rust-unread.md`); Kotlin 94 of 3,933 and 7.88% (B59).
A Kotlin body whose last member shares a line with `}` reports an error and shows no ERROR or MISSING node, which is why the count has a floor of one.
Given up: a real syntax error in one of the seven reads as "may be fine", and an unread file's sites leave every denominator.
The gate is one-sided: a tree with an ERROR or MISSING node is unread, and text the language itself rejects and the grammar reads clean is counted.
Run against `python3` 3.9.6, `php -l` 8.1.34 and `gofmt -e` from Go 1.26.5 on 61 hand-written inputs: those parsers reject 53, and the grammars read 32 of the 53 with no error, 15 of 20 for Python, 11 of 18 for PHP and 6 of 15 for Go.
One of the 32 is a `match` statement Python 3.9 is too old for, so 31 stand.
Among them are `print "x"`, `exec "x"` and `except E, e`, so Python 2 source is read as Python and its functions are counted; a PHP duplicate parameter and a `break` outside a loop; and a Go file with no `package` clause.
`fun f(a: Int): Int { return a }` saved as UTF-16 and read as UTF-8 comes back from the Kotlin grammar with no error and no site, where each of the others rejects the same bytes.
A lone `\r` is no line break to a grammar: the Python and Go grammars reject a file whose only line break is one.
For Java, C#, Rust and Kotlin each language's own parser was run in a container over the three repositories (javac 25, Roslyn 5.9.0, rustc 1.99.0 and the Kotlin 2.4.21 compiler's parser; `docs/measurements/2026-10-08-reference-parsers.md`): it accepts all 103 unread files and rejects none of the 11,055 the grammars read, so in those twelve repositories no unread file of the four is a real syntax error and the one-sided gate counted nothing its language refuses.
At Java level 21 javac rejects 4 files of junit5 the grammar reads, for an unnamed variable `_`.
Written inputs for those four, one construct each, run against the same parsers (`docs/measurements/2026-10-11-invalid-inputs.md`): of 95 the parsers reject, the grammars read 37 with no error, 16 of 24 for Java, 8 of 25 for C#, 9 of 21 for Rust and 4 of 25 for Kotlin, so 69 of 148 over the seven languages; among them `goto x;` and `if (true) int x = 1;` in Java, `#error` and a `using` after a namespace in C#, `a < b < c` and `let async = 1;` in Rust, and a call at the top level of a `.kt` file.
Over eight more corpus repositories, 3,384 files of the four, the parsers reject 3 and the grammars read 2 of them, both in vscode and both a statement at the top level of a file: a colouriser fixture opening with `let`, and a test snippet of `public` methods with no class.
Both give no site.
No guard and no "Not covered" line follow: the tool cannot know which read file its language would reject, so the line would be fixed text on every map holding one of the seven languages, and the one class real repositories hold moves 2 files of 3,384 that give no row a site.
What that gives up: those two files count toward their directories' file totals
