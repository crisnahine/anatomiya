# H16

Section: H. Layout

## Decision

`module_include` counts the body that declares nothing. A class body is a site when it includes something, and also when it includes nothing, names no superclass and is not nested inside another class. A module including nothing, a subclass, and a class inside a class are not sites

## Why

The row already said "the body is one site" in its own predicate and counted only the bodies that had an include, so the omitted include was invisible: a planted worker with `include Comparable` was caught and one with no include at all passed clean on the same run (#46).
The strongest reading of a stated claim, every class here carries this include, was the one reading the check could not enforce, and the omission is the violation an agent actually commits.
The three exclusions are each a body with somewhere else to have got the mixin, and each was a wrong finding on the corpus before it was excluded: counting `module Users` around a worker read forem `app/workers` at 88 of 176 and suppressed a claim true of every worker in it; the other nine of that 97 were `< BustCacheBaseWorker`, which carries the mixin for them, the mirror of the rule `class_base` states; and discourse `Chat::Channel::Policy::MessageCreation` holds a bare `class Strategy`, a helper rather than a peer of the services the claim is about.
Measured over twelve Ruby repositories, eleven do not move at all and a measured Rails API is identical row for row, including the `app/workers/workers/orders` 38 of 38 the report was filed against.
The one claim that moves is discourse `plugins/chat/app/services/chat`, from 46 of 46 to 46 of 47: `Chat::MessageDestroyer` is a real class there that does not include `Service::Base`, and one counterexample takes the Wilson bound to 0.889, under the 0.90 bar.
That is the evidence gate reading a true population rather than a filtered one
