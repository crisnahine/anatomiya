# H18

Section: H. Layout

## Decision

An empty tail falls through to the same `mirrors` test a nested tail already uses, rather than waiving the tail match and taking the first same-stem file in path-sorted order from anywhere in the repository. Both sides at the top of the tree is the one further shape it accepts

## Why

The `whole` check read `tail === "" || t.dir === tail || t.dir.endsWith(...)`, and the first disjunct made every file sitting directly in the root being evaluated match unconditionally, in any directory, in any language. openproject built an oracle from the same mirrors rule this module already applies correctly to nested files and measured over its real 500 areas: 3,849 producers with an empty tail, 1,536 matched, 868 correct, **668 false, 43.5% of all matches, across 167 of 500 areas**; one engine, backlogs, holds the repository's only real `engine_spec.rb`, and 24 siblings were each credited through it for sharing the stem. decidim: 58 of 156 Ruby areas inflated, 134 files credited with no same-engine candidate, `decidim-elections/lib/decidim/elections` stating 6 of 8 for a gem with no `spec/lib` at all. fastlane: file after file credited across gem boundaries. chef: 488 root-level files matched this way, all 5 hand-verified wrong, one shadowing the genuinely on-point spec because the loop broke on the first alphabetical hit. puppet: a decoy planted at `spec/unit/totally_unrelated/network_spec.rb`, describing nothing to do with `Puppet::Network`, moved both counts by exactly one and moved them back on revert. plots2 credits a 17-line WebSocket consumer with a server-side Ruby spec, so the defect was language-agnostic as well as namespace-agnostic. huginn generated a self-contradiction from one run, the overview reading 0 of 18 with a non-empty tail while the area file read 2 of 6 over the same files

## Status

**done** `companions.mjs` (`namesakeCompanions`), pinned by `test/companions.test.mjs`.
The nested path is untouched by construction, the same branch as before: openproject measured zero cross-engine leakage among its 2,623 nested producers.
The flat-repository half was found by scanning one fixed tree with both builds and diffing the maps rather than by a test: mirroring the root's own directory has nothing to mirror with when that directory is nobody's tree word, and this repository's own overview went from a true `8 of 15` to `0 of 15`.
Both sides at the top of the tree is the narrowest rule that keeps it: what the two share is the top and not the shape below it, so a test root that files by type (`test/unit`, `test/integration`, whose own word is nobody's tree name) answers too, and it does not reach a package, where `apps/www` answered by a repository-wide `test/`, or a top-level script answered by one package's own tests, is the shape a monorepo keeps beside the package instead.
That branch asks one question the nested path never had to: the directories part first there and here they do not, so a JS script is not answered by a Ruby spec of the same stem.
What it still does not close is a source root whose own name is a tree word, where `lib` and a `test/app` both strip to nothing and mirror each other: pre-existing, unchanged from before this row, and the accepted cost of the width the typed test root needs.
With it the two maps are byte-identical
