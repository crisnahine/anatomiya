# G18

Section: G. Scope

## Decision

What a user gets is measured as the plugin on against the plugin off, on tasks whose checks a scenario file fixes before any trial runs: each arm a session with the tools a coding session has, each alone at the same leaf name, scored on what git shows it changed, and reported with each arm's Wilson interval, Fisher's exact test and what each trial cost

## Why

G5's harness asks whether the map moves one stated claim, with the plugin loaded in both arms and the tools cut to Read, Write, Glob and Grep so no shell can reach a rule file.
A reader of the README asks something wider: what a session gets from installing the plugin, with its map, its echo, its notice before a write and its reuse check, in a session that has Bash and Edit.
With the plugin off, arm B holds no map to read, so the reason for cutting the tools does not apply.
What does apply is that a shell shows the agent where it is: each arm sat at `with-map` or `no-map` beside the other, so each now sits alone in its own temporary directory at the repository's own name.
A shared clone's alternates file and its `origin` both named the checkout that holds the map, and a clone's reflog opens with "clone: from" that checkout, so each arm is now a hard-linked local clone with its remote and its reflog removed.
The 2026-10-25 runs came in two batches, the first on shared clones and the second on local clones whose reflog still named that checkout, and none of their 320 sessions without the plugin mentions the map in its answer; none of the 280 outside rubocop, whose `.gitignore` covers `.claude/`, wrote a file there.
Both arms still sit in the system's temporary directory, where a shell that lists its parent's siblings could find arm A; only a container closes that.
A claim the map states as a count is scored by the map's own predicate, as G5 does.
What no dimension counts, such as a companion file a change ships with or an existing function the new code calls, is scored by a pattern over the files the trial wrote.
Both kinds are fixed in `scripts/ab/scenarios/<name>.json` with the commit they were written against, and the runner refuses a clone at any other commit.
Each result records the scenario file's sha256, so a reader can see the file it was scored by is the one in the tree.
It also records the `claude --version` and the anatomiya version and commit its trials ran on, read before the first trial and marked where the plugin or the harness has uncommitted changes, since a rerun on another build measures something else.
Trials run with `DISABLE_AUTOUPDATER=1`, since a build that updates itself mid-run is two builds, and `--from-raw` refuses records of two builds.
The 2026-10-25 runs predate that field, and their summary page names Claude Code 2.1.310.
The record cannot show the file existed before the trials, so a run should commit its scenario first.
The scenario file is not touched once a trial has run, so a check thought of later is reported apart as exploratory.
A row whose predicate counts only files that already reach a translation layer gives a hardcoded string in a new file no site at all, so a scenario whose failure is that string scores it with a pattern; scored by the row, the arm that fails would read as not judged.
A trial counts toward a check only where it did the task and the check had something to judge, so an arm cannot pass `unchanged` by writing nothing.
The first real trial on a Rails clone counted 4,362 written files in the arm whose agent booted the app, 4,360 of them bootsnap cache and a log that git ignores, so a trial's work is what git would show it changed, which takes in the operator's global excludes too, and a `node_modules` directory is never walked.
Four Haiku rubocop trials regenerated eight documentation pages each without changing a byte, and all 32 were listed as written, so a tracked file whose bytes match the trial's starting commit is left out; no check read those pages.
That comparison is against the starting commit, so a trial that commits its work still shows it, and it is made only where the arm is the top of its own repository, since from a subdirectory `ls-tree` and `diff` name paths from different roots.
A file a trial deleted is not seen at all.
A dangling link in a mastodon clone made the snapshot throw before the first trial, so a link is not followed.
A failure reason was Node's "Command failed:" message, which carries the whole argv, the prompt and this machine's plugin path among it, so a reason is now the exit code and the CLI's own subtype or the first line of stderr.
The CLI's `duration_ms` and `num_turns` cover only the stretch after the last background notification.
Measured on 2.1.310, a session that waited 25 s on a background task reported 1,557 ms and one turn against 32.7 s on the harness's clock, while its cost and tokens covered the whole session, so the harness times each trial itself and records no turn count.
Each record keeps the first 2,000 characters of a trial's answer, so a claim read from the answers can be checked by someone else.
A rubocop session credited its changelog entry to the account name of the machine it ran on, so a kept answer and a failure reason have the operator's home directory replaced by `~` and the machine's account name after an `@` by `@<user>`, before the answer is cut.
A GitHub handle an answer quotes is left as it is: four rubocop answers name the maintainer's, which is public.
The account is matched only after an `@`, since an account called `test` would otherwise rewrite every "test" in an answer.
Four rubocop sessions, two on each model, say they took their credit from the operator's `gh` login, so a trial runs with no GitHub token and a `GH_CONFIG_DIR` under a file, which nothing can create, so `gh` stops before it can read a login; git and ssh credentials still reach it.
A slow scenario runs as several workers on separate clones, and `--from-raw` joins their records.
It refuses a record of another commit, another engine, another scenario file or another digest of the same file, since two scenarios can share a commit.
It also refuses a record that names no scenario at all.
Records made before the digest was recorded carry none, so a page rendered from them prints the digest of the file in the tree when it was rendered.
The scenario harness's default engine is G11's, and a batch at any other model, such as `claude-opus-5-5` or `claude-haiku-5-5`, is its own batch and is never joined with another.
Sizes come from `docs/research/what-proof-of-effect-rests-on.md`: ten trials per arm tell only a gap of about 0.7 from noise, 0.3 against 0.7 needs 24 to 29 per arm and 0.5 against 0.8 needs 39 to 45, and more tasks narrow the answer faster than more repeats of one.
Cost is reported beside the effect because the one controlled study of context files found pass rates unchanged and inference cost up by over 20% on average (arXiv:2602.11988).
Each trial runs an agent with a shell on the repository under test, with the operator's environment less the model variables G11 strips, so cloud credentials still reach the model; the harness is to be run in a container or under an account that holds nothing else.
