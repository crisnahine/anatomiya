# A112

Section: A. Delivery

## Decision

A pin records the area ceiling its give-back settled on, where that rose past the plain ceiling, and a scan under the pin folds to it and gives nothing back. A pin that records none folds at the plain ceiling. A recorded ceiling that is not a count, is above the areas the pin lists, is at or below the plain ceiling, or is above twice the plain ceiling for the pin's own corpus, or a ceiling in a pin that names no corpus size, makes the pin unreadable

## Why

The give-back asks which areas count nothing, which reads file content, so at the ceiling an edit that adds or removes no file moved the partition against the pin: on a 383-file fixture three Python files rewritten to count nothing gave two places back, so an inner area left its host, and the host read `population-change` while the scan said 0 files changed since the pin.
The corpus size is pinned for the floor for the same reason.
A pin taken before the give-back reads at the plain ceiling, so updating moves no area: a v0.14.0 pin at the ceiling gave 2 population changes on the build before this row and none on this one.
The pin writes its own area list, so a bound on that list alone let a hand-edited pin lift the ceiling to any count: 80 forged entries took a 1,080-file fixture from 120 areas to 200.
Twice the plain ceiling, which `areaCeiling` clamps at 500, holds any pin to 1,000 areas
