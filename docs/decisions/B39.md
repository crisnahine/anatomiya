# B39

Section: B. Engine

## Decision

The checker's worker is a shell over `semantic-job.mjs`: `runJob` builds the program, measures resolution and answers per-file hits through a `send` it is handed, and the worker holds only `process.on("message")` and the ready line

## Why

The parse worker was already a shell over a tested body (B22); the semantic one kept its job handler, program build, per-dimension loop and `measureResolution` inline, so the function the whole degraded verdict rests on was reachable only by forking a real typescript program.
The loader is handed in too, so the not-installed path runs where typescript is absent

## Status

**done** `semantic-job.mjs` and `test/semantic-job.test.mjs`, which pins the message order, the resolution count over `any` and a typed receiver, the key filter, and the one-error-message rule; a scan with the checker of the oracle repository is byte identical across the two builds.
The file sits under the lib per-file floor and its namesake test runs wherever typescript is installed: it is the plugin's optional dependency, and the coverage job's `npm ci` installs it
