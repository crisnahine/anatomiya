# B71

Section: B. Engine

## Decision

No JavaScript row and no site name costs more than one pass over the file however deep it nests: the walk carries each declaration's named class and each node's object binding as it enters them, a row reading a function's own nodes steps over nested declarations (`ownNodes`), and `swallowed_error` resolves names and throws in the one walk

## Why

Measured per doubling at 800 to 1,600 levels with `test/growth.mjs` on the build before this row, where linear is about 2 and quadratic about 4: callbacks 3.84 through all rows (`absent_is_null` walked every function body, nested functions included, once per function), async callbacks 3.87, catches nested in catch bodies 3.44 to 3.62 (`swallowed_error` 3.98 to 4.09: `usesParam` and `hasRethrow` walked each catch body), unnamed classes nested 8.10 through all rows and 4.73 for the bare walk (`whereOf` scanned the stack), object literals with a method per level 3.96 for the bare walk (`objectBinding` climbed the ancestors), and a chain of `!` links 3.4 to 3.7 at 4,000 to 8,000 links (`optionalChain` climbed the chain once per link; the `nonNull` shape in `test/dimensions.test.mjs`, run on the build before 3cc9532a).
`optionalChain` keeps each link's answer, so a chain is climbed once.
The parser segfaults near 3,000 levels on any build, so a file can only repeat such nests side by side.
Every JavaScript row's hits matched the build before, file by file, over 73,843 corpus files and about 1.5 million sites; with `new` and `await` added to the binding's path only `where` moved, on 146 of 30,628 files.
On 3,000 ordinary vscode files all the JavaScript rows run 1 to 7% faster and the bare walk a little slower

## Status

**done** `walk.mjs` (`OWNER`, `holders`, `ownNodes`, `optionalChain`, `CHAINS`), `dimensions-base.mjs` (`readCatches`, `scopeNames`), `dimensions-extra.mjs`, `dimensions-jsx.mjs`, pinned by the growth tests in `test/walk.test.mjs` and `test/dimensions.test.mjs`.
Given up: `ownNodes` steps over classes too, so a `yield <X/>` in a class's computed key or `extends` inside a generator is not seen by `yieldsJsx` (0 differences over 73,843 files); the Ruby and tree-sitter walks were not measured for nesting.
`check` holds the same bound for a site's identity and text: `readerOf` in `introduced.mjs` collects a program's bodies once, sorted, and collapses the file's whitespace once, so a site takes its text as a slice and finds the bodies inside it by halving; 2,000 nested catches against a base went from 15.4 to 0.1 seconds per row, pinned by a growth test in `test/introduced.test.mjs`.
A site's text is cut at 4,096 UTF-16 code units of its collapsed text as the finding is built, an ellipsis past them and a surrogate pair kept whole: a site holding a whole file copied that file into every finding on it.
Every writer, JSON included, prints the 100-grapheme snippet cut from it.
What stays is the hash over each site's own text, which is the identity a pin holds
The Ruby rows have no `ownNodes` and thirteen sites walk a class or method body again (`walkRuby` on a subtree, seven of them for the ancestors it carries). Measured on 2026-10-29 with a counter in the walk, per parse worker: on mastodon the one top-level walk visits 163,000 to 173,000 nodes in 223 to 232 ms and the re-walks 90,000 to 112,000 nodes in 26 to 32 ms; on a 929-file Ruby corpus 336,000 to 346,000 nodes in 441 to 480 ms against 5,700 to 11,900 in 3 to 10 ms. About a tenth of the walk and a fiftieth of a Rails scan, so the thirteen sites stay as they are until a measurement says otherwise.
