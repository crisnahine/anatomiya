# C21

Section: C. The counted-claim model

## Decision

A predicate does not count a construct whose conforming form does not exist. Where the language decides it the exclusion is in the predicate; where the area's own learned class decides it the exclusion is in the fold, because only the fold knows the class

## Why

Eleven rows, each executed rather than reasoned about, each asking for code that does not compile or does not run.
TypeScript: an overload set has no arrow form, so `function_style` made the only available syntax the first violation in a 280-of-280 area; `const container: HTMLDivElement` with no initialiser is a SyntaxError and assigning to a const is a TypeError, so `module_state_const`'s two MUST-FIX on the ordinary React Testing Library setup asked for a file that does not compile, and measured over a 2,486-file repository 0 of its `let` bindings were initialised-and-never-reassigned while 9 of the 17 the row called violations could not be fixed as asked; an interface inside `declare global` carries the identity of the thing it augments, so `IWindow` compiles and the merge silently stops, which was 24 of that row's 40 non-conforming names; `x?` is TS1109 so a bare `x!` has no optional form, and `o?.r = 3` is TS2779 so neither does one in a write position, a `new` callee or a tagged template's tag; `a || b ?? {}` is TS5076 so a mixed chain cannot be flipped one operator at a time; a plain `.js` file cannot carry a return type at all; a JSX element name is a value read, so `import type` on a component is TS1361; and React refuses `return null` from an effect in its own words.
Ruby: `[]=` cannot take keywords at all, `EachValidator#validate` calls `validate_each` positionally, and Sidekiq reaches `perform` through a splat of a JSON array where a splatted Hash is never keywords, which was 76 of that row's 297 violations; ActiveRecord raises `Cannot add a foreign key to a polymorphic relation`; a Sidekiq job that returns instead of raising is acked as successful, never retried and never in the dead set; and Rails' `change` auto-inverts only a closed set of schema commands, so a migration the schema-only row already flags cannot answer the reversibility row, which was 88 of its 121 violations.
A spread onto a host element is the same shape from the other end: something has to reach the DOM, and a rest element is by definition the props nobody named, which was 11 of that row's 16 violations at 69% and the fastest way to teach somebody to ignore the tool.
A directive comment is the same argument about text rather than syntax: `eslint-disable`, `@ts-expect-error` and a triple-slash reference are not documentation on either side of a doc-comment claim, and obeying the finding deletes a directive and breaks the build

## Status

**done** `dimensions-base.mjs` (`module_state_const`, `optional_chaining`), `dimensions-extra.mjs` (`function_style`, `non_null_assertion`, `nullish_default`, `absent_is_null`, `type_only_import`, `doc_comment_style`), `dimensions-jsx.mjs` (`spread_on_component`), `dimensions-naming.mjs` (`interface_prefix`, `function_naming_case`; C46 adds a binding annotated as a React component type and a constructor), `dimensions-ruby.mjs` (`keyword_params`, `service_result_shape`, `zone_aware_time`), `dimensions-rails.mjs` (`migration_reversible`, `column_null_declared`, `reference_foreign_key`; the polymorphic exclusion is narrowed by C34, which reads the option Rails reads and lifts it for the list form that declares a key), `walk.mjs` (`optionalChain`, the one grammar rule both `?.` rows ask).
Two of the eleven were left alone on measurement rather than fixed, and the reasons are in C28.
One consequence is worth knowing before somebody reads the audit: excluding components narrows `function_naming_case`'s population, and its median applicability share on a components-heavy front end reads 0.375 (re-measured on the corpus client after C46) against main's 0.889.
The exclusion alone takes it to 0.125, which is under the 0.25 the audit flags at, and C25's narrowing lifts it back over the line by cutting the denominator with the numerator, so the shipped build is not flagged and the audit's own footer does not name the row.
It is narrow on purpose, because in a components directory a function's name is JSX's to decide, and the row still states in 19 areas of that repository, 14 of them through the prior D8 gives it.
Two of the sixteen needed a second pass.
`absent_is_null` guarded only the `undefined` arms, so a `return null` in an effect stayed a site of a row whose own predicate says an effect callback is not one; both arms go now, which is what the reason the predicate gives already argued, and no corpus repository holds such a site.
And a component was recognised only by a bare `return <jsx/>`, so one rendering through a ternary or an `&&` stayed in the naming vote: in a directory of 40 components beside 40 helpers that flipped the learned class to camelCase and the check then asked for a lowercase component name, which is a host element and is the impossibility this row exists to stop.
Four corpus repositories hold 62, 35, 33 and 33 module-level PascalCase functions that read that way.
The exclusion asks every value the function hands out now, through a ternary, an `&&` or a yield, rather than only a bare return, and stops at a nested function, so a `renderRows` returning `items.map((i) => <li/>)` is still the helper it is named as.
Asking the whole body instead was measured and refused: a function that builds an element and returns a string made from it hands out no JSX, and ten such functions across two repositories left the population with nothing announcing it, which is the under-count direction the applicability contract exists to catch.
`exported_symbol_case` reads the same rule, because excluding a component on one row and not its twin left the same declaration asked for a lowercase name by the other sentence The closed set `change` can invert is now also read inside a `change` body, not only for unreadable SQL (`dimensions-rails.mjs` `holdsIrreversible`, C42).
`doc_comment_style` reads a JSDoc above an overload set's first signature as documenting the set, since TypeScript reads it from there and the implementation has to follow the signatures directly.
