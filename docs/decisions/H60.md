# H60

Section: H. Layout

## Decision

A scan writes a code index beside the map, `.claude/anatomiya/index.json.gz`: every function, method, class and type no function holds, in every language the scan reads, and Go's and Rust's constants and statics, each with its line, its container, its parameter list as written, the first sentence of its doc comment or docstring, and how many other files import or call it. `anatomiya find <words>` and `/anatomiya:find` rank it; nothing on a hook's path reads it

## Why

The reuse line (H9, H58) names five helpers per area, and the reuse check's subagent (A91) found the rest by grep.
Both answer "which helper already does this" and neither could list a repository's functions with what they take and who calls them.
The facets already resolved who reaches which name out of which file in all nine languages (H58, H59) and kept only the names a file defines; the line and the doc comment were one read away in each engine.
On the scenario repositories, the first `find` for the words of the task named the helper first: atuin `uuid v7` gives `uuid_v7()` (19 files import it), gitea `database engine session context` gives `GetEngine(ctx context.Context)` (252 files), mastodon `compare urls` gives `compareUrls` (4 files) and `local url` gives `TagManager#local_url?` (6 files).
The importer count is in the score as well as the tie-break, since what a repository already leans on is the helper to call: without it gitea's `GetEngine` ranked fourth behind `GetContextSession`.
Each word is weighed by how rare it is among the names, because a subagent asks in a sentence's words: atuin `run script id new uuid`, the first query a measured session sent, ranked `uuid_v7` past the twelfth hit with every word counted alike, and second once weighed.
A name run together is a word of its own and endings are folded, since `unindent` did not find eslint's `unIndent` and `strip indentation` did not reach `indent`.
A word counts once, in the best place it matches, as Sourcegraph's BM25F work argues against summing a score per field (`docs/research/how-code-search-ranks-a-symbol.md`): on 19 queries over the indexes of atuin, gitea, mastodon, eslint and django, the mean reciprocal rank of the helper each query was after went from 0.794 summed to 0.833, with 14 of 19 first and 17 in the top three; within the six hits `find` prints, 18 of 19 are there and the rank reads 0.826.
Counting a word's rarity over the name, the class and the doc, the places a match is scored, rather than the name alone, and dropping filler words such as `the` from a query, raised the six hits to 0.879, 16 of 19 first: a word no name holds had weighed most, so `read the index` and `read index` answered differently.
The same 19 queries are why the importer prior stays a multiplier: capped at 1.3 they read 0.790, and with no prior 0.684.
Zoekt uses its static rank only to break ties, but a code search looks for the definition a person asked about, and a reuse search for the one the repository already leans on.
A whole-name bonus, Zoekt's, changed no rank, since the name run together is already one of its words.
Constructors, C# delegates, Kotlin type aliases, Rust macros and Python lambdas bound to a name are indexed too, since a session looks for them by name as it does a function; properties and constants outside Go and Rust are values a session does not call.
A committed index is the repository's to write and reaches the reuse subagent's prompt, so a row longer than a scan writes, a name past 200 characters, parameters past 80, a doc past 60 or a path past 1,024, is dropped on read.
A scan that had no engine for a language keeps the last index's rows for that language's files, as B41 keeps its areas.
A Java or C# definition is listed at the line of its name, not of the first annotation above it, which is where a reader is sent; a call qualified by an inline module, `util::parse`, credits the function that module holds; and where the last refresh recorded that its scan could not write an index, doctor and `find` say so rather than asking for a scan.
A Ruby `module` is listed as a module, not a class, so a session is not told a namespace can be instantiated, and `Billing.round` credits the module's method as `Role.find` credits a class's.
The queries were written by the author after the first ranking had been seen, so the numbers compare variants and claim no accuracy for `find` in general; they, their ranks and each variant's are in `docs/measurements/data/2026-10-28-find.json`.
