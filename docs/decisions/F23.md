# F23

Section: F. Safety

## Decision

Every read of a path a repository controls opens without waiting and types the handle before it reads: the record and the pin through one `readRecord`, a changed file in `check`, and a tracked path in the corpus, which is dropped when it is not a regular file

## Why

A fifo with no writer blocks an open for reading, and F17 held the rule for the rule-file audit and the hooks while three reads went round it.
`check` hung with nothing printed on a branch that turned a tracked file into a fifo; `scan` and `check` hung the same way on a fifo where the record or the pin belongs; and `scan` handed a fifo to a parse worker, which waited out its watchdog, 10 seconds on a ten-file repository, and was then reported as a file that crashed the parser.
A tracked path that is not a regular file (a fifo, a socket, a directory, a gitlink named like a source file) has no source to read, so it goes where a tracked file that is gone already went, the `escaped` count, which nothing renders: a false crash line is traded for silence about a path nothing could have been counted from.
The record and the pin take the 64 MiB cap the hook already held its read of the record to, against 9,957,450 bytes for the largest record written

## Status

**done** `facts.mjs` (`readRecord`), `baseline.mjs` (`loadPin`), `check.mjs` (`treeSource`), `corpus.mjs` (`classify`).
A tracked symlink is dropped the same way, to `escaped`, even where its target stays inside the repository.
What git tracks for a link is its target's name, not source.
Read through it, the target's sites counted twice, and the baseline reused that parse for a path whose link blob had not changed since the pin, so an edit to the target moved the pinned counts from 52/52 to 52/55 (E2).
`classify` lstats the listed path, pinned by `test/corpus.test.mjs`., `rules.mjs` (`readHead`, which also loops a short read).
The fifo cases in `test/facts.test.mjs`, `test/baseline.test.mjs` and `test/check.test.mjs` run the read in a child under an 8 second bound; the corpus case in `test/corpus.test.mjs` runs in process, since the fifo is dropped before anything opens it for reading.
A record past the cap is not silence: `readFacts` names it, and `check` prints it.
Every cap is asked of the file's size on disk, which `readHead` reports, rather than of the decoded head, where a byte that is not UTF-8 counts three times: 22 MB of such bytes read as past 64 MiB, and `reuse` left out a file the parser reads.
Past the cap a record is not read at all: `readRecord` asks the size first, through `readHead`'s `whole` option, so a committed record past it costs each hook call an open and a stat rather than a 64 MiB read; a record of exactly 64 MiB is read and one byte more is not.
A tracked file that is gone, or that the filesystem refuses to resolve, now goes to `unreadable` rather than `escaped` (A21), since it is no link and no special file and the reader can act on it; a link whose target is gone is still `escaped`.
