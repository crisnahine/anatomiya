# H57

Section: H. Layout

## Decision

What a path's name says about being a test file is read in one function, `namesATestFile` in `test-shape.mjs`, which takes the evidence its caller holds. A reader that parsed the file asks a test tree to agree with a `_spec.rb` or `_test.rb` name (H35). A reader holding only the path reads that name as a test anywhere

## Why

The rule lived twice, in `isTestFile` and in `isTestPath`, and the two had drifted with nothing recording it: the path reader never took H35's narrowing, and no row extended it there or exempted it.
The strict rule applied to the path reader was measured over all 377,420 tracked paths of both corpora: 51 answers move, every one a Ruby name outside a test tree, and none the other way.
It is right for 7 (four Homebrew source files named `_spec.rb`, a Cucumber support file, a CI driver and a custom cop), an accepted miss for 1, and wrong for 43: canvas-lms's 39 specs under `gems/plugins/<plugin>/spec_canvas`, 3 puppet acceptance specs and 1 spec of rails-api.
The file reader can hold the strict rule because its parse reads those 43 as tests before their name is asked.
The path reader holds a path and nothing else, so it keeps the name alone, as a parameter of the one function (`read`) and no second copy.
The dotted and hyphen forms are read on the basename by both: a directory named `a.test.d` makes no file under it a test, where the path reader had read the whole path, and 0 of the 377,420 paths move.
`isTestPath` on 0.15.1 and on this build agree on all 377,420, 47,046 of them tests
