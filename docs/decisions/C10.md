# C10

Section: C. The counted-claim model

## Decision

The facts record carries a schema version, and a reader refuses a version above its own rather than reading the fields it does not know

## Why

The version was written by `write.mjs` and read by nobody: the check took whatever shape was on disk.
Fields have moved twice already, at 2 for the polarity keys and at 3 when the single `glob` became `globs`, and a plugin update is not atomic with the map a repository has committed.
Reading a newer record positionally enforces a convention nobody stated, which is the one failure the whole counted-claim model exists to avoid.
An older version stays readable, because the compat rules for 1 and 2 are written down and tested

A build that does not know the key reads such a record as any other and writes its own without the key.
