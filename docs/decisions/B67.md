# B67

Section: B. Engine

## Decision

A machine without `web-tree-sitter` loses the seven languages and nothing else, and a grammar file that does not load loses its one language. The two are named apart: the package's remedy is `setup`, and a grammar file's is to reinstall the plugin

## Why

Run on an install with the package taken out: a Python-only repository was refused with `web-tree-sitter is not installed` and the `setup` command, exit 1; a repository of TypeScript, Python and Kotlin got its TypeScript mapped and the line `no kotlin or python file was read: tree-sitter reported no version` with the same remedy, exit 0.
Run on an install with `kotlin.wasm` cut to 1,000 bytes: a Kotlin-only repository was refused with `grammars/kotlin.wasm did not load`; the mixed one got TypeScript and Python mapped and `no kotlin file was read: the plugin's kotlin grammar did not load`; `doctor` printed `grammars: 6 of 7, kotlin.wasm did not load`.
Run with `java.wasm` copied over `kotlin.wasm`: the file loads, `doctor` printed `grammars: 7 of 7`, and a scan of kotlinx.serialization answered `720 files could not be read by this tool's grammar` and that the files may be fine; with `grammars.json` deleted, `7 of 7` again.
So the probe `doctor` and `setup` share also hashes each file that loads against the SHA-256 the manifest records, from bytes read once under a bound of 32 MB (`shippedBytes`; the largest grammar shipped is 5.4 MB), and the row says `kotlin.wasm is not the file this plugin shipped`, or `grammars: 0 of 7, grammars.json is missing or is not the file this plugin shipped` where the manifest is gone, is not JSON, or records no hash for one of the seven.
A file the runtime turns away by its language version is said in the runtime's own numbers and not as one that did not load: `grammars: 4 of 7, java.wasm and rust.wasm and kotlin.wasm are language version 14 and this runtime reads 15 through 16`, on an install whose runtime reads from 15 (`test/readiness.test.mjs`).
Only the digits of the loader's message reach the line.
A scan and a check print the loader's own words where a grammar does not load, on one line and through the encoder, since the message quotes names out of the file.
An entry at a grammar's name that is a link, a directory, a fifo, a device or a file over the bound is never read: it reads as `is not the file this plugin shipped` in `scan` and `check` as in `doctor`, and a manifest that is no regular file or is over 64 kB reads as a missing one.
With a fifo at `go.wasm`, `doctor` answers in 0.4 s, where a plain read of the path did not return in 6 minutes 42 seconds.
The remedy stays the reinstall, which brings back the runtime the lockfile names.
A scan hashes nothing and loads what is there, so its own sentence for a swapped file stands, and `doctor` is where it is found.
No package install writes a grammar file, so the engine's own remedy would run and change nothing.
With the grammar cut `setup` and `setup --dry-run` print `doctor`'s line for it under `nothing to install`, run no install and exit 2.
The files of a language nothing was there to read are counted once, on the summary line that says why (`16 files: tree-sitter reported no version`, `8 files: the plugin's kotlin grammar did not load`), and on no `could not be parsed` line of the summary or the overview.
Given up: the reinstall remedy names no command, the overview names the language without a count, and a link at a grammar's name is refused even where it leads to the shipped file, except on Windows, which has no `O_NOFOLLOW` and types what the link leads to
