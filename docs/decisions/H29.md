# H29

Section: H. Layout

## Decision

A file the parse read and found no statement in is not a test file, whatever it is named

## Why

empire-flippers/api commented one spec out top to bottom, header and all, and it still made the service beside it read as covered; the runner collects nothing from it.
The empty program is the whole test and not the absence of a case, which was tried first and measured: reading "no test call at the top level" as "not a test" costs vscode 1,864 of its 2,366, because `test` there is nested inside `suite`, and 100 of this client's 102 Cypress specs.
Over the corpus the empty-program rule moves 23 files across 14 repositories, at most 0.6% of any one, and every one hand-checked is a licence header, a comment pointing at another file, or a bare triple-slash reference.
A file the parse never reached keeps its name's answer: unexamined is not empty, and that is the silence every other dimension keeps about an unread file.
The other half of the report needed no code and is recorded so it is not reopened: `RSpec.context` and `RSpec.feature` were already spec entry points, in the call table `facets.mjs` has carried since 0.1.13, and the receiver test already accepted `RSpec`.
The claim that they were unrecognised was read off a doc comment rather than off the behaviour.
Nor is an empty file a producer: left in the source list a commented-out spec could take ownership of a real one.
What this deliberately does not do is require an example, which is what the report asked for: of the corpus's 21,418 `_spec.rb` files that declare a group outside a whole-line comment, 1,064 hold no bare `it`, `specify`, `scenario` or `example`, and the ones read by hand are real suites pulling their examples in through `it_behaves_like`, so the rule as asked would drop about a twentieth of the corpus's specs
