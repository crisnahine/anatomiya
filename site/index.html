New to the codebase? So is your coding agent.

anatomiya reads your repository and its git history, then teaches Claude Code what a senior teammate teaches you in your first week: where files go, which helpers already exist, how tests are written here, and what has to change together.

Every rule it hands the agent is counted from your code, with the count beside it, so Claude can tell a habit from an accident.

The problem

The conventions are in your code. The agent starts from zero.

An agent writing code in your repository has no memory of the last review, and the conventions it needs are rarely written down: they are what the existing code happens to do. A reviewer catches the mismatch, the agent fixes it, and the next task starts over.

In a session

What Claude gets, and when

anatomiya hands each part of the map to Claude at the moment it matters. Every block below is output from a public repository, at the commit the README or the usage guide names.

Every session: the house rules

The overview is in context on every turn, before Claude reads or writes anything: where things live, how tests are laid out, and which areas state rules. In a long session it is handed back about every 30k tokens.

When Claude opens a file: that directory's rules

An area file loads the moment Claude reads a file under it: each habit that cleared the gates with its evidence, and a count for each one that did not.

Before a new file: what your history ships with it

Before a Write, an Edit or a notebook edit, a hook says what the default branch's history ships with that kind of file, or that a test is going where its siblings keep none. On every other write it says nothing.

When its turn adds code: the helper you already have

When a turn adds code, one subagent looks for an existing function that does the same job, starting from the code index, and Claude is asked to call it. In mastodon every session without anatomiya wrote its own URL comparison, and every session with it called compareUrls.

Whenever it asks: the code index

Each scan indexes every function, method, class and type a file declares at its top level or in a class, with its parameters, its place, the first sentence of its doc and how many files import it. /anatomiya:find asks it in plain words, and a name in any casing works.

Before you review: what this branch broke

/anatomiya:check compares the branch with its merge base, uncommitted work included, and lists each habit the branch broke at the line that broke it. Nothing is blocked, and --format github turns each finding into a pull request annotation.

In the background, a checkout, a pull or a commit starts a refresh, so the map keeps up on its own. The checks measure against a baseline that moves only with commits that came to your default branch from the remote, so Claude cannot lower the bar it is judged by.

    How it works

    Counted, gated, delivered

    A scan reads your tracked files once and writes a map Claude Code loads on its own. Four hooks keep it current and speak at the moments above. The scan runs on your machine, and anatomiya itself sends nothing anywhere.

    What a scan does

    1. Collects the corpus from git ls-files and nothing else, so an .env or a key file never enters it, and leaves out fixture, vendor and build directories.
    2. Finds the areas: any directory holding enough source.
    3. Parses each file once in a pool of child processes: oxc-parser for JavaScript and TypeScript, Ruby's own prism, and seven tree-sitter grammars for Python, PHP, Go, Java, C#, Rust and Kotlin.
    4. Counts per area across {{dimensions}} dimensions, plus one pass over git log for who wrote what and which files change together.
    5. Applies the gates, and prints whatever fails one as a count.
    6. Writes the map into .claude/rules/, each file's body forty lines at most, and the facts, the pin and the code index beside it.

    What runs in a Claude Code session

    1. refresh looks in the background when a session starts and whenever HEAD moves, and rescans where anything the map depends on changed.
    2. echo hands the overview back once the model has read on past its last copy.
    3. notice speaks before a Write, an Edit or a notebook edit, only where the history or the test layout has something to say about that path.
    4. reuse asks one subagent for a function that already does the job when a turn adds code.
    5. check runs the same counts at the merge base and in the working tree, and reports what the branch introduced.

    Quick start

    Install in three commands

    The plugin installs its three runtime dependencies itself. After the first scan, a checkout, a pull or a commit keeps the map current.

    1. 1

      Add the marketplace

      /plugin marketplace add crisnahine/anatomiya
    2. 2

      Install the plugin

      /plugin install anatomiya@crisnahine
    3. 3

      Scan your repository

      /anatomiya:scan

    What it needs

    • Node 22 or newer, on the PATH Claude Code runs hooks with.
    • git 2.31 or newer, and the history itself, for what ships together.
    • For Ruby, ruby with prism 1.x: Ruby 3.4 ships it.
    • Linux, macOS or Windows: CI runs the suite and an end-to-end scan, pin and check on all three.

    The commands

    /anatomiya:scan
    writes the map and the code index
    /anatomiya:check
    reports what the branch broke, as MUST-FIX, FIX or NIT
    /anatomiya:find
    looks a job up in the code index
    /anatomiya:pin
    accepts the current code as the baseline, by hand
    /anatomiya:doctor
    says which parser engines loaded
    /anatomiya:setup
    installs the parser packages where an install stopped short
    Run it without Claude Code, or in CI 
    git clone https://github.com/crisnahine/anatomiya
cd anatomiya && npm install --ignore-scripts
node plugins/anatomiya/bin/anatomiya.mjs scan /path/to/your/repo
node plugins/anatomiya/bin/anatomiya.mjs check /path/to/your/repo --format github

    --format github prints one annotation per finding, and --format json gives a job the same answer as a record. Cursor and GitHub Copilot get the same map with scan --targets cursor,copilot, without the hooks.

    Limits

    What it will not do

    Read this before deciding.

    • It does not catch bugs. Of 317 defect comments measured across ten repositories, 1 was preventable by a map like this one. It catches code that works and does not belong.
    • It is not a linter. It enforces nothing, and a rule your linter already enforces is wasted in the map.
    • A directory's file loads on a read. An agent that only greps and runs cat gets the overview and not the directory's file.
    • A habit that just changed can lag. A ship-together rule stays until the newest changes outweigh it.
    • Some lines are fixed sentences. Every overview asks Claude to read before editing, to look instead of guessing, and to finish the change; the usage guide lists each one and what it rests on.

    Questions

    Questions you should ask first

    Does it send my code anywhere?

    No. It runs on your machine. The only command that goes online is /anatomiya:setup, which installs the parser packages from npm. The reuse search is an ordinary subagent in your own session.

    Will it block a commit or a merge?

    No. Nothing it writes blocks a commit, a push or a merge. check reports, and you decide.

    What if the map says something wrong?

    Every rule carries its evidence, and every overview tells Claude that where the map and the code disagree, the code is right. The map rebuilds itself on the next checkout or pull. Where a line is wrong, an issue with the line and its directory is the fastest fix.

    Which languages?

    JavaScript, TypeScript, JSX, Flow, Ruby and Rails in depth, and the script blocks of Vue and Svelte. Python, PHP, Go, Java, C#, Rust and Kotlin get the layout, their tests, the code index and a few habits each, and the views written in ERB, HAML, Slim, Blade, Razor, Jinja, Twig and Go templates get the reuse check.

    Does it work outside Claude Code?

    Cursor and GitHub Copilot get the same map, written where each one reads it. The hooks are Claude Code's, so those tools get the map and not the notice, the reuse check or the background refresh.

    What does it cost?

    It is free and MIT licensed. What you pay is tokens: the overview on every session, 2.3 to 3.4 KB on the repositories measured, a directory's file when Claude opens a file there, and one subagent on each turn that adds code.
