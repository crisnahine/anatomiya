# anatomiya build contract

Every row is a finding that survived review or a probe that overturned an assumption, reduced to the
decision it forces on the code. This replaces the v1/v2/v3 specs as the thing to build against; those
are history. Status is what the code does **today**, not what it should do.

Sources: five-lens verification of v3 (26 blocking findings), six empirical probes, a ten-repo
public measurement, a 4,616-comment classification, and a 237-entry glossary re-audit.

## B. Engine

| # | Decision | Why | Status |
|---|---|---|---|
| B1 | `oxc-parser` for JS/TS, `prism` for Ruby, as the syntactic tier | Measured 4,153 and 6,867 files/sec, enclosing scope free from the walk | **done** |
| B2 | `oxc` runs in a pool of warm **child processes**, never in-process, never worker threads | Measured: uncatchable SIGSEGV from inside `parseSync` at nesting depth, a worker thread does not contain it, and no static pre-screen predicts it. The pool is also *faster*: 8,463-10,563 files/sec vs 3,058 | **done** |
| B3 | Guards per file: 4 MB size, 5s timeout, 1 GB RSS polled after 250ms in flight | Measured; no V8 heap flag caps it | **done** |
| B18 | The raw parser transfer is refused on Windows, whatever `rawTransferSupported()` says | It allocates a 6 GiB buffer per parsing operation to take a 4 GiB-aligned window inside it, and oxc's own note says almost none of those pages is ever touched. That is address space where the kernel overcommits and committed memory where it does not. Windows does not overcommit, this pool runs up to eight workers each parsing, and Windows is the one platform where the pool's memory guard stands down because there is no `ps` to poll. `rawTransferSupported()` asks about pointer width and the Node version and never about the platform | **done** `limits.mjs` (`rawTransferAllowed`), `parse-worker.mjs`. The flag is experimental upstream and the parser answers the same tree without it, so the cost is the measured 3.06x on the parse alone, on one platform. Not reproduced here: this machine is macOS, and the reasoning is oxc's documented allocation plus Windows commit behaviour rather than a run |
| B4 | `prism` stays in-process with an explicit `rescue SystemStackError` | Measured safe | **done** `ruby.mjs` — prism runs in Ruby, so one subprocess and no pool is what "in-process" can mean here |
| B5 | **Never index a disk buffer with a parser-reported offset.** Slice the same in-memory string handed to the parser | Measured: `oxc` reports UTF-16 code units, `prism` reports UTF-8 bytes, 5.4% of real files are non-ASCII. Silent corruption, worse than the crashes | **done** |
| B6 | Containment collapse, keyed within one file | Measured: overlapping matches are *nested*, not duplicate. A range hash catches none of it. Offsets are not comparable across files | **done** |
| B7 | `typescript@5` checker is a second tier, opt-in via `--deep`, never the default. Pin major 5 | Measured: 26x slower, whole-program (narrowing the file set drives unresolved types from 3.1% to 36.2%), and it buys 5 entries. `typescript@7` is the Go port with no JS API | todo |
| B8 | A broken `tsconfig.json` is detected and reported as degraded mode | Measured: typed resolution drops 89.5% to 39.8% silently | todo |
| B9 | The semantic tier reads repository-authored `tsconfig.json`, so the "libraries read no repository configuration" claim is false. Confine `extends`, force the root file list to the corpus, resolve our own deps from the plugin root | The v3 claim was untagged and its own evidence section falsified it | todo |
| B10 | **Dimensions run in the worker; only counts cross IPC.** The tree comes back only for the check, which needs line numbers, and only for the files a diff touched | Measured: the walks are 85% of the scan's CPU (1.57ms/file against 0.27ms to parse) and running them in the parent left that 85% on one core, so pool throughput stopped improving past 4 workers on 11 cores. The reply for an 18 KB file went 278,261 bytes to 649 | **done** |
| B11 | **No cap on repository size**: not file count, not total bytes, not cumulative Ruby output. Per-file guards only | The 50,000-file cap did not trim a tail, it set `truncated`, which suppresses every directive in the map. Measured on a synthetic 100,000-file repository: 50,000 files seen and 0 of 720 claims stated, against 100,000 files and 480 of 720 now | **done** |
| B12 | The baseline reads only files that differ from the pinned commit; the rest reuse the corpus parse | Measured: the baseline stage was 6,875ms of an 8,768ms scan, re-reading through one `git cat-file` per file, on a repository where nothing had changed. Now 90ms | **done** |
| B13 | A missing parser dependency fails the scan **and the check**, and a file that answered `ok: false` is counted apart from one that crashed | Measured: with no `node_modules`, every file failed to parse, was charged as parsed, and the CLI printed a clean empty map and exited 0. `/plugin install` does not run `npm install`, so that was the first run a marketplace user got. The fix landed on the scan alone: the check went on folding all four causes into one caveat per file and reporting no findings, which the command file tells the agent means the check ran | **done** `parse.mjs`. One module drives both engines and decides the classification once, so the two callers cannot disagree about it again. Both bridges report an absent interpreter as one fact rather than as every file crashing: `ruby.mjs` marked a missing `ruby` the way a poison file looks, so the check's guard, which reads the flag, could not see it |
| B14 | The parser buffer is named after the file's real extension, never after its language | Measured: JSX is legal in `.js` and the TypeScript grammar reads `<div` as a type assertion, so 727 of react/react's 2,296 files and 3,924 of next.js's 21,358 were counted from a recovered tree, with nothing reporting it. Always asking for the JSX grammar is not the fix: `<string>x` is legal in `.ts` and a syntax error in `.tsx` | **done** `parse-worker.mjs` |
| B15 | A parse reporting syntax errors answers `ok: false`, and its count is reported on its own line | Measured: oxc recovers to an almost empty program, so react/react counted 906 `assertion_style` sites where there are 13,737; prism recovers further and answered a *conforming* site from a method with no body. | B19 | A `.js`-family file oxc rejects is retried with its Flow types stripped, and the stripper is loaded the first time one is needed and never before | oxc refuses Flow by name, and react is written in it: 287 of its 2,277 files were charged as syntax the parser rejected, so every site in them counted nowhere and the areas holding them were closed as a population that moved. The stripper replaces types with whitespace rather than removing them, so the length in UTF-16 code units is unchanged and every offset and line number still lands where it does in the source. Scoped to `.js .jsx .mjs .cjs`, because Flow is not legal in the `.ts` family. Lazy because the stripper reaches `hermes-parser` and costs about 13 MB resident, which all eight workers would pay on every repository as a top-level import; a repository with no Flow never loads it. A file the stripper cannot read either, or a retry that still reports errors, stays rejected: the retry may not turn a genuine syntax error into a clean parse |

## C. The counted-claim model

| # | Decision | Why | Status |
|---|---|---|---|
| C1 | Every dimension carries `applicability`, `candidates`, `conforming`. Ratio over **candidates**, never over file count | Measured: file-counting flips 10 of 39 verdicts, in both directions. It hides real conventions *and* manufactures false ones | **done** |
| C2 | A dimension with no writable applicability predicate does not ship | 8 of 8 were writable; 3 of them under-count applicability, which is the dangerous direction. Re-measured over expressjs/express, sidekiq/sidekiq, vuejs/core and mastodon/mastodon, across the 37 of 40 rows that produced a slot in any of them, since which rows those are depends on which repositories are asked: 6 precise rows sit under a 0.25 median applicability share and each names a construct that is simply rare, so the share ranks rows to open and decides nothing. The under-count the row is about was found by the witness rather than by the share, and by widening it: `service_result_shape` refused every receiver, so `def self.call`, the commonest Ruby service entry form, was not a site at all and the ratio was stated over whichever subset writes instance entry points. One witness per sentence would not have caught it either, and neither would a sixfold narrowing of `optional_chaining`, the row this contract already names as the measured false-convention case. A sentence naming a set is only as true as the members somebody wrote down | **done** `dimensions.mjs` (`assertApplicability`), `pairing.mjs`, `dimensions-ruby.mjs`, `test/applicability.test.mjs`, `scripts/audit-applicability.mjs`. Writable was already true. What nothing held was that the predicate a row ships agrees with the sentence anybody would write for it: `applicability` is whatever `run` emitted, so a predicate seeing a tenth of its own construct gives 1.0 over four files and reads as a strong convention. Each row states the files it can speak about and, where it is partial, what it cannot see, tied to `precision` so the marker and the reason cannot disagree. The witness is per form rather than per row: every shape the code treats differently gets a source, because one source proves the sentence names something and nothing more. A closed table of names is one shape, so it is covered from the other side, each member driven through the predicate against a list written out in the test: dropping `next-intl` from the module list changes no shape and makes every file in such a repository inapplicable, and reading the expectation off the table would agree with it by construction |
| C3 | Render `applicability` beside the area file count on every line | A wrongly narrow predicate gives ratio 1.0 over a small set and reads as a strong convention. This is the only thing a human can audit it with | **done** `render.mjs`, `facts.mjs` (schema 6). The rendered line carried the number a reader audits by eye; the machine record did not. `langFileCount`, the files a dimension could speak about rather than every file in the area, shaped the gate and was then dropped before the record was written, so the share that separates a narrow predicate from a rare construct could not be read back at all. The record carries this pass's count beside this pass's `applicability`, which is the pair that divides; the gate reads the baseline's where there is one, and storing that instead would put a numerator and a denominator from two populations on one line. Auditing one line at a time is what a reader does; auditing every row that produced a slot, across four repositories, needs it on disk |
| C4 | Applicability floor: the stricter of two, `applicability >= max(ceil(sqrt(F)), ceil(0.25 * F))`, where `F` is the files the dimension can speak about | v3 promised this floor and gave it no number, no gate, no storage, no test. Each floor alone is wrong: the root asks for more than a quarter below sixteen files, where a quarter of a small directory is one or two files, and the share is what holds above it. Measured: the root alone asked 11 files of 120, and a 120-file area where 11 files used `?.` and 109 read absent values without it stated the claim over all 120 | **done** `reduce.mjs` (`GATES.minApplicabilityShare`, gate name `applicability`). `F` is the files the dimension could speak about, and a file nothing was read from is not one of them: `applicability` counts files that produced a site, so a denominator over every file of the language divided one population by another. Measured over a 35-repository corpus, on the repositories that hold syntax this tool does not take: react is written in Flow, 287 of its 2,277 files are rejected, 55 of its 122 areas hold at least one and one area holds nothing else, and its stated claims go from 36 to 65 once the denominator counts only what was examined. Webpack 80 to 92, next.js 162 to 172. None of those claims was suppressed because a predicate was narrow. An obligation is counted the same way, since `applyPairings` skips a record that is not ok and an unread producer answers nothing. The count is taken off the records handed in rather than off the area's file list, which is what makes `applicability <= langFileCount` hold in both passes: the pinned pass reduces records keyed by the pinned paths against an area holding today's, so reading `area.files` dropped every file renamed since the pin, and twelve renames with no content change took a slot from suppressed to stated. That is the laundering the pinned population exists to refuse, arriving through the denominator |
| C5 | Dimensions carry `precision: precise \| partial`. A `partial` dimension can never reach top severity | 3 of 8 measured predicates are partial | **done** `dimensions.mjs` (`assertPrecision`), `check.mjs` (`severityFor`), `pairing.mjs`. The cap was enforced; carrying the field was not. `severityFor` reads `precision !== "precise"`, so a row that forgets it or spells it `"Precise"` is capped by the same comparison a deliberate `partial` is, silently, and reads in the map as a claim nobody marked. Checked at load rather than in a test, because the registry is assembled from six files and the obligations were the sixth: they are not in `ALL_DIMENSIONS`, and every per-file precision test had missed them |
| C6 | A dimension may state its inverse only where it carries a hand-written `counterClaim`. Refusal is an explicit `null`, never an absent key. Both sides run the same gate battery, and every gate but the three numerators is polarity-free | 144 dimension slots across ten repositories hold a strong inverse and state nothing. A machine negation names nothing for the agent to write, and writing the sentence out loud is where an inverse that is really a defect becomes visible. 13 of 32 dimensions are eligible; a counter needs the same measured cross-repository spread the claim does | **done** `reduce.mjs` (`judge`), `facts.mjs` (`statedSide`, the record the polarity fields are written into, and the schema they arrived in), `check.mjs` |
| C7 | A file-to-file obligation is a dimension whose site is the file, counted over the corpus rather than over a tree. Every such row carries `companionsElsewhere`: producers whose companion is missing where the predicate looks, which C9 now learns rather than declares and whose namesake exists elsewhere. A repository is asked the question only for a companion suffix it actually uses | Every other dimension asks a question inside one file, and a review comment is as often about a missing companion as about syntax. Two things a first cut got wrong and the measurement caught. A ratio of zero has two meanings, so the audit count is what separates them: on alphagov/whitehall the `app/models` area scores 0 of 160 and 117 of those models have a test one directory deeper, which without the count reads as a repository that does not test its models. And producers exist whatever a repository tests with, so counting both the RSpec and the minitest row put a line that can only read zero into every Rails map | **done** `pairing.mjs`, `reduce.mjs`, `scan.mjs`, `check.mjs`, `render.mjs`, `facts.mjs` (schema 6). The namesake count was rendered and not stored, so the map printed a number the record it is derived from could not reproduce. Stored beside the two counts behind "and N more", which had the same shape, and the version moved for them: two records both calling themselves 5 with different fields is the coincidence C10 replaced |
| C8 | A dimension whose claim belongs to a framework carries `framework`, and is offered only where the corpus shows that framework | Measured: `zone_aware_time` has no counter-claim, so off-Rails it can only ever print zero, and did: 123 sites on Homebrew, 197 on puppet, 97 on fastlane, 96 on chef, plus a NIT delivered onto a plain-Ruby branch. The signal is `app/models/`, `db/migrate/` or `config/application.rb` in the corpus, which separates 14 Rails from 5 plain across 19 repositories; read from the corpus, because rubocop's only `app/models` files are three fixtures the corpus drops. Only the two dimensions that cannot see their own context are marked. The check asked its own question and never asked which frameworks are here, so the measured NIT on a plain-Ruby branch outlived the fix on the scan | **done** `dimensions.mjs` `corpus.mjs` `check.mjs` |
| C9 | An obligation learns its companion root from the corpus, with the declared pair as the prior | Measured: alphagov/whitehall keeps model tests under `test/unit/app/models` and scored 0 of 160 with 117 namesakes one prefix away, now 117 of 160; discourse answers its controllers in `spec/requests`, which no hardcoded pair reaches. Learned on the path tail rather than the basename, because basename matching was ambiguous for 388 of one repository's services. A tie learns nothing and the declared pair stands, or an obligation is decided by a filename | **done** `pairing.mjs` |
| C10 | The facts record carries a schema version, and a reader refuses a version above its own rather than reading the fields it does not know | The version was written by `write.mjs` and read by nobody: the check took whatever shape was on disk. Fields have moved twice already, at 2 for the polarity keys and at 3 when the single `glob` became `globs`, and a plugin update is not atomic with the map a repository has committed. Reading a newer record positionally enforces a convention nobody stated, which is the one failure the whole counted-claim model exists to avoid. An older version stays readable, because the compat rules for 1 and 2 are written down and tested | **done** `facts.mjs` (`schemaProblem`, `readFacts`, `FACTS_SCHEMA`), `scripts/audit-applicability.mjs`. The rule is one function now rather than a shape each reader re-tests, because a second reader arrived: the audit read a record field by field and reported a file that was not a map at all as a clean empty table. Which of the two refusals it is comes back tagged rather than as a message, or rewording the sentence would silently move the branch |

## D. Gates

| # | Decision | Why | Status |
|---|---|---|---|
| D1 | `conforming / candidates >= 0.90` | The measured gate elsewhere; v1 loosened it to 0.80 with no argument | **done** |

| D3 | **The sites are worth at least 3 files by inverse-Simpson count, and the ratio still reaches 0.90 with the largest file dropped** | v3's `files_conforming >= 3` does not block its own motivating case: 200 candidates in one file plus one each in 13 others gives 14 files, ratio 1.0, and every gate passes. ## E. Baseline and drift

| # | Decision | Why | Status |
|---|---|---|---|
| E1 | Store the baseline **file list** per area at pin time; compute baseline over that list, not the current glob | Moving violating files into a denied or new directory otherwise re-selects only the conforming ones at the baseline sha, ratio 1.00, every guard held | **done** `baseline.mjs`, `reduce.mjs` (`verdictFor` orders the population block ahead of the gates) |

| E6 | Drift is files changed in mapped areas over `<baseline>..<base-ref>`, never `..HEAD` | Over HEAD the branch's own changes count as drift, so severity falls as the change under review grows | **done** `git.mjs` (`resolveBaseRef`, the one resolver both phases read) |
| E7 | Carry a rename map from `git diff --find-renames` into the baseline lookup | A path hash cannot tell a rename from a delete-plus-add, and at the baseline sha the new path does not exist | **done** `baseline.mjs` |
| E8 | A pinned file this tool cannot read closes the area, unless it cannot be read today either, which makes it a blind spot rather than something the pin lost | Any unread pinned file suppressed the whole area, and a permanent blind spot is not a population that moved. The current pass already leaves such a file out of its counts, so the two passes disagreed about what an unreadable file means. A file readable at the pin needs no exception at all, since the pinned population is what the gates read and it was counted in full. The obvious objection is laundering, and all three routes were tried on a repository pinned at 54 of 84: breaking the violating file at HEAD leaves the ratio at 0.64 and the gate on `ratio`, because the baseline reads the blob at the pinned commit where it still parses (E2); deleting it reads 1.00 today and is closed by `population-change` (E1); and a file unreadable at both revisions was never counted at either, so it has no sites to hide |

| # | Decision | Why | Status |
|---|---|---|---|
| F1 | Corpus is `git ls-files -z`, NUL-split, deny-list applied | Git permits newlines in paths; a newline split turns one hostile filename into two entries | **done** `corpus.mjs` |
| F2 | Lexical containment, then realpath both sides, fail closed, read the resolved path | v3 dropped this to one sentence about symlinked directories, which exempts symlinked files | **done** `corpus.mjs` (the read), `rules.mjs` (`resolveInside`), `write.mjs`, `facts.mjs`, `check.mjs` (the write). It held for the corpus and for nothing else, which is the half that only reads. Measured: a tracked `.claude -> ../victim`, git mode 120000 so it survives a clone, had the scan write the map and `facts.json` into a directory the repository does not own, name that directory's files in the always-loaded overview, and remove one of its `anatomiya-*.md` files on the next scan. `join` normalises `..` and resolves no link, so lexical containment is not containment. Every component is resolved now, a dangling link is refused rather than created through, and the two directories are checked before anything is written, since one link at `.claude` escapes with both. The scan fails closed; the check reports, because refusing a branch over a link is the blocking behaviour this design rejects |
| F17 | A file in `.claude/rules/` is read by its head and only when it is a regular file, and every listing of them is bounded | Measured: the ownership test is a regex anchored at byte zero, and it was reading whole files to run it. A tracked symlink to a 400 MB blob took a scan's peak resident size to 1.2 GB; pointed at `/dev/zero` the read never returned at all, and a symlink is available on every Unix box. A directory named `anatomiya-overview.md`, which is a fixed name a repository can spell, threw `EISDIR` out of the atomic rename and failed every scan with an errno. The check listed every name it found, into the context of the agent reading the report | **done** `rules.mjs` (`readHead`, `HEAD_BYTES`, `occupied`, `listSome`), `check.mjs`, `render.mjs`, `bin/anatomiya.mjs`. The cap is sized by our own frontmatter rather than by a guess at how long one should be: an area's `paths` list is one line per pattern, and a cover needing 170 of them is 14 KB on canvas-lms, so a first cut at 8 KB put that file's closing fence past the head and this tool's own output came back as a file it had not written, never removable and named as somebody else's in the always-loaded overview. A megabyte is far past any cover generated across 35 repositories and far short of a file worth holding in memory. A file the tool cannot open is its own answer rather than an empty one: read as empty it failed the frontmatter test and came back as somebody else's, which the always-loaded overview then said out loud about the tool's own output, and which no later scan could undo because a file called foreign never re-enters the removable set. A directory that will not list is reported for the same reason the symlinked one is |
| F3 | One encoder, allowlist not denylist: reject non-printable codepoints, NFKC normalise, reject mixed-script paths, reject `\|`, `---`, comment delimiters, backtick runs; cap **before** quoting, on grapheme clusters; emit paths JSON-quoted | Bidi controls and zero-width joiners are category Cf and pass an ASCII control filter; `JSON.stringify` does not escape them either | **done** |
| F4 | Every repository-controlled value goes through F3: paths, area names, author names, commit subjects, branch names, matched source text | | **done** |
| F13 | History is read off the stream, and history git could not read is told apart from history that is empty, by exit code rather than by message | Measured: buffering put an oversize log in the same silent branch as a repository with no commits. Every file came back with no author, every dimension failed the author gate, and the map stated nothing with nothing to say why | **done** `authors.mjs` |
| F15 | A git read the check could not perform is reported, never absorbed as an empty answer | Measured: with the base commit's tree object missing, `git diff` exits 128 and every caller in `check.mjs` read its output without looking at the exit code. The result was zero changed files, zero findings and no caveat, which renders identically to a branch that broke nothing. Same shape as F13 for history and B13 for the parser, and the same rule closes it: tell "could not read" apart from "read, and there was nothing there", by exit code | **done** `check.mjs`. Every read looks at its exit code before its output: the diff, the added-line ranges, the pending-edits listing, and base resolution through `resolveBaseRef` and `mergeBase`, which report their outcome rather than an empty string. One read stays deliberately soft: an unanswerable `--is-shallow-repository` reads as not shallow, which costs a fallback rather than a wrong answer |
| F16 | No module in `lib/` imports its way back to itself | A cycle loads under ESM hoisting, so nothing fails at run time and the first symptom is a module reading a half-initialised binding from a partner still evaluating. `ruby.mjs` carried a comment refusing an import for exactly this reason and the comment was deleted in the same change that took the import, closing `ruby.mjs -> dimensions.mjs -> dimensions-ruby.mjs -> ruby.mjs`. The Ruby AST helpers living in the parser bridge are what make the registry unreachable from it, so shared code both bridges need goes in a module that imports nothing of ours | **done** `walk.mjs` (`collectHits`), pinned by `test/modules.test.mjs` |
| F5 | Any subprocess: `execFile`, arguments after `--`, reject paths starting with `-`, cwd outside the repository, no network, timeout, streamed stdout byte cap | Measured: `--` neutralises the whole argv class; a tracked file named `--instruction-file-path=.git/config` exfiltrated a secret without it | **done** `git.mjs` (`FLAGS`, `refuse`, `gitEnv`), `pool.mjs`, `ruby.mjs`. Two runners, one buffered and one streamed (F6), and both carry the timeout and a byte bound. Every git call goes through one of them: `corpus.mjs` and `authors.mjs` were the last two running their own `spawn`. One thing reaches the network and it is not the scan: on a shallow clone the check fetches the single base commit, because `merge-base` cannot answer without it and the alternative is reporting a branch against nothing. `ls-remote` and `fetch --depth=1` are the whole of it, both on that one path, and F14 separately forbids the lazy-fetch a partial clone would otherwise trigger. The scan makes no outbound call at any point, and the `gh` measurement helper that did was published in `lib/`, imported by nothing, and is gone. `--` is still not universal, because `rev-parse`, `cat-file`, `merge-base`, `config` and `status` do not take it, so the rule is stated from the other side instead: an argument that reads as an option must be one this tool wrote, checked against a closed list of the flags it actually passes. A ref, a sha or a path that begins with a dash now refuses the call rather than resting on whichever predicate was supposed to have caught it. The two subprocesses that are not git carry the battery too: `ps` runs with a timeout, a kill signal and a byte bound, since `execFileSync` blocks the parent's event loop and a `ps` that never returns is the memory guard becoming the hang; `ruby.mjs` times the wall clock behind the idle window, since a child answering one file every fourteen seconds never trips a liveness check. Both parser bridges now run outside the repository, and git carries an environment that refuses a credential prompt |
| F6 | Never buffer subprocess output; `spawn` plus streamed parsing | Measured: `execFile` throws `RangeError: Invalid string length` inside Node's own exit handler, `maxBuffer` does not protect, V8 caps any string at 0x1fffffe8 bytes | **done** `git.mjs` (`gitStreamed`, `pathSet`, `nameStatusReader`), `check.mjs`, `ruby.mjs`. The two callers that hand-rolled a stream, `corpus.mjs` and `authors.mjs`, share one field split; each kept its own reading of what the fields mean. The streamed side also bounds one record, which neither hand-rolled reader did: output carrying no delimiter grew one buffer to the same string limit streaming exists to avoid. Four reads that grow with the repository were still buffered, not one: `filesAt`'s `ls-tree -r`, `changedSinceWorktree`, `diffRange`, and the check's own `changedFiles`, where a branch off a distant base lists every path there is. The `--name-status -z` grammar now has a streaming reader beside the buffered parse, both of them one reading of what a rename's three fields mean. Which runner a function uses is pinned by `modules.test.mjs`, because both answer the same values on a repository small enough to test with |
| F7 | A partly-read corpus sets `truncated` and **suppresses every directive** | Counting over an arbitrary subset and rendering it like a complete scan is worse than reporting nothing | **done** `ruby.mjs`, `scan.mjs`, `baseline.mjs`. No repository size can set it (B10); the Ruby per-line guard can, and that path is tested end to end. Both corpus reads set it: the baseline materialises blobs from the pinned commit and parses them a second time, and that pass hits the same guard, so its flag travels back out of `measure` rather than being dropped at the seam |
| F14 | On a partial clone the author pass uses `-M100%` and refuses to lazy-fetch | Measured: `-M` scores similarity, which needs blob content a `--filter=blob:none` clone does not hold, so git fetched from the promisor one round trip at a time. 33 of 35 measured clones could not answer at all and reported history unread; warming them cost 62 seconds to 57 minutes each and 4 GB of network. A full clone is untouched and keeps the inexact detection D5 was measured on | **done** `authors.mjs` |

## What is deliberately not built

- **No hooks.** Worst-trusted channel, highest complexity, measured being flagged as prompt injection.
- **No MCP server.** Nothing to expose.
- **No skill.** It would spend resident context describing the tool instead of the repository.
- **No health score or grade.** It changes nothing about the next line of code.
- **No restating what the linter already enforces.**
- **No "catches bugs earlier" claim.** Measured: 1 of 317 defect comments across ten repositories was preventable by a conventions map. Nine of ten repositories scored zero.
