# anatomiya build contract

Every row is a finding that survived review or a probe that overturned an assumption, reduced to the
decision it forces on the code. This replaces the v1/v2/v3 specs as the thing to build against; those
are history. Status is what the code does **today**, not what it should do.

Sources: five-lens verification of v3 (26 blocking findings), six empirical probes, a ten-repo
public measurement, a 4,616-comment classification, and a 237-entry glossary re-audit.

## C. The counted-claim model

| # | Decision | Why | Status |
|---|---|---|---|
| C1 | Every dimension carries `applicability`, `candidates`, `conforming`. Ratio over **candidates**, never over file count | Measured: file-counting flips 10 of 39 verdicts, in both directions. It hides real conventions *and* manufactures false ones | **done** |
| C2 | A dimension with no writable applicability predicate does not ship | 8 of 8 were writable; 3 of them under-count applicability, which is the dangerous direction. Re-measured over expressjs/express, sidekiq/sidekiq, vuejs/core and mastodon/mastodon, across the 37 of 40 rows that produced a slot in any of them, since which rows those are depends on which repositories are asked: 6 precise rows sit under a 0.25 median applicability share and each names a construct that is simply rare, so the share ranks rows to open and decides nothing. The under-count the row is about was found by the witness rather than by the share, and by widening it: `service_result_shape` refused every receiver, so `def self.call`, the commonest Ruby service entry form, was not a site at all and the ratio was stated over whichever subset writes instance entry points. One witness per sentence would not have caught it either, and neither would a sixfold narrowing of `optional_chaining`, the row this contract already names as the measured false-convention case. A sentence naming a set is only as true as the members somebody wrote down | **done** `dimensions.mjs` (`assertApplicability`), `pairing.mjs`, `dimensions-ruby.mjs`, `test/applicability.test.mjs`, `scripts/audit-applicability.mjs`. Writable was already true. What nothing held was that the predicate a row ships agrees with the sentence anybody would write for it: `applicability` is whatever `run` emitted, so a predicate seeing a tenth of its own construct gives 1.0 over four files and reads as a strong convention. Each row states the files it can speak about and, where it is partial, what it cannot see, tied to `precision` so the marker and the reason cannot disagree. The witness is per form rather than per row: every shape the code treats differently gets a source, because one source proves the sentence names something and nothing more. A closed table of names is one shape, so it is covered from the other side, each member driven through the predicate against a list written out in the test: dropping `next-intl` from the module list changes no shape and makes every file in such a repository inapplicable, and reading the expectation off the table would agree with it by construction |
| C3 | Render `applicability` beside the area file count on every line | A wrongly narrow predicate gives ratio 1.0 over a small set and reads as a strong convention. This is the only thing a human can audit it with | **done** `render.mjs`, `facts.mjs` (schema 6). The rendered line carried the number a reader audits by eye; the machine record did not. `langFileCount`, the files a dimension could speak about rather than every file in the area, shaped the gate and was then dropped before the record was written, so the share that separates a narrow predicate from a rare construct could not be read back at all. The record carries this pass's count beside this pass's `applicability`, which is the pair that divides; the gate reads the baseline's where there is one, and storing that instead would put a numerator and a denominator from two populations on one line. Auditing one line at a time is what a reader does; auditing every row that produced a slot, across four repositories, needs it on disk |

It ranks areas by headroom and refuses under 0.05, because that run scored 10 of 10 in both arms on a claim stated at 140 of 145 and measured a ceiling rather than a map. And it scores through `parseAll` and `reduceArea` rather than by grep, so the harness's number and the map's number are the same number by construction. Injection is verified before any trial: arm A must name the area and arm B must answer NONE, and either failing aborts. First run recorded in `docs/measurements/2026-08-16-vscode.md`: 10 trials per arm on vscode against a claim with headroom 0.077, and both arms wrote conforming code every time. That is a null result about the task rather than about the map, which the result file now says in its own words rather than leaving to the reader, since the reading is the thing the first run got wrong |
| G6 | The corpus takes every extension the two parsers already read, plus Ruby's extensionless filenames | Measured: `.mts`, `.cts`, `Rakefile`, `Gemfile`, `config.ru`, `.gemspec` and `.jbuilder` are 803 files in a 35-repository corpus, neither counted nor reported as skipped. `.rbi` stays out: a Sorbet signature describes types rather than anything anyone wrote, so a claim counted over one speaks for no code | **done** `corpus.mjs` |
| G7 | The excluded directories cover the other names deliberately unidiomatic code goes by | Measured: angular keeps 2,010 files of golden compiler output under `test_cases`, which was 55 of its 339 areas and every one of its 476 unparseable files. `test_cases`, `testdata`, `test-data`, `golden`, `goldens`, `__mocks__` and `mocks` are 2,218 collected files across 35 repositories, and `.yarn` is 14 more, every one a machine-generated bundle whose 2 MB releases sit at the parse timeout boundary and flip between crashed and rejected across runs, which moves the always-loaded overview (A5). `examples` is deliberately left in: 8,967 paths match it and much of that is maintained code | **done** `corpus.mjs` |

## H. Layout

| # | Decision | Why | Status |
|---|---|---|---|
| H1 | The roster is delivered through the always-loaded overview and through nothing else | The overview carries no `paths` key, so it is in the system prompt before any Read or Write. That is the one channel that reaches a write path nobody Reads in, and #34 measured that path: on a 5,517-file Rails API the exploration phase ran as four subagents and no area file attached in any of them, the one dissected having made 54 `cat`, `grep` and `head` calls and no Read at all, and the four directories that feature's code landed in never attached one either. The other way to reach it is a hook, which "What is deliberately not built" already refuses on complexity and on being flagged as prompt injection, and the chameleon inventory measured a hook channel at 10 to 40% adherence against 100% for the always-loaded one. So the fact that decides where a new file goes is paid for on every turn instead | **done** `layout.mjs`, `layout-scan.mjs`, `scan.mjs`, `render.mjs` (`renderLayout`). #34 stays open; this is the measured answer to it for now |
| H2 | No vocabulary of kinds. A line is labelled with a directory name and a count is nouned with an extension | "components", "services" and "helpers" are a taxonomy this tool would have to ship and then defend on every repository, and the repository has already written the name it uses on the directory itself. So the tests line reads `0 of 504 .tsx files have a namesake test` rather than `504 components`, and a root prints as the path it is. It also removes the whole class of failure where a repository's own word for something disagrees with ours | **done** `render.mjs` (`rootLine`, `testsLine`), `layout.mjs` |
| H3 | Five shell names are descended past: `src`, `lib`, `app`, `packages`, `source`. Every other directory name is printed | Those five say nothing about what is inside them, so a line naming one carries no fact a reader can use. Five words rather than a list that grows, because the rule is "this name is empty" and a longer list starts deciding what a name means, which is H2 arriving through the back door. A Ruby gem's `lib/<gem>` is descended twice, once as a shell and once as a wrapper, and lands on the name the gem actually uses | **done** `layout.mjs` (`SHELL_NAMES`) |
| H4 | Root selection scales with the corpus: a floor of `max(3, ceil(0.01 * N))` cumulative files, descent through any directory one child holds 80% of, and at most 7 lines. The three numbers are tuned by measurement; that they scale is the decision | A fixed floor right for a 200-file repository makes every directory of a 100,000-file one a root, which is the failure area discovery already answered with a scaled floor. 80% is what separates a wrapper from a parent. 7 lines is what the section can spend without crowding the listing it sits above, and the whole section is 15 lines of a 40-line file. A directory under the floor folds into the nearest root above it or into `and N more directories holding M files`, and the direct files of a descended directory are their own candidate, because rubocop prints `lib/rubocop (files at this level): 45 .rb` beside `lib/rubocop/cop`. A descent that earns no line at all keeps the directory instead, because webpack's `lib` is 652 files with 117 at that level and no child clearing its 144-file floor, and the map named `test` and `examples` and never webpack's source | **done** `layout.mjs` (`minRootFiles`, `layoutRoots`, `WRAPPER_SHARE`, `ROOT_BUDGET`) |
| H5 | The roster describes the tree as it is; the five learned rows read the baseline like every other row (D6) | The roster is counts and never a directive, so there is nothing in it to launder: a tests line that moves when an agent adds a test file is a true count that flips no claim, exactly as the area listing's file counts already are. A learned row states a sentence, so it reads the pinned population. The one thing the roster refuses is a subset: a truncated corpus prints `layout: not counted, the scan was truncated` and no roots, because counts over an arbitrary slice of the tree rendered as a description of the tree is what F7 exists for | **done** `layout-scan.mjs` (`counted`, `notCounted`), `reduce.mjs` |
| H6 | C7 is unchanged. The pairing obligations keep their null counter-claim and the roster carries the absence as a count instead | `0 of 40 have a spec` is a fact about a directory; a directive telling an agent to write specs where nobody writes them is a sentence nobody measured. The count prints whenever the repository holds any test file at all and the root's top printed extension is one this tool parses, so a root whose largest is images or data is not asked. That is the line the api side needed: workers ship no spec, services do, and nothing in the map said so, because an obligation treats a missing companion as an absence rather than as a habit. The namesake is matched on the path tail the way C9 learns a companion root, and the root the namesakes share is named by a count of votes rather than by the first match | **done** `companions.mjs` (`namesakeCompanions`), `layout.mjs` (`rootFacts`), `render.mjs` (`rootLine`, `testsLine`) |
| H7 | Every tracked file counts in the roster, source or not; a file in no language this tool parses is never a test file | A directory holding 40 `.md` files is a fact about where things live, so the roster's corpus is the whole `git ls-files` pass under the same deny list rather than the source extensions, and a non-source file is named by its extension and nothing else. The test side runs the other way, and it was measured: twenty screenshots under `cypress/` are not twenty specs, and counting them made the denominator this whole section exists to be read 24 over 4 | **done** `layout-scan.mjs` (`roster`), `layout.mjs` (`isTestFile`) |
| H8 | The common-imports line skips relative specifiers and the runtime packages a framework area cannot be written without, matched by package name so every subpath of one is runtime too | "This React area imports React" is a line the reader already has, and a sibling import is a fact about one file rather than a habit the next file should copy. Matched on the package, so `next/link` and `react-dom/client` are the framework while a package that merely starts with the same word, `next-auth`, is not. A closed table for the same reason C8's framework list is one, and it grows the same way | **done** `siblings.mjs` (`RUNTIME_MODULES`, `commonImports`) |
| H9 | The reuse line resolves a specifier on the path tail, an ambiguous tail resolving to nothing, and counts only importers outside the area | `~/utils/user` and `@/utils/user` both name `src/utils/user.ts` because the tail `utils/user` does, which is the shape C9 already learns a companion root with; a tail two files answer resolves to neither, or one file is credited with another's readers. No `tsconfig` is read, because the aliases a repository points at its own root with are a short closed list and a wrong resolution here is a wrong number rather than a missing one. Counting the area's own files made this repository's `lib` line report twelve readers of a name eleven of its own modules pull in: a directory importing itself is how it is written, not who depends on it | **done** `siblings.mjs` (`specifierToFile`, `mostImported`) |
| H10 | The section and the area `kinds` line shrink into whatever the rest of the file leaves, and both give way to a directive | A6 bounds what a reader reads, and the head, the tail and the two listings that grow are paid first. The section gives way in the order it is read backwards: root lines fold into the count that was already there, then that count, then the two sentences, then the tests line, and under four lines it prints nothing, because a root line names one directory while the tests line is the denominator for all of them. In an area file the `kinds` line prints under the heading and is dropped with the roster lines after a suppressed count and before a stated directive, since a directive is what the file exists to deliver and a description is what makes the next file fit beside the ones already there | **done** `render.mjs` (`renderLayout`, `renderArea`, `LAYOUT_FRAME`, `fit`) |
| H11 | Five learned rows carry a name out of the repository instead of a class from a closed set: `extends_base` and `class_base` for a superclass, `module_include` for a mixin, `interface_prefix` and `type_alias_prefix` for a declared type name's prefix letter. A source-learned class is encoded where the sentence is filled, and a row that can learn an absence writes the absence out in full | What a new file in a directory is expected to sit on is a review comment nothing here counted, and it is repository-specific by construction, which is what C13 already built the learning for. Two rules the template alone cannot carry. The class is text an attacker writes and it lands in a file the agent loads, so it goes through the encoder once at the fill rather than at every render site, where one site would eventually be missed. And `none` is an absence rather than a value: filled in it renders "named with a `none` prefix", so a prefix row spells the whole sentence instead. `none` is also the model default for both prefix rows, so a repository that prefixes nothing prints counts and a prefixed one states. Keyed per engine and per construct, because one key is one predicate and a repository can prefix its interfaces and not its type aliases | **done** `dimensions-naming.mjs` (`extends_base`, `interface_prefix`, `type_alias_prefix`, `claimFor`, `prefixClass`), `dimensions-ruby.mjs` (`class_base`, `module_include`) |
| H12 | Whether a learned class may be enforced is asked of the row, not of the four naming classes | C13's check compared the stored class against the closed list of naming classes, which is the whole vocabulary of the rows that existed then. | H13 | Two sentences under the roster and no others: match sibling test shape, and match directory granularity. Both are about which kind of file to create and where, which is the class of finding no shipped row counts, and each has a counted ground directly above it: the tests line is the denominator that said 4 vitest against 102 Cypress on the repository the review was on, and the helper facet is the sibling-module and inline-helper pair. A sentence with no such ground is a rule this tool did not measure, which is what keeps the list at two. ## What is deliberately not built

- **No hooks.** Worst-trusted channel, highest complexity, measured being flagged as prompt injection.
- **No MCP server.** Nothing to expose.
- **No skill.** It would spend resident context describing the tool instead of the repository.
- **No health score or grade.** It changes nothing about the next line of code.
- **No import-direction (layering) dimension.** Probed on four repositories (2026-08-16): a
  require() repository is invisible to an import-statement site, the cross-area graph is sparse
  everywhere but vscode, and at this tool's own Wilson gate 0 of 4 repositories put even a third
  of their pairs over the bar. `docs/measurements/2026-08-16-layering-probe.md` has the numbers
  and the revisit conditions.
- **No restating what the linter already enforces.**
- **No "catches bugs earlier" claim.** Measured: 1 of 317 defect comments across ten repositories was preventable by a conventions map. Nine of ten repositories scored zero.
